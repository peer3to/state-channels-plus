## Purpose and observable model

The protocol's deterministic predicates — state-proof verification, dispute reduction, output-state
construction, balance-invariant checks, replay execution — are implemented **once**, as contract
code. Each participant runs a local deployment of the same logic in its local VM and evaluates
predicates there instead of reimplementing them in client code. There is no second implementation
to diverge, so _if it verifies on-chain, it verifies locally the same way_ — within the stated
constraints below, which is why those constraints must be explicit.

The local deployment is a **deterministic check engine**: output-snapshot computation, block
structure checks, outbound-run checks and fraud-proof preflight call the contract logic locally
over data the caller supplies, with no gas cost and no round trip. It holds no copy of the chain's
channel state. Every read of replicated channel state that a decision depends on (snapshots,
windows, slash sets, calldata commitments, membership sets, proof walks, reductions) is made on the
chain ([`REQ-MIRROR-6-0WSB4V`](local-mirror.md#req-mirror-6-0wsb4v)). The engineer decided on 2026-11-27 that the event-built
replica the local deployment used to keep (the "mirror") is removed.

The local deployment is scoped to the selected channel's checks. It does not answer global manager
state such as the enumerable set of all open channels.

## Equivalence constraints

Local evaluation equals on-chain evaluation only when all of the following hold. Outside them,
local results are advisory at best:

- **Same logic.** The local deployment runs the same contract logic as the live manager —
  matching protocol version and semantics. A client MUST NOT run one version locally against a
  manager running another.
- **Same supplied state.** The predicate reads only the state its caller supplies. A predicate that
  would need channel state the caller did not supply is evaluated on the chain instead.
- **Controlled context.** Predicates that read ambient chain context — above all block time for
  period arithmetic (kill, evidence, challenge windows), and any caller-identity dependence — are
  locally valid only when the local VM's context is explicitly set to the intended values. Time
  drives most enforcement predicates, so local time control is load-bearing
  ([time.md](../protocol-model/time.md)).
- **State-free evaluation.** Local checks run read-only or against explicitly supplied state (the
  local analogue of call simulation).

Predicates satisfying these constraints are the intended local workload. Anything else — and any
result that will be _acted on_ with on-chain consequences — is decided by the chain.

## Chain reads

- **Chain reads, proven when the light client serves.** The reads of replicated channel state go to
  the chain alone ([`REQ-MIRROR-6-0WSB4V`](local-mirror.md#req-mirror-6-0wsb4v)). While the chain access answers contract reads from state the
  serving endpoint proved ([`REQ-LC-1-JT5PKT`](../runtime/light-client.md#req-lc-1-jt5pkt)), the
  chain's answer is no longer the endpoint's word; otherwise it is, under the honest-RPC
  assumption (A6, [trust-model.md](../security/trust-model.md) §5).
- **Local evaluation fails loudly.** A thrown local error, including a contract revert or executor
  failure, propagates fatally; it is not a completed false result and triggers no fallback. Each
  local evaluation is granted bounded gas ([`REQ-MIRROR-4-H9C4YS`](local-mirror.md#req-mirror-4-h9c4ys)).
  The predicates that decide an on-chain action (the dispute-audit predicates, the auditing-data
  omission) and reduction and the validation of a committed reduced result are computed by the
  chain (engineer decisions, 2026-09-27 and 2026-11-27).
- **Global-state boundary.** Discovery reads that enumerate all open channels go directly to the
  authoritative manager view or a permissionless indexer with manager fallback.

## Requirements and invariants

**<a id="inv-mirror-1-vaf778"></a>`INV-MIRROR-1-VAF778` — Single implementation.** Every protocol predicate evaluated locally MUST be the
same contract logic that enforces it on-chain. Client-side reimplementation of an on-chain
predicate is prohibited; a client needing a predicate the contracts do not expose must add it to
the contracts, not beside them. **Signature carve-out:** signature recovery against a declared
signer is a pure cryptographic check and MAY be evaluated in client code instead, for speed and
caching, only when it applies exactly the contracts' acceptance rule: it MUST NOT accept a
signature encoding the contracts reject and MUST NOT reject one the contracts accept. The same rule
applies to every signature of one scheme (an author signature and a confirmation signature over
the same bytes are checked the same way). The carve-out does not cover decoding of a signed
envelope: decoding is not a pure signature check, and the client and the contracts MUST apply one
encoding rule, accepting and rejecting the same byte strings, for every input inside the
canonical-encoding boundary of [`REQ-DATA-1-1KNRQS`](../protocol-model/data-types.md#req-data-1-1knrqs).
Outside that boundary, for signature-bound inputs that are used only through their decoded
fields, the client MAY be stricter than the contracts.

**<a id="req-mirror-1-xcy9cb"></a>`REQ-MIRROR-1-XCY9CB` — Constrained equivalence.** Under the [equivalence constraints](#equivalence-constraints)
(same logic, same supplied state, controlled context, read-only evaluation), a local
evaluation and an on-chain evaluation of the same predicate on the same inputs MUST agree. Any
predicate evaluated outside those constraints MUST NOT be treated as an on-chain-equivalent
result.

**<a id="req-mirror-4-h9c4ys"></a>`REQ-MIRROR-4-H9C4YS` — Local evaluation is funded and fails loudly.** A thrown local error, including a contract revert, MUST propagate as a fatal error and MUST NOT be converted into an answer or a fallback trigger. Each local evaluation MUST be granted bounded gas: at least the larger of the
dispute execution budget and twice the upfront funding a fraud-proof replay requires for the
transition's full limit, and no more than the larger of those two and a fixed minimum floor. The
replay requirement funds only the transition's limit and the machine's fixed setup; deleting the
previous transition's outbound messages and copying the transition input come on top of it, and
cost at most about one more requirement, because they undo or move what one funded run wrote.
With twice the requirement a local transition is not refused where a funded chain replay runs it,
as far as the chain's block gas limit lets such a replay be sent. The requirement is a funding
baseline, not a bound on the rest of a dispute call (proof checks, restoring the machine's state),
which an on-chain submission funds through its own estimate; a local evaluation can therefore run
out of gas where the chain would not. Running out of gas locally MUST propagate as an error and MUST NOT become an answer or trigger fallback. A local state transition has no chain answer to fall back to: its refusal, its
out-of-gas outside the transition, and an executor failure are local failures that MUST NOT become
a verdict ([`REQ-ENFSM-1-DKJCY2` (Injected context, bounded gas)](execution-and-consumer.md#req-enfsm-1-dkjcy2)).

**<a id="req-mirror-6-0wsb4v"></a>`REQ-MIRROR-6-0WSB4V` — Replicated channel state is read from the chain, proven when the light client serves.** A node MUST make each of these reads on the chain and MUST NOT answer them from a local copy: the dispute window's creation time, the block's calldata commitment, the slashed participants for a dispute, the anchor a built proof starts from, the walk of a state proof from a start it is given (the node's own finalized state, a fork's genesis or the chain's anchor), the reduction of disputes (the comparison of evidence when a dispute is built, the next fork a spectator's sync proves), the commitments of a dispute window, the objective timestamp check of a block ([`REQ-TIME-4-83V27Z`](../protocol-model/time.md#req-time-4-83v27z)), the seated and pending sets that decide whether a node removed by a snapshot it never installed leaves, the snapshot a spectator's sync starts from, whether the chain still holds the snapshot a snapshot event announced before membership publishes it ([`REQ-GOSSIP-4-J5Z4DF` (Eligible transport contribution)](../peer-communication/block-gossip.md#req-gossip-4-j5z4df)), the slashes the chain holds that the node has not handled ([`REQ-DISPUTE-PIPE-9-TDWQPV` (Existing-window state contributions)](../disputes/dispute-processing.md#req-dispute-pipe-9-tdwqpv)), the chain's pending set when it is asked whether it lists a signer (read at the block [`INV-MEMBERSHIP-PENDING-1-2H1T75` (Submitted joins are locally pending before acknowledgement)](../peer-communication/join-authorization.md#inv-membership-pending-1-2h1t75) names), the threshold set a join countersigner checks ([`REQ-JOINSIG-1-8X1A4V` (Pinned-state authorization)](../peer-communication/join-authorization.md#req-joinsig-1-8x1a4v)), whether a fork is disputed once the node's own dispute record does not answer it (the per-block ingest gate, on-chain slash handling, the dispute-acknowledgment request), and the predicates that decide a dispute audit or the auditing-data omission and read replicated state (proof header, latest state, balance invariant, inbound hash, auditing-data omission, the timeout-calldata proof preflight). A state proof is walked from the node's own finalized state when it has one, and from the chain's anchor otherwise. While the chain access answers contract reads from state the serving endpoint proved ([`REQ-LC-1-JT5PKT`](../runtime/light-client.md#req-lc-1-jt5pkt)), each such read is a proven read; otherwise it is the endpoint's word under the honest-RPC assumption (A6). A failed read MUST propagate to the decision that asked, as an error and never as an answer. Evaluation over supplied state and evaluation that depends on the local VM's controlled context are not reads of replicated channel state and stay local. The chain's objective timestamp check takes the previous block's on-chain timestamp from the proof it is given, and answers that it cannot prove an invalid timestamp when that value is unknown: when the node does not know it and the chain holds that block's calldata commitment, the node recovers the calldata first and asks the chain after. The ingest-gate read runs inside the state mutex, so it can wait for the light client's block, and its failure propagates to the ingest step that asked. The engineer decided on 2026-11-21 that the countersigner check and the ingest gate go to the chain while reads are proven, on 2026-11-22 that no exception remains, and on 2026-11-27 that the chain is read directly whether or not the light client serves, that the snapshot comparison reads the chain at its head, that the slashes a node has handled are the set of slash events it handled (replayed ones included, none seeded from the chain), that the pending set is read at the latest block of a handled event that changes it, and that the mirror is removed.

## Assumptions and constraints

- Requires a local VM able to execute the contract logic with controllable time and caller
  context ([execution.md](../runtime/execution.md) — the executor may live in its own context).
- The local deployment may omit production-only parts with no local role (e.g. real asset
  custody behind the consumer adapter is stubbed locally); the omission set is a deployment
  commitment and MUST NOT include any predicate the client evaluates locally.
- Unproven chain reads inherit the trust model's honest-RPC assumption (A6).
- The reads of [`REQ-MIRROR-6-0WSB4V`](local-mirror.md#req-mirror-6-0wsb4v) need a reachable endpoint: nothing local answers them, and a
  failed read propagates.
- "Proven" is the serving endpoint's own claim, made by listing the light client methods
  ([`REQ-LC-4-E29Y46` (The light client is on when the endpoint serves it)](../runtime/light-client.md#req-lc-4-e29y46); the chain access reports it as
  [`REQ-LC-11-MTCBF9`](../runtime/light-client.md#req-lc-11-mtcbf9) states, and
  [`REQ-LC-3-W7RRHM` (A failed read falls back to the endpoint and is made known)](../runtime/light-client.md#req-lc-3-w7rrhm) governs a light-client failure).
  A failure falls back to the endpoint's unproven word, so the honest-RPC assumption (A6) still
  applies on that path, and so it does for every read while the endpoint does not serve the light
  client. A proven answer still takes the endpoint's
  block header on its word ([light-client.md](../runtime/light-client.md), assumptions).

## Security considerations

Evaluating time-dependent predicates with uncontrolled local time yields plausible-but-wrong
window verdicts ([`REQ-MIRROR-1-XCY9CB`](local-mirror.md#req-mirror-1-xcy9cb)'s context constraint), and a version-skewed local
deployment silently disagrees with the manager (same-logic constraint). The signature carve-out of [`INV-MIRROR-1-VAF778`](local-mirror.md#inv-mirror-1-vaf778) reintroduces a second implementation for
signature recovery, so its only defense is exact parity: a client check that is more permissive
than the contracts (for example one that accepts a compact or re-normalized signature encoding)
lets a Byzantine author place history in local state that fails every on-chain proof check, and one
that is stricter drops blocks the chain accepts. Parity is therefore tested differentially against
the contract logic. Envelope decoding needs the same parity: if the client and the contracts
accepted or rejected different byte encodings of one block, a Byzantine participant could post an
encoding the chain accepts and peers treat differently — for example to refute an honest timeout
dispute with posted calldata the peers never accepted. The reads of [`REQ-MIRROR-6-0WSB4V`](local-mirror.md#req-mirror-6-0wsb4v) are made on the chain, so no local copy can make this node miss a challenge or act on a stale window, commitment, slash set or membership set. The cost is availability: the dispute-audit checks, the participant-timeout reads, the block ingest gate and a join countersigner's membership check depend on the endpoint, a slow endpoint delays block ingest and countersignatures, and a failed read of the ingest gate drops a gossiped copy it was checking (gossip delivers it again), while queued blocks go back to the queue and their timeout checks again after a short delay. The participant-timeout check is armed again after a failed chain read. While the reads are proven, the honest-RPC residual narrows to the endpoint's own claim that it proves its answers, to a header and state under it that the endpoint makes up consistently, and to the unproven fallback after a light-client failure; without the light client the endpoint's word decides these reads (A6).
Every answer that would stake the node (a fraud proof, omitted auditing data) is decided by the
chain, and reductions and reduced-result challenges are computed by the chain directly. Treating an
executor failure as a verdict would turn infrastructure faults into protocol decisions, so thrown errors propagate. Local evaluation is bounded by a per-call gas budget
([`REQ-MIRROR-4-H9C4YS`](local-mirror.md#req-mirror-4-h9c4ys)): the larger of a fixed minimum floor, the dispute execution budget and
twice the replay requirement. The replay requirement covers the transition's full limit and fixed
setup only; the second requirement covers deleting previous outbound messages and copying the
input, so a local transition is not refused where a funded chain replay runs it. The rest of a
dispute call (proof checks, state restoration) is funded on chain by the submitter's estimate and
locally only by whatever the grant leaves. A local predicate evaluation can therefore run out of
gas where the chain would run it; that failure is fatal to the operation, never a false verdict or an extra chain attempt. A local state transition that is
refused or runs out of gas outside the transition is a local failure, never an invalid transition:
if it were judged, a node with a misconfigured or failing local environment would build a fraud
proof against an honest author. The node instead raises the error and restores its state; it
cannot judge that block until its environment is fixed, while the other peers judge it. The floor can
exceed a dispute transaction's budget, so a local call can do more work than one dispute
transaction may. The accepted residual is that floor: when the chain's budgets are smaller than it,
a Byzantine dispute can make an auditor spend up to the floor in local work per evaluated predicate
before the chain is asked, which is more than the chain itself would execute for that call but
bounded and independent of the attacker. A dishonest RPC answers unproven reads wrongly — that is the trust
model's residual (A6), not a new exposure created here. The single-implementation rule also
concentrates risk: a contract bug is now a bug in both the enforcement and every local check, which
is the accepted trade for eliminating divergence bugs.
