## Purpose and data model

Each queued network entry has one block hash, its first-seen time, an authenticated source-to-signatures
map, and the block that will be validated. Each source is charged only for its own admitted signatures.
The original author signature counts in each source's allowance.

Dequeue removes the entry from the queue and returns the block with its attribution for normal
processing. New copies arriving afterward follow the normal intake path and may form a new queue entry.
If processing restores an entry, merge its source contributions with any queued copy under the same limits.
Proof and chain inputs do not invent a transport identity.

## Requirements and invariants

**[`REQ-QSTORE-1-PS769J`](../peer-communication/block-gossip.md#req-qstore-1-ps769j) — Attributed merge.** Every admitted source is credited only for signatures
in its own copy that passed that source's allowance. Shared signatures charge each supplying source
once. Reverse supplier lookup derives from this same record. Below each source's limit, duplicate
and reordered copies converge. At a source's limit, its first admitted distinct values win.
Trusted chain timestamps merge independently of signature admission; network copies cannot supply them.

**<a id="req-qstore-2-vywjaq"></a>`REQ-QSTORE-2-VYWJAQ` — Independent source allowances.** Let N be the configured maximum
participant count read from the bound deployment. One queued network entry MUST admit at most N
source identities and at most N distinct supplied signature values per source, counting the author first.
The union therefore contains at most N² distinct supplied values. Signature representation follows the
block model. Storage applies only the count limit; admitted invalid signature values consume the
supplier's allowance and go to normal validation. This is not a fixed-byte or total-memory bound.

New identities or values beyond their allowance are ignored without a validity verdict or punishment.
Existing contributions are not evicted. One source cannot consume another admitted source's slots.
The source map records contributions already admitted to that entry. Removing an invalid confirmation
from its block does not delete that attribution. While queued, keep the first N admitted source identities;
a new identity cannot evict an existing source. A currently ineligible or known-slashed source supplies
no further contributions. No shared allowance record survives dequeue.

The N-source limit still holds when authoritative eligibility contains more than N addresses. It does
not promise space for every eligible identity in an oversized or changing set. N² bounds one network
entry, not the number of hashes, total memory, global request rate, or work across later lifetimes.

**<a id="req-qstore-3-dekyg6"></a>`REQ-QSTORE-3-DEKYG6` — Queue scheduling.** Dequeue-at removes and returns entries
at exactly (fork, height). Priority dequeue selects the lowest queued height on that fork not above the
caller's bound. Returned entries carry the source map into normal validation. Restoration merges queued
copies, preserves the earliest first-seen time and enforces each source's quota. Fork cleanup removes
queued entries on that fork. Standalone proof processing is independent of queue cleanup.

## Assumptions and constraints

- Network source eligibility is established before retention, including already-stored duplicates.
- The live block remains subject to author, signer, linkage, state-transition, and strategy validation.
- Storage boundaries isolate returned blocks and source maps from entries still in the queue.
- Proof replay and chain evidence use their own input bounds and validation. They do not consume a
  fabricated source allowance. Chain observations can update the same block through its existing merge path.
- The deadline is fixed at first admission. Duplicate traffic and restoration cannot extend it.
- These per-entry limits are independent of aggregate admission and retention policy ([`REQ-RPC-5-CV1R1Y` (Resource bounds)](../peer-communication/rpc.md#req-rpc-5-cv1r1y),
  [`REQ-STOR-4-MF6FT6` (Obligation-bounded retention)](durability.md#req-stor-4-mf6ft6)).

## Security considerations

An authenticated eligible sender can fill only its own allowance with junk or alternate valid
signatures. Other admitted sources keep their own allowance. A malicious source can waste its own
slots in a queued entry. A later copy after dequeue is independent; these limits do not bound total validation work.
Source attribution identifies actual suppliers without assigning pooled signatures to innocent peers.
Unknown-source intake awaits ordinary sync and ends without creating a queue entry.

Membership churn can leave all source slots occupied by earlier identities. New eligible identities
then wait for a later queue entry or recovery. This conservative rule preserves the bound. Neither
per-entry limits nor bounded unresolved requests limit total hashes, channels, connections, or CPU
across successive lifetimes. Those remain separate availability concerns.
