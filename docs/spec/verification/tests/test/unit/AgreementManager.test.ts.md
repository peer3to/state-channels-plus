## Overview

The suite drives `AgreementManager`'s read-side machinery on live in-process channels through the
harness session — `h.control(...).query.*` RPC probes and `execOnHost` calls against a peer's
StateManager: per-participant latest-signature walks, everyone-signed checks, state-proof
construction (`buildStateProof`), milestone snapshot and latest-block selection, virtual-vote
milestone building (`tryBuildMilestone`), and the reduce-path accessors
(`getForkDisputes`/`getForkDisputeConfirmations`/`getReduceData`).

Proof cases use the `constructProof` fixture (`test/fixtures/StateProofConstructionStaging.ts`):
it calls `buildStateProof` on a peer, then sends the proof and its milestone snapshots to the
chain's `verifyMilestones`, and returns the milestone block heights, the walk start height, the
builder's finalized and latest snapshot hashes, the chain verdict, and the chain's
`replayBlockIndex`. The strongest oracle is this on-chain round trip.

- **buildStateProof** — a fully-signed tip gives one one-block milestone that the chain accepts;
  an unknown fork throws "Fork not found"; a proof at a join height whose raised threshold is
  completed only above it tops out at the requested height and verifies; proofs sampled while ten
  blocks are produced each verify at their sampled height.
- **Compact construction from the start** — with an on-chain start at height 5 the proof is one
  threshold milestone at height 10 and needs no gap blocks; on a genesis start with 102 blocks of
  unchanged membership, blocks 0..97 deleted and blocks 98..100 holding only their authors'
  signatures (network confirmations dropped so they do not merge back), the proof at height 100 is
  the one milestone `[98, 99, 100]`, finalized at block 98; without any threshold point the proof
  is one run from the block that commits the start, finalized at the start, replay from block 1;
  an unsigned genesis tip gives one unfinal run from block 0; a prover whose mirror missed an exit
  builds from its genesis view and the chain still accepts the proof.
- **Overlapping runs and tails** — a fully-signed change-point tip gives two milestones with the
  same start; virtual-vote runs overlap across a change; a one-block unfinal tail reaches the tip.
- **Required history** — a missing participant-change block, a missing required run block (an
  interior one or the block at the requested height), or a required block that does not link to
  its predecessor makes `buildStateProof` throw; after a missing change block is restored, the
  next call builds the same proof as before and the chain accepts it; height -1 on
  the genesis gives an empty proof that the chain accepts; a request below a non-genesis start
  throws.
- **Milestone selection** — two exits move the start above height 0 and two joins put change
  points above it: the proof has one milestone per change point above the start plus the latest,
  finalized and latest selections come from the last milestone, and the chain accepts the proof.
- **Virtual voting** — `[a] -> [a,b] -> [c] -> [d]` gives milestone `[1..3]`, final at block 1
  without block 1 ever being fully signed.
- **Reduce path** — a peer whose `InboundMessagesProcessed` logs are dropped stages a committed
  dispute over that inbound gap; `getReduceData` over the window's `reduce.staticCall` output
  recovers the run from chain and returns the same number of inbound blocks as the disputer, with
  no throw. The unrecoverable case (`undefined` reduce data) has no test: an auditing peer cannot
  store a dispute whose inbound run it lacks, because its audit throws first.
- **Runs, start and evidence** — on an exit-anchored fork the tip proof starts at the anchor, holds
  no block below it, and the chain's `verifyStateProof` accepts the peer's dispute;
  `stopAtThresholdCompletion` drops the unfinal tail, and a tip whose stored neighbor is unlinked
  or missing builds no milestone, so the final proof is empty; a milestone whose snapshot storage
  lacks returns no finalized snapshot and runs no builder walk; `describeStateProof` of a foreign
  proof maps the run holding the start to the start snapshot, another run to its first block's
  snapshot and an unknown snapshot to undefined, with no walk.
- **Verification ladder** (`StateProofConstructionStaging.verifyOnPeer` runs `verifyStateProof`
  on a peer with the evidence it describes; the harness mirror service observes the peer's
  `verifyMilestonesFromTrustedStart` and `verifyMilestones` reads record-only and injects one-shot
  local or chain read faults) — a valid tier-one walk decides with its start, finalized snapshot
  and replay index; a forged genesis run of a Byzantine author is not valid from the final point
  and the storage tier answers valid from the genesis (start undefined) without a chain walk;
  replay indexes at a tail start, at the last milestone's length and 0 for the empty proof; a peer
  with no stored block or no threshold milestone skips tier one; a `TypeError` from the ABI encoder
  propagates from tier one and from the storage tier; a local revert or executor failure
  propagates and no later tier runs, and an auditor's audit throws with no counter stored; local
  invalid answers followed by a refused or reverted chain read propagate the error, never
  `invalid`, and an auditor of a posted forged proof stores no counter.

Skipped declarations document inputs unreachable from the public surface (malformed addresses,
corrupt stored signatures, out-of-range sync heights, empty milestones, hostile reduce outputs).
The dispute e2e suite owns populated-window reduce-path behavior.
