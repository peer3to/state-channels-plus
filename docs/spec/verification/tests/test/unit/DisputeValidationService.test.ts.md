## Overview

The suite drives `DisputeValidationService.validateDispute` on real channel history through the
harness: a constructed dispute (`h.dispute.fetchConstructedDispute`) is tampered, then audited on
another peer (`h.dispute.auditDispute`), or audited with a before/after storage probe
(`h.dispute.auditPersistence`). The oracles are the audit outcome (`returned` with `isValid`, or
`threw` with its message), the stored dispute fraud proof type and its decoded evidence (`blockIndex`
in the last milestone), the proof count, the stored-before/after state of blocks, snapshots and
state-machine states, the number of blocks that enter the replay pipeline (`holdBlockWork`), and, for
replay proofs, the on-chain `applyFraudProofs` simulation (`simulatedFraudProofSlashes`): the
offender is slashed and the auditor is not. No declaration expects an abstention: every audit ends
in a verdict or throws. Proof crafting helpers live in `test/fixtures/DisputeAuditStaging.ts`:
`storedProofBlock`, `craftProofBlock`, `omittedProof` (a proof without auditing data), `postedProof`
(a proof with matching posted auditing data, optionally another finalized state), `stageExitAnchoredFork`
(an exit posts an on-chain snapshot above height 0) and `postedRepeatedTailDispute`.

- **Inbound hash, header and structure, other checks** — a random inbound hash, a header with a
  wrong channel or fork, a block copy signed by a confirmer appended to the last milestone (the
  `DisputeInvalidBlockStructure` evidence points at the copy's block index 1 in the last milestone,
  also with `requireExistingDisputeWindow` set), a random latest-state hash, extra on-chain slashes,
  a proof truncated below the disputer's latest signed block, and the equal-height boundary. An
  honest posted proof of two separated threshold milestones gets one local structure read and no
  structure proof.
- **Posted auditing data** — a broken balance invariant, a real join's inbound blocks, an inbound
  anchor behind the latest state.
- **Milestone finality and inbound runs** — a joiner audits a pre-join head. On the settled path a
  recoverable inbound gap is healed from chain logs (full audit, the run is held afterwards); an
  inbound gap whose logs are held back throws "inbound run is unavailable" with zero proofs; on the
  posted path an emptied posted run with a gap also throws (the run is rebuilt from chain logs, never
  from the posted data). One unfinal genesis run with posted auditing data is replayed from block 0
  and accepted. A random fork on an empty proof throws "without the genesis of fork" after the same
  dispute on the real fork stored `InvalidDisputeReason`. A local inbound-hash "false" is confirmed
  by the chain, and the chain's "true" wins. On an exit-anchored fork a pending join through the
  dispute's inbound hash is required: without posted data its missing signature stores
  `DisputeLastMilestoneNotFinalAndNoAuditingData` against the disputer.
- **State-proof verdicts** — a malformed confirmation signature stores `DisputeInvalidStateProof`;
  an empty proof on the genesis passes; a forged unseen block 0 with a wrong state gives a replay
  proof at block index 0 of the last milestone that slashes the author, and the block is not stored;
  a proof whose every milestone is below the on-chain snapshot stores
  `DisputeStateProofBelowOnChainAnchor` against the disputer; undecodable bytes give
  `DisputeInvalidBlockStructure`, not a header mismatch. A participant cut off right after a
  snapshot post (`stageParticipantCutOffAtChainAnchor`) audits an unlinked block at the anchor
  height that commits the anchor, then a non-leader block linked to it: the replay proof is at block
  index 1 and slashes that author, not the auditor. A pending participant synced past the start
  without the start-height block audits an honest posted proof in full (true, zero proofs), and a
  posted forged run wholly below the auditor's local final point is replayed on the dispute's own
  chain: `DisputeInvalidBlockInStateProofApplyFraudProof` against the disputer. Without posted data,
  a broken link (an earlier milestone ending in an unlinked block, or a block 0 with a wrong genesis
  link) stores `DisputeInvalidStateProof` after the local and chain linkage reads both answer false,
  while a stripped earlier milestone with linkage and data availability true runs no walk and stores
  nothing. A posted run whose first block is a threshold-final point above the anchor replays from
  the next block (proof at block index 1); a posted run wholly below the anchor stores
  `DisputeStateProofBelowOnChainAnchor`. A dropped milestone below the start with an undecodable
  interior block gives no proof and is not stored; a dropped forged prefix does not hide a forged
  tail block (proof at its original block index 1). A chain `verifyStateProof` read that fails
  throws with no proof, and an explicit repeat audit then stores `DisputeInvalidStateProof`.
- **Dispute output and replay** — wrong output snapshot, required dispute window, invalid reason,
  and one stored proof for a dispute audited twice. An honest posted unfinal run the auditor already
  validated is fast-forwarded (no block enters the replay pipeline); omitted data whose replay base
  the auditor does not hold throws "Dispute replay base ... is not held" with zero proofs.
- **Audit persistence** — a peer that missed an honest unfinal run audits it and stores every
  replayed block and the latest snapshot; a posted finalized state of another real state is
  rejected by the chain (`DisputeInvalidStateProof`, D1) while the honest key keeps the honest state,
  and the right state passes; honest posted data stores the finalized state under the key its block's
  snapshot commits; a posted forged block above the tip is rejected and nothing of it is stored.
  Verified persistence does not store a threshold milestone snapshot that its block does not commit
  (the audit is false), nor a forged block or snapshot below the on-chain snapshot. A re-timed copy
  of the start state supplied as a snapshot entry (start at the run's first block or inside the run)
  is not stored while the real start stays stored and the replay stores the tail's latest snapshot;
  an all-dropped proof is false and stores no block or snapshot; a re-timed genesis is false and
  leaves the stored genesis hash and timestamp unchanged. A valid tail block the auditor lacks is not
  stored while its replay is held (`holdBlockWork`), and is stored after it.
- **Repeated support and tail identity** — the same block as threshold support in the first
  milestone and as the replay tail of the second is not stored before its own replay, and its bad
  transition gives a replay proof at block index 1 of the last milestone that slashes its author; a
  valid repeated tail block is stored only by its replay, with its confirmations.
- **Timeout checks and race** — timeout linkage, next-writer, too-early (both sides), signature
  forfeit, a window not yet in the local chain view, and a fork that advances while the audit is
  parked.
