## Overview

The suite drives the real `SnapshotUpdateService` instance inside each peer's worker realm via
`execOnHost`, against live channels staged by the harness (plain four-peer sessions, pre-dispute
setups with byzantine blocks, and full final-dispute resolutions). The oracles inspect the
prepared update itself: its kind (`ready`, `nothing` or `blocked`), the blocked reason, and — for
the terminal case — the parsed `updateStateSnapshotFork` transaction and its target fork. The cases
cover the zero-generation no-op on an undisputed fork, a same-fork preparation for a fork whose
snapshot is not on chain (`blocked`, `fork-not-posted`), a post
held at its send while a dispute commits that resolves `false` with the chain's disputed-fork refusal, a `postStateSnapshotWait` that resolves `false` with no transaction while a same-fork update waits on a pending join its snapshot has not consumed, a `postStateSnapshotWait` with nothing to post that resolves `true` with the snapshot unchanged, two admission gates (a current
dispute without a final reduced result blocks fork calldata; a same-fork snapshot that has not
consumed the on-chain inbound head blocks same-fork calldata), and a walk across two finalized
dispute windows that assembles exactly one terminal fork update targeting the second resolution's
fork. Outbound-range assembly details are out of scope here.

The `same-fork post from the generation start` cases use `test/fixtures/StateProofConstructionStaging.ts`
and read the on-chain snapshot after `postStateSnapshotWait`. A genesis start whose only blocks
never reach the threshold posts nothing (the chain keeps the genesis). A non-genesis start at
height 2 with one later unfinal block posts nothing: the run holding the start maps to its first
block's snapshot, which is not newer than the start. When the threshold completes at block 2 and blocks 3 and 4 stay unfinal, the prepared
calldata holds one one-block milestone and the post lands at height 2. Block 0 that consumes a
forced join, or block 0 that is a fully signed leave, is final from the genesis start and is posted
at height 0 with the new participant set and the snapshot hash block 0 commits. A run from the
start block that claims its unfinal last snapshot is refused by the chain's
`updateStateSnapshotSameFork` with `ErrorInvalidStateProof`. A missing participant-change block
makes the post reject with the builder's error and submit nothing; after the block is stored again,
a retry posts height 4 with three participants.
