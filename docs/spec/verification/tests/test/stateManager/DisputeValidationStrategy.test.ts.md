## Overview

The suite drives `DisputeValidationStrategy` inside a live harness runtime. Every strategy the
probes build carries a predecessor: the stored block below the replayed block (the fork genesis
at height 0), as the dispute audit passes the previous block of the dispute's own chain.

Two cases call the strategy directly in the peer's worker realm. The result-matrix case
(`probeDisputeStrategyResultMatrix`) enumerates every `BlockValidationResult` value through
`interpretFinalValidationResult`: `SUCCESS` and `DUPLICATE` keep the connection, `DISPUTE` returns
false, and the four live-only results (`NOT_READY`, `DISCONNECT`, `BROADCAST`, `NOT_ENOUGH_TIME`)
throw. The missing-snapshot case (`probeMissingParticipantSnapshots`) builds a block whose resulting
snapshot is not held: `blockAuthorIsNotParticipant` returns `SUCCESS`, `notAllSingersAreParticipants`
with the author signature and no executed participant snapshots throws, and no proof is stored.

Three cases run the real pipeline probes under a dispute strategy: an identical stored
confirmation merges as `DUPLICATE` with the signature set unchanged; a same-author conflict at a
stored height stores an ordinary `BlockDoubleSign` proof, requests no dispute and continues to
`SUCCESS`; an unlinked conflict at a stored height fires `conflictingButNotLinkedBlockDetected`,
which continues, and then `blockIsNotLinkedAndIsNotFirstBlock`, which throws, with no dispute fraud
proof stored.

The eligibility case drives `blockAuthorIsNotParticipant` with two real constructed disputes and
observes the chain's `isBlockChallengeEligible` answers: for an empty proof the chain answers false
and the allegation throws with nothing stored; for a single run from block 0 it answers true and
exactly one `DisputeBlockAuthorNotParticipant` is stored. Each allegation asks the chain once.

Three cases audit a full posted dispute (`auditDispute`). A pending participant whose join
installed the head state (`stagePendingAuditorForgedTail`) audits a tail whose block 1 is a forged
non-leader block: the replay judges it from the posted finalized state and stores a
`DisputeInvalidBlockInStateProofApplyFraudProof` for block index 1 wrapping a
`BlockInvalidStateTransition` proof; a simulated apply slashes the forger, not the auditor. A
participant cut off before block 0 (`stageFarFutureGenesisTail`) audits a dispute whose one unfinal
block 0 is re-signed with a timestamp far past the genesis: `objectiveInvalidTimestampDetected`
stores an apply proof wrapping `InvalidTimestamp` for index 0. An outsider-authored tail block whose
resulting snapshot the auditor lacks (`stageOutsiderAuthoredTail`) passes the early author check;
the leader check then stores an apply proof wrapping `BlockInvalidStateTransition` at that block's
index. Each audit returns invalid.

The deviation hooks' dispute-evidence construction against a committed dispute is also owned by
the `disputeValidation` e2e suites; live-strategy behavior is out of scope.
