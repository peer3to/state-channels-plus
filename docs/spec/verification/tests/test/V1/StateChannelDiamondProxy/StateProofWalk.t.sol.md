## Overview

One Foundry contract, `StateProofWalkTest`, runs on the shared `StateProofStaging` harness: a diamond-like
`StateProofHarness` that inherits the real `DisputeFraudProofFacet` and `DisputeVerificationFacet` and reaches
`StateProofFacet`, `FraudProofFacet` and `UtilityFacet` by delegatecall, as the proxy routes them. `setUp` stores
the fork genesis {A, B} as the chain snapshot; `_seedAnchor` moves the chain snapshot to a normal same-fork
snapshot (height 5 by default). Milestones are runs of linked blocks by one author; a run's first block carries
the given confirmation signers, and the supplied milestone snapshot is the state its first block commits.

Most cases call the routed `verifyMilestones(ProofWalkInput)` and read the `ProofWalkResult`: `valid`, the
`finalizedSnapshot`, and `replayBlockIndex`, where the last milestone's unfinal tail starts (its length means no
tail). The cases cover:

- the anchor from `getAnchorSnapshot`: `canUseOnChainSnapshot` is true for the same-fork normal snapshot and false
  for the fork genesis (recognized by its data) or a snapshot on another fork;
- a normal on-chain start inside a run: the start block commits it at its exact height, needs no predecessor and
  no threshold, supplies the finalized state, and replay starts after it (start at the first offset, the last
  offset, inside the run, and a normal start at height 0 that a genesis-linked block 0 does not match);
- genesis block 0: an unfinal block 0 alone replays from 0; a final block 0 replays after 0; a final join at 0
  makes the joined set the next hop's old set; a final exit at 0, signed by the old/new union, makes the exited
  set the next hop's old set (without it, the departed member must sign the next hop); a missing old or new
  signer leaves block 0 unfinal;
- the union threshold: a pending inbound joiner in the interval is required, only distinct expected signers
  count (an outsider or a duplicate fails), a later milestone needs the threshold, and a membership change hop
  cannot be omitted;
- order and overlap: overlapping runs prove distinct states; two runs that start with the same block each need
  their own threshold (an author-only repeat rejects); an author-only run at a proven height that commits another
  state rejects with either snapshot entry; decreasing first heights reject; an unfinal block 0 beside another
  milestone rejects;
- dropped and empty proofs: milestones wholly below the start are dropped (not certified, a forged entry for
  them installs nothing, their broken bytes and the anchor run's prefix before the start are never read); the
  empty proof always denotes the fork genesis, also with a normal snapshot on chain;
- kept block defects (broken link, skipped height, bad author) fail both the walk and `isStateProofLinked`;
- genesis authentication through `isStateProofLinked` and `verifyMilestones`: a reduced fork that the chain has
  not adopted accepts its authenticated genesis; with a normal anchor on chain and an empty proof, wrong genesis
  data fails; while the fork genesis is on chain, a genesis-linked run and the empty proof walk valid with empty
  genesis data (the walk reads the genesis from storage); and a correct genesis with a wrong block-0 link fails;
- `verifyStateProof` on a posted-data dispute: a proof built from the genesis whose milestones all end below a
  newer on-chain snapshot passes, a proof spanning that snapshot passes, and a proof that starts above that
  snapshot passes with genesis data that does not hash to the fork ID;
- `verifyStateProof` binds the posted finalized state to the walk's finalized snapshot: over two threshold
  milestones it accepts the state of the second milestone's snapshot and rejects the first milestone's state and
  empty bytes; with the anchor (height 5) inside a run [3, 6] it accepts the anchor's state and rejects the state
  of the run's first block;
- `test_badInputIsInvalid`: 14 bad-input cases, each an invalid walk — a start offset past the run, a wrong height
  at the start offset, a start block that commits another snapshot, an empty milestone, an undecodable first,
  interior or last block (these also fail `isStateProofLinked`, and `findFirstInvalidBlockStructureInStateProof`
  reports that block), missing or extra snapshot entries, a confirmation signature of the wrong length, a later
  hop whose entry is not its first block's commitment, a height wrap at the maximum height, an interior block on
  another fork, and a confirmation signature that recovers no signer.

- the structure scan reports only the last milestone's first defect, by its index there, and
  `isBlockChallengeEligible` answers false when the first or the challenged block does not decode;
- `verifyStateProof` fails when the milestone above the anchor misses B's signature, and when the
  posted latest state or the claimed latest state is not the last block's commitment;
  `isCorrectLatestState` is false for an undecodable last block, and an empty proof's claim is the
  genesis;
- an on-chain slash of B changes no walk verdict: a proof B signed stays valid and one without B
  stays invalid.

Off-chain proof building and the dispute fraud-proof wrappers are out of scope here.
