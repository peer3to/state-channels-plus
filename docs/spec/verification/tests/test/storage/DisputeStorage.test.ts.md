## Overview

The suite drives `DisputeStorage.storeDisputeConfirmation` directly with factory-built signed
disputes and co-signatures made by fresh wallets over the dispute hash, and reads back through
`getDisputeConfirmation`. It covers the retention rule: the first copy is stored with exactly its
signatures, later `SYNC` copies (once or repeatedly, with extra signatures) leave it unchanged, a
`CHAIN_EVENT` copy replaces a `SYNC` copy, a `SYNC` copy after a `CHAIN_EVENT` copy and a second
`CHAIN_EVENT` copy are ignored, different hashes stay independent, and an identical re-store under
either origin keeps the stored object. The oracles assert the returned hash, the stored object's
identity, and the exact stored signature list. The per-fork flags are not exercised here, and no test
decodes the stored dispute, so those permutations stay unassigned.
