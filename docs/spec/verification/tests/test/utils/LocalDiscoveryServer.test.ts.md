## Overview

These component cases run real loopback discovery and real authenticated `P2PManager` instances. They compare
transport identities across an explicit raw close, prove that close does not blacklist the remote identity,
then observe the same topic after leave or explicit blacklist. The tests
exercise the production session, canonical dialer, retry timer, handshake, and blacklist checks; no synthetic
transport or precomputed result boolean stands in for discovery.

Three cases drive a one-sided reconnect suspension across the pair, with the suspending side chosen by real
address order rather than by index. Two of them place it on the canonical dialer, the side that owns the
pair's only dial loop. The first holds one full agreement window with the suspension standing and reads the
suspending side's transport token as `null` — the pair is genuinely down while it holds — then lifts the
suspension on that same side and waits for a transport to come back, so the oracle is that the side that
placed the suspension is the side that restored the connection. The second counts handshakes on that same
suspending side after its own close and requires zero: the only peer that could have produced one is the side
that merely accepted the route, and it must never dial a close back, because a close caused by a suspension
and a close caused by a deliberate departure are the same observable event to it. The third places the
suspension on the other side instead, leaving the canonical dialer redialing into a refusal it is never told
about, and holds one full agreement window after the first redial before reading both peers' standings — the
oracle is that neither identity is excluded, so a refusal does not become an exclusion on the refused peer
and a suspension does not escalate on the suspending one.
