## Overview

The suite checks the header binding between a dispute's claims and every block carried in its
state proof, plus the relevance gating for foreign-fork disputes. `stubConstructDispute`
rewrites peer 3's dispute, with `submitDoubleSignBlock(1)` as the trigger: the header `channelId` of
the last block of the last milestone is randomized on the calldata path
(`preDisputeSetupCalldataPath`), and the header `forkId` of block 0 of the last milestone is
randomized on the disconnected-peer path, where the proof is one unfinal run from genesis
(`preDisputeSetupDisconnectedPeer`). Oracle for the mismatch cases: the dispute initiates with
auditing data, peer 0 observes `onDisputeKilled`, honest peers store a
`DisputeStateProofHeaderMismatch` dispute fraud proof, and the window resolves. The block-0 case
shows that a wrong-fork block 0 is killed by the header check before any genesis-link judgment.
The uniform-junk-forkId case rewrites `dispute.input` and the entire proof consistently to a
nonexistent fork and asserts the opposite outcome: the dispute commits, no kill fires within the
observation window, and every honest peer stays on the original fork — a dispute for a fork nobody
runs is ignored, not fought. Two skipped declarations cross-reference
`uploadRevert/channelId.test.ts` and `disputeInputFields/forkId.test.ts`. The
[`REQ-DISPUTE-PIPE-1-HRBFP7` (Bound intake)](../../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-1-hrbfp7)
intake splits belong to those dedicated suites.
