## Overview

Six cases tamper \`dispute.input.latestStateSnapshotHash\` to a random hash for an empty proof (the
fork genesis; the stub also clears \`milestones\`) and for a proof with milestones, whose last
milestone block must commit to the hash. Each shape runs without calldata
(\`preDisputeSetup\`, invalid-state-transition trigger, no auditing data) and with calldata posted
(\`preDisputeSetupCalldataPath\` or a leave-plus-timeout setup, auditing data posted). Synced auditors
and intentionally disconnected auditors (peer 3 on the no-calldata path, peer 1 on the calldata path,
which recovers the calldata and audits inside the kill period) both kill the dispute. Oracles: the
dispute initiates with the expected auditing-data flag, the named auditor observes
\`onDisputeKilled\`, honest peers store \`DisputeInvalidStateProof\`, and the fork resolves. The synced
no-calldata cases construct the honest replacement only after the auditor observes the kill
(\`suppressDisputeInitiation\` then \`restoreDisputeInitiationAndDispute\`), so a pre-kill output cannot
become final under the smaller post-kill threshold.
