# Specification Review Coverage

> **Status:** Draft.

## Purpose

This map records where each numbered note (1–44) of the engineering review in
`temp/SPECIFICATION-REVIEW.md` is represented in this specification tree, and its disposition. It
exists so that review detail cannot silently disappear during the split from one review file into
many focused documents, and so an auditor can confirm that every review note has an owner.

The review file lives under `temp/`, which is gitignored, so it is not part of the repository
history. The Subject column therefore summarizes each note enough to be meaningful without the
file. The review's unnumbered progress interludes (areas reviewed without objection) carry no
requirements and are not mapped.

Disposition vocabulary:

- **Accepted** — the note's content is stated as normative in the tree.
- **Decided** — an engineer decision was recorded (cited by OQ entry or dated decision). Several
  decisions dated 2026-08-10 postdate the tree's first version and are reflected below.
- **Open — OQ-n** — tracked in [open-questions.md](../open-questions.md).
- **Gap exposed** — the intent is clear but current code contradicts it; the owning document
  records the `Current:` / `Intended:` divergence.
- **Non-normative / Future Work** — recorded as ideas, not approved requirements.

A row may combine several dispositions.

## Maintenance

When a specification change moves ownership of a review note's content — a section is split,
merged, renamed, or its normative text migrates to another document — update this map in the same
change. When an open question in a row is resolved, update the row's disposition and cite the
decision. Do not mark a note complete because its terminology merely appears somewhere in the
tree: the owning document must carry the note's actual requirements, divergences, or decision
record.
