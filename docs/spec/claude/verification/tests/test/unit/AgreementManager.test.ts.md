## Overview

The suite drives `AgreementManager`'s read-side machinery on live in-process channels through the
harness session — `h.control(...).query.*` RPC probes and `execOnHost` calls against a peer's
StateManager: per-participant latest-signature walks, everyone-signed checks, state-proof assembly
(`getStateProof`/`tryGetStateProof`), milestone snapshot and latest-block selection, virtual-vote
milestone building (`tryBuildMilestone`), and the reduce-path accessors
(`getForkDisputes`/`getForkDisputeConfirmations`/`getReduceData`). The strongest oracle is a real
round trip: assembled proofs go to the on-chain verifier and the tests assert
`verified`/`isFinal`/the on-chain finalized snapshot hash, alongside structural checks of the
carrier (milestones vs. signedBlocks fallback), height bounds across join/leave membership
changes, and which milestone supplies the finalized and latest snapshots. Staged scenarios include
disconnected signers, two leaves across milestones, a join with a raised threshold completed only
above the requested height, partial confirmation delivery, a lone-author head, attacker-style
unknown forkIds, and proofs sampled concurrently with block production. Skipped declarations
document inputs unreachable from the public surface (malformed addresses, corrupt stored
signatures, hostile reduce outputs) rather than missing coverage, and the dispute e2e suite owns
populated-window reduce-path behavior. The genesis-anchored fallback permutation is claimed by
`DisputeManager.test.ts`, whose empty-proof dispute test verifies that carrier on-chain. The
specification-level `REQ-SP-*` permutations are now atomized into single scenarios, but their
definitive demonstrations are the on-chain verifier suites and the dispute e2e flows, so none
are claimed here.
