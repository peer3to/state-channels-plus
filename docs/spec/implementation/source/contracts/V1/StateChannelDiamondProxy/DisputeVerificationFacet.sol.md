## Responsibility and observable boundary

The reduction engine: the pure fold (`reduce` — longest-valid-latest-block with hash tie-break,
slash candidate union, lowest-height timeout, self-removals, chain-derived inbound
tip), `reduceOutputToSnapshotData` (linkage verification, inbound application, slashes of the
participant state only, slashes-suppress-timeout precedence, exit emission), `reduceAndFinalize` (kill-period gate, commitment-exact set,
expectation match, idempotence), `challengeDisputeReduction` (currently unreachable from commit
paths), kill, output helpers, and the balance-invariant check.

## Key design decisions

Only `challengeDisputeReduction` checks eligibility: it admits only current snapshot participants and eligible joins inside the unconsumed inbound interval, excluding on-chain-slashed signers, through the shared bounded eligibility owner. See [challengeDisputeReduction](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L181) and [`REQ-DIS-2-PKVZ7E`](../../../../../specification/disputes/disputes.md#req-dis-2-pkvz7e). [`reduceAndFinalize`](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L221) has no eligibility check, so anyone can reduce; who may reduce is the recorded open question [`OQ-27-GT4W09` (Reducer eligibility is disabled)](../../../../../specification/open-questions.md#oq-27-gt4w09).

Slash and removal application append exits only for successful hooks. An already departed target produces no new exit, balance change or withdrawal, even if the chain snapshot still grants eligibility. See [the slash hook check](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L578) and [the removal hook check](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L597).

1. **Immediate finalization by construction:** every commit path back-dates the reduction timestamp so the challenge period is pre-expired — gas traded for latency; the challenge entry point is dormant scaffolding for the optimistic design (spec-flagged open question).
2. **The empty-timeout fold cancellation lives here:** a dispute without a timeout resets the candidate (height 0 beats real heights). For a slash-carrying dispute this is intended slash precedence (engineer decision 2026-08-14, [`INV-DIS-7-9GGZSD`](../../../../../specification/disputes/disputes.md#inv-dis-7-9ggzsd)); the slash-free case remains the open specification question [`OQ-9-XR1MFS` (Timeout precedence edge rules)](../../../../../specification/open-questions.md#oq-9-xr1mfs).
3. **The commitment-set guard reports both commitment sets, from a revert branch.** Both
   commitment checks
   ([#L189](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L189),
   [#L253](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L253))
   raise `ErrorDisputeCommitmentNotAvailable(channelId, forkId, committedDisputeHashes, submittedDisputeHashes)`
   — the chain's committed hashes before the caller's submitted hashes, matching the required-side-first
   order used across the error vocabulary. The hashes, not their counts: the mismatch is usually a
   substituted dispute at equal length, which a pair of counts cannot express at all. The submitted
   side is produced by
   [`_disputeCommitmentHashes`](../../../../../../../contracts/V1/StateChannelDiamondProxy/utils/DisputeUtils.sol#L81),
   the same per-dispute hash `areDisputesCommitted` compares with, so the reported set cannot drift
   from the set that was actually tested. They use `if (!…) revert` rather than `require` because the
   committed list is a storage read `areDisputesCommitted` performs internally and the submitted
   hashes are worth computing only once the comparison has failed, and error arguments are evaluated
   eagerly: inside `require` the happy path would hash every submitted dispute a second time.
4. **`reduce` reads no participant set.** It folds as slash candidates every on-chain slash up to
   the window expiry ([`_getOnChainSlashedParticipantsUpToTimestamp`](./StateChannelCommon.sol.md))
   and every dispute's listed slashes, deduplicated
   ([#L72](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L72)). Slash eligibility ([`REQ-DIS-11-WQK8P2`](../../../../../specification/disputes/disputes.md#req-dis-11-wqk8p2)) is decided where the
   disputed fork's participant state is verified: in `reduceOutputToSnapshotData` (decision 6).
   The channel's current snapshot is not fixed per fork — once a reduction for the fork is mined it
   lists only the survivors — so an eligibility filter on it made late reducers fold fewer slashes
   than the reduction on chain (observed as honest reducers aborting on `Block hash … not found in
storage` while building the fork-snapshot calldata). The candidate set needs no participant
   bound: its size is the on-chain slash count plus the listed slashes.
5. **The dispute output state is loaded once.** `_generateDisputeOutputState`
   ([#L366](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L366))
   calls `setState` once, applies the inbound joins
   ([`_applyInboundMessages`](./StateChannelCommon.sol.md), which returns only the new deposit total),
   the slashes and the removals to that loaded machine, and calls `getState` once. The slash and
   removal helpers ([#L568](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L568),
   [#L587](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L587))
   take no encoded state and return only their exit channels. The output state stays loaded, so
   `computeDisputeOutputSnapshotData`
   ([#L28](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L28))
   and `reduceOutputToSnapshotData`
   ([#L348](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L348))
   read the output participants with `getParticipants()` and no second `setState`. Rationale: each
   `setState` on a large application state costs gas in proportion to its size; with one load per
   helper, a dispute over a large state (poker in the middle of an eviction) used more than the
   poker deployment's 10M dispute execution budget of the gas-capped local computation (this
   repository's default budget is 3M,
   [StateChannelManagerProxy.sol](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateChannelManagerProxy.sol#L30)). The output is the same as
   with a load per helper, because each helper used to load exactly the state the previous one
   read back.
6. **Only slashes of the participant state apply and suppress the timeout.** `reduceOutputToSnapshotData`
   ([#L281](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L281)) and the per-dispute output helpers pass the slashes, the self-removals
   and the timeout to `_generateDisputeOutputState`
   ([#L366](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L366)). It loads the latest state, applies its pending inbound joins, and
   slashes there: the state machine slashes only its participants, so exactly the slashes of
   participants of the disputed fork's participant state take effect
   ([`REQ-DIS-11-WQK8P2`](../../../../../specification/disputes/disputes.md#req-dis-11-wqk8p2)). The timeout joins the removals only when no slash took effect
   ([#L385](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L385), [`INV-DIS-7-9GGZSD`](../../../../../specification/disputes/disputes.md#inv-dis-7-9ggzsd)). The rule is
   `slashExitChannels.length == 0`: it reads the state machine's `slashParticipant` return values,
   not the listed slashes. So it holds only while the machine keeps the
   [`_slashParticipant` contract](../../../../../../../contracts/V1/AStateMachine.sol#L108)
   (true for every current participant); a consumer machine that returns false for a present
   participant also removes the timeout target ([AStateMachine.sol.md](../AStateMachine.sol.md)). The latest state is fixed by the committed
   disputes (the reduced latest block commits it) and the inbound blocks by the chain up to window
   expiry, so every reducer — on chain, local, early or late — gets the same result. A slash of a
   participant an ancestor fork removed therefore neither applies nor blocks the fork's timeout. A
   dispute cannot list such a slash: `_hasDisputeReason` makes it invalid
   ([DisputeUtils.sol.md](./utils/DisputeUtils.sol.md)), so the dispute-level suppression on its
   listed slashes is the same rule. `_selfRemovals`
   ([#L532](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeVerificationFacet.sol#L532)) gives the dispute's self-removal.
7. **A dispute's outbound blocks are not verified here.** The auditing data's
   `outboundMessageBlocks` hold only the run above the on-chain snapshot's outbound head; auditors
   persist them for a later snapshot post, and that post verifies them against the on-chain
   snapshot of its own time (`StateSnapshotFacet._updateStateSnapshot`). No reduction path reads
   them, so this facet has no outbound check.
   [`StateProofFacet.isDisputeOutboundRunInvalid`](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L93)
   judges them against the chain anchor;
   [DisputeFraudProofFacet dispatches it](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L306).
