## Responsibility and observable boundary

The temporary client-local mirror deployment: extends the proxy with event-driven storage-sync
handlers and a zero consumer facet — the local half of dual execution. Never production-deployed.
It mirrors only events indexed by its selected channel. It does not synchronize or answer global
manager state such as the enumerable open-channel registry. Its mirrored dispute-window
bookkeeping resolves commitments through the shared
[`_disputeCommitmentHash`](./utils/DisputeUtils.sol.md) owner, so a locally mirrored window keys
on exactly the preimage the manager committed.

Because it derives from [StateChannelManagerProxy](./StateChannelManagerProxy.sol.md), its
generated ABI carries only its own declarations plus the proxy's; every selector the proxy routes to
a facet is answered by the fallback and absent from that ABI. Clients therefore bind it through the
merged ABI in [localDiamond.ts](../../../src/utils/localDiamond.ts.md).

## Key design decisions

1. **Event-replication entry points** (`on*` handlers) are how the client advances the mirror — replication, never local hypothesis ([`REQ-MIRROR-2-E9F3TM` (Unconditional replication)](../../../../../specification/enforcement/local-mirror.md#req-mirror-2-e9f3tm)).
2. **No block-authentication or decoding entry point of its own.** The public `isBlockAuthentic`
   entry point is gone; the client checks author signatures itself under the signature carve-out of
   [`INV-MIRROR-1-VAF778` (Single implementation)](../../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778) and decodes blocks with `Codec`. The mirror
   no longer overrides `_isBlockAuthentic` either: mirrored fraud-proof and state-proof checks run the
   inherited production internal ([StateChannelCommon](./StateChannelCommon.sol.md)). The former local-only
   helpers for the auditing-data hash, the unfinalized blocks of a proof and the latest join block
   hash are deleted; their callers use the routed `verifyStateProof` and the walk result instead.
3. **Channel-open event order preserves genesis deposits.** `InboundMessagesProcessed` is mirrored
   before `ChannelOpened`, so `onChannelOpened` retains the finalized snapshot deposit total instead
   of resetting the local balance mirror to zero.
4. **Channel-local by design.** Stateful and stateless channel computation stays on participant
   hardware without repeated RPC reads, but the event feed is not a complete or verified chain
   view. Consequential decisions retain their chain/RPC fallback. A future verified light-client
   RPC can replace this temporary mirror instead of extending it into global-state replication.

5. **The mirrored snapshot never goes back.** `onStateSnapshotUpdated` ([#L100](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L100)) first asks `_isOlderSnapshot` ([#L118](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L118)) and drops an older snapshot before the event-order guard ([#L106](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L106)–[#L107](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L107)). Older means: a lower height on the stored snapshot's fork ([#L123](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L123)), any snapshot of the stored fork's origin fork, or a zero-fork snapshot, which a chain read of a closed channel returns ([#L124](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L124)). A snapshot at the same height on the same fork, and a snapshot on any other fork, are accepted. The rule applies to observed logs and to trusted (0, 0) reconciliations alike. Why: a (0, 0) reconciliation passes `_acceptEvent` without moving the event coordinate ([#L285](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L285)), so the event order alone cannot stop a queued older log that arrives after it; without this rule that log would replace the newer snapshot that the auditor installed from the chain ([`REQ-MIRROR-5-YSFRKG` (Mirror snapshot never goes back)](../../../../../specification/enforcement/local-mirror.md#req-mirror-5-ysfrkg)). A refused log also leaves the event coordinate unchanged, because the check runs before `_acceptEvent`. Residuals, by design of the one-step rule: a snapshot of a fork two or more reductions back is not linked to the stored fork by its origin and is accepted as a new fork, and `onChannelOpened` writes the genesis snapshot without this check ([#L81-L82](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L81-L82)).

6. **A local walk from a trusted start.** `verifyMilestonesFromTrustedStart(input, chosenSnapshot, checkFinality)`
   ([#L424](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L424)) runs the one walk `_walkStateProof` from a start the caller
   supplies ([#L429](../../../../../../../contracts/V1/StateChannelDiamondProxy/LocalDiamond.sol#L429)) instead of the mirrored snapshot. It is
   `view`, so it never changes the mirror. Why: the SDK's first verification tier walks from the latest
   threshold-final snapshot the node itself holds, which can be newer than the mirrored chain snapshot, and the
   answer must come from the same walk as the chain's. A trusted start is a local trust decision, so the entry
   exists only on this contract: it is not declared on [StateChannelManagerInterface](../StateChannelManagerInterface.sol.md)
   and no production route reaches it ([StateChannelManagerProxy](./StateChannelManagerProxy.sol.md)). A local
   success is final for the SDK, a local failure falls through to the next tier, and only the chain answers
   invalid ([`REQ-MIRROR-3-THD7K8` (Cache, never authority)](../../../../../specification/enforcement/local-mirror.md#req-mirror-3-thd7k8),
   [`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).
