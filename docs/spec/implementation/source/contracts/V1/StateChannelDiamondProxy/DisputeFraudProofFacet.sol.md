## Responsibility and observable boundary

Dispute fraud-proof application: skip already-killed, kill-period-open gate, dispatch across the
19 content/timeout families, valid → kill + slash disputer, invalid → slash submitter; plus the
timeout-evidence view predicates (calldata-posted validation, last-milestone finality, header
mismatch, inbound-hash validity).

## Key design decisions

Dispute-fraud targets use the same bounded current eligibility as ordinary fraud proofs. Historical proof validation keeps its historical membership walk; eligibility is not inferred from old joins outside the current boundary. See [DisputeFraudProofFacet.sol](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L32).

1. **Kill is the only commitment-removal path**, pairing with the window bookkeeping's swap-removal — the order perturbation input to [`OQ-4-JGDCNX` (Dispute-reduction order-independence)](../../../../../verification/open-questions.md#oq-4-jgdcnx) originates here.
2. **Typed self-calls go through the manager interface, not the proxy contract.** The three
   operations this facet reaches on `address(this)` — the dispute-window creation timestamp
   ([#L499](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L499)), the state transition
   ([#L687](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L687)) and the milestone finality check
   ([#L855](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L855)) — are typed by
   [StateChannelManagerInterface](../../StateChannelManagerInterface.sol.md). The calls are
   unchanged; only the compile-time type is, which removes this facet's dependency on
   [StateChannelManagerProxy](./StateChannelManagerProxy.sol.md) now that the proxy no longer
   declares the routed functions.
3. **A listed slash set that is a subset reverts with both sets.**
   `_handleDisputeOnChainSlashesNotSubset` returns the disputer as the offender the moment one
   listed slash is absent from the chain's record; reaching the end means the proof was wrong and
   the call reverts with `RaceConditionOnChainSlashes(channelId, disputeSlashes, onChainSlashes)`
   ([#L404](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L404)).
   Slash-set contents are time-dependent, so the client classifying this race needs to know which
   slashes the two sides held, not how many: the arrays are already in memory at the revert, and
   the sets can differ while their counts agree. The site is a plain `revert`, so nothing is
   evaluated before the loop has proven the subset relation.
4. **Milestone finality is judged against the dispute's historic threshold set.**
   `_getHistoricThresholdSet` ([#L846](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L846)) reads the chain snapshot participants plus the joiners at
   or below the dispute's inbound anchor, minus `input.onChainSlashes` only. Its name sets it apart from the live
   `_canParticipateInDisputesNow` eligibility read. The disputer commits the slash list, so construction and every
   later proof read the same set; over-listing stays provable through `DisputeOnChainSlashesNotSubset`, and an unlisted
   slash only makes the threshold stricter. The participant half comes only from chain data, never from the
   dispute's own latest state, and cannot move while a proof can land: adoption targets only the latest undisputed
   fork and a disputed fork advances only by reduction ([StateSnapshotFacet.sol.md](StateSnapshotFacet.sol.md)).
5. **The inbound-anchor families stay as defence in depth.** Upload admits only a dispute anchored exactly at the
   chain's inbound head ([DisputeManagerFacet.sol.md](DisputeManagerFacet.sol.md)), so
   `DisputeInboundHashNotInChain` ([#L130](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L130)) and `DisputeInboundAnchorBehindLatestState`
   ([#L259](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L259)) are unreachable for committed disputes. Their handlers are kept unchanged.
6. **A timeout refutation replays only from the dispute's latest state.**
   `_validateTimeoutCalldataPostedProof` checks, before the replay
   ([#L673-L680](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L673-L680)), that the proof's latest state snapshot is the one the dispute's
   latest proved block commits to (or the fork's genesis snapshot) with
   `_isSnapshotLinkedToLatestBlock`, that the snapshot's `stateMachineStateHash` equals the hash of
   the machine state the replay starts from, and that the posted block's `previousBlockHash` is the
   hash of the latest proved block's signed bytes, `keccak256(encodedBlock)` (or of that genesis
   snapshot at genesis). The signed bytes are the block identity, as in the state proof's chain
   linkage and the client's `Block.hash`; hashing the re-encoded fields would reject an honest
   block built on a non-canonical but accepted encoding. The calldata-posted grace check compares
   the same signed-bytes hash. The blamed author signs
   and posts the block itself, so without these links it could post a block built on a made-up
   pre-state, name that pre-state in the proof, replay it successfully, and refute an honest timeout
   dispute, which slashes the honest disputer. A proof that fails a link returns `false`, so the
   submitter is slashed like any failed refutation. The same predicate backs the auditor's
   `validateTimeoutCalldataPostedProof` preflight, so an honest auditor never submits such a proof.
   The posted block's author signature is still not verified here
   ([`FIND-TIMEOUT-2-J7S0TS`](../../../../../audit/open-findings.md#find-timeout-2-j7s0ts)).
7. **The balance invariant is judged on the dispute's latest state.**
   `_handleDisputeInvalidBalanceInvariant` ([#L364](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L364)) requires the alleged snapshot to be
   the dispute's latest state: `_isLatestStateLinkedToLatestBlock` checks that its hash is the
   dispute's `latestStateSnapshotHash`, that the supplied machine state hashes to its state hash, and
   that the latest block links to it ([#L370](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L370); [StateChannelCommon](./StateChannelCommon.sol.md)).
   No walk runs and the allegation carries no walk evidence. Why: the latest state is the one the
   dispute asks the chain to adopt, final or not, so a bad balance there is the submitter's fraud;
   naming exactly that state also keeps an older or honest snapshot from being alleged. Only then
   does it delegate to `DisputeVerificationFacet.verifyBalanceInvariantCheckSnapshot`
   ([#L377](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L377)). That check still compares withdrawals with the channel's current on-chain
   value ([`FIND-BALANCE-1-S6SP4N`](../../../../../audit/open-findings.md#find-balance-1-s6sp4n)).
8. **A claim below the on-chain start has its own counter.**
   `_handleDisputeStateProofBelowOnChainAnchor` ([#L273](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L273))
   reads the anchor through `_getAnchorSnapshot` and is invalid unless the proof can start from the
   stored snapshot: it is on the dispute's fork and is not its genesis ([#L280](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L280)). An empty
   proof claims the fork genesis, which that snapshot is past, so it is valid at once
   ([#L281](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L281)); otherwise
   the latest block must decode and its height must be strictly below the stored height
   ([#L286](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L286)). The
   payload carries no data (`{ bool __; }`): the chain reads the start itself. Why: the walk accepts such a
   proof (its milestones are dropped and the start is final), so without this type an honest participant
   would need a newer state signed by the disputer to answer it. Equal height, a higher claim, a stored
   snapshot on another fork, and a stored fork genesis are not offenses.
9. **Block challenges address the last milestone, and only its unfinal tail.**
   `DisputeInvalidBlockInStateProofApplyFraudProof` ([#L740](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L740))
   and `DisputeBlockAuthorNotParticipant` ([#L154](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L154)) name a
   `blockIndex` of the last milestone and carry no walk evidence. `_isBlockChallengeEligible`
   ([#L799](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L799)) delegatecalls the public `StateProofFacet.isBlockChallengeEligible`, which
   reads no walk ([StateProofFacet](./StateProofFacet.sol.md)); `_getLastMilestoneBlock`
   ([#L806](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L806)) reads the challenged block. Why: finalized history and dropped material carry
   other signers' agreement, so only the submitter's unfinal tail can punish the submitter, and the
   SDK reads the same public answer before it submits. The apply wrapper then requires the embedded
   block fraud proof to name exactly the challenged signed block ([#L748](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L748)). The validity of
   the whole proof is not checked here; the `DisputeInvalidStateProof` counter covers an invalid proof.
10. **The structure challenge needs no walk and no eligibility check.** `_handleDisputeInvalidBlockStructure`
    ([#L138](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L138)) asks the input-only `isInvalidBlockStructureInStateProof` for `blockIndex`
    of the last milestone ([#L147](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L147), [StateProofFacet](./StateProofFacet.sol.md)).
    Why: a malformed or forged block is never honest history, so the proof need not be a valid walk; a
    defect in an earlier milestone is not the submitter's tail and cannot be addressed.
11. **`DisputeInvalidStateProof` without posted data checks linkage with the walk.** When the dispute posted
    no auditing data, the handler requires the supplied genesis data to be linked to the fork and the last
    milestone to be final by everyone, then calls `isStateProofLinked`
    ([#L328](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L328)); an unlinked kept run kills the disputer. With posted data
    it calls `verifyStateProof` ([#L354](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L354)) and kills the disputer when it answers false
    ([#L360](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L360)). That includes a posted finalized state that is not the state of the walk's
    finalized snapshot ([StateProofFacet](./StateProofFacet.sol.md)): every auditor replays the tail
    from that state, so the dispute must post the state the chain's walk proves final.
12. **The header-mismatch check skips an undecodable block.** `_hasStateProofHeaderMismatch`
    ([#L824-L839](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L824-L839)) decodes each milestone block with `UtilityFacet.tryDecodeBlock`
    and skips a block that does not decode ([#L834](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L834)), so it answers "no mismatch" for that
    block and never reverts on it; the block-structure check judges it. The public predicate
    `hasStateProofHeaderMismatch` ([#L819-L821](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L819-L821)) and the handler
    `_handleDisputeStateProofHeaderMismatch` ([#L121-L128](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L121-L128)) are `view` because the
    decode is an external call to the utility facet. On chain, a `DisputeStateProofHeaderMismatch`
    proof against a dispute that also holds an undecodable block is judged on the decodable blocks
    instead of reverting. Why: an auditor's local check and the chain handler must give the same
    answer, and the local check must not fail on input the structure check already owns
    ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)).
13. **The timeout refutation reads the participants from the loaded state.** `executeStateTransition`
    leaves the transitioned state loaded, so the refutation's snapshot takes its participants from it
    with no further `setState` ([#L718](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L718)).
    Why: each `setState` of a large application state costs most of the dispute-execution budget.

## Specification contradictions

- **A failing proof with a zero declared target kills a valid dispute**
  ([`FIND-SECURITY-1-6SAJ4E`](../../../../../audit/open-findings.md#find-security-1-6saj4e)).
  `applyDisputeFraudProofs` kills the dispute when the handler's verdict equals the declared
  participant
  ([#L27-L30](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L27-L30)).
  Every handler returns `address(0)` for a failing proof
  ([#L102-L103](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L102-L103)),
  and the dispatcher does not reject a zero declared participant. So any caller that declares
  `address(0)` with a failing proof kills a valid committed dispute and slashes its disputer. This
  contradicts [`REQ-DIS-3-C4KYSF`](../../../../../specification/disputes/disputes.md#req-dis-3-c4kysf),
  which lets only an invalid committed dispute be killed.
