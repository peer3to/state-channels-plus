## Responsibility and observable boundary

Dispute fraud-proof application: skip already-killed, kill-period-open gate, dispatch across the
the current content and timeout families, valid → kill + slash disputer, invalid → slash submitter; plus the
timeout-evidence view predicates (calldata-posted validation, last-milestone finality, header
mismatch, inbound-hash validity).

## Key design decisions

The invalid-step handler authenticates and checks the selected step without first proving that auditing-data omission was permitted. It does not walk an unrelated final milestone. The auditor may still prefer the missing-data counter; full-payload copying and hashing remain part of the apply cost.

The facet applies below-anchor, timeout-superseded and same-height final-conflict counters through StateProofFacet. Invalid-state-proof dispatch checks one pointed step. Omission is permitted for empty genesis proof, a matching same-fork anchor in the LAST milestone, or finality by the committed historical everyone set. That availability set subtracts committed slashes; historical membership-hop unions do not. Balance evidence must name the actual latest claimed state. TimeoutThreshold remains direct signatures at the target height and author. Block-specific wrappers use indices in the original last milestone and the common eligibility predicate. See [DisputeFraudProofFacet.sol](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L273).

Dispute-fraud targets use the same bounded current eligibility as ordinary fraud proofs. Historical proof validation keeps its historical membership walk; eligibility is not inferred from old joins outside the current boundary. See [DisputeFraudProofFacet.sol](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L32).

1. **Kill is the only commitment-removal path**, pairing with the window bookkeeping's swap-removal — the order perturbation input to [`OQ-4-JGDCNX` (Dispute-reduction order-independence)](../../../../../verification/open-questions.md#oq-4-jgdcnx) originates here.
2. **Typed self-calls go through the manager interface, not the proxy contract.** The three
   operations this facet reaches on `address(this)` — the dispute-window creation timestamp
   ([#L482](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L482)), the state transition
   ([#L669](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L669)) and the milestone finality check
   ([#L828](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L828)) — are typed by
   [StateChannelManagerInterface](../../StateChannelManagerInterface.sol.md). The calls are
   unchanged; only the compile-time type is, which removes this facet's dependency on
   [StateChannelManagerProxy](./StateChannelManagerProxy.sol.md) now that the proxy no longer
   declares the routed functions.
3. **A listed slash set that is a subset reverts with both sets.**
   `_handleDisputeOnChainSlashesNotSubset` returns the disputer as the offender the moment one
   listed slash is absent from the chain's record; reaching the end means the proof was wrong and
   the call reverts with `RaceConditionOnChainSlashes(channelId, disputeSlashes, onChainSlashes)`
   ([#L387](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L387)).
   Slash-set contents are time-dependent, so the client classifying this race needs to know which
   slashes the two sides held, not how many: the arrays are already in memory at the revert, and
   the sets can differ while their counts agree. The site is a plain `revert`, so nothing is
   evaluated before the loop has proven the subset relation.
4. **Auditing-data omission finality is judged against the dispute's historic threshold set.**
   `_getHistoricThresholdSet` ([#L801](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L801)) reads the chain snapshot participants plus the joiners at
   or below the dispute's inbound anchor, minus `input.onChainSlashes` only. Its name sets it apart from the live
   `_canParticipateInDisputesNow` eligibility read. The disputer commits the slash list, so construction and every
   later proof read the same set; over-listing stays provable through `DisputeOnChainSlashesNotSubset`, and an unlisted
   slash only makes the threshold stricter. The participant half comes only from chain data, never from the
   dispute's own latest state, and cannot move while a proof can land: adoption targets only the latest undisputed
   fork and a disputed fork advances only by reduction ([StateSnapshotFacet.sol.md](StateSnapshotFacet.sol.md)).
5. **The inbound-anchor families stay as defence in depth.** Upload admits only a dispute anchored exactly at the
   chain's inbound head ([DisputeManagerFacet.sol.md](DisputeManagerFacet.sol.md)), so
   `DisputeInboundHashNotInChain` ([#L127](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L127)) and `DisputeInboundAnchorBehindLatestState`
   ([#L256](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L256)) are unreachable for committed disputes. Their handlers are kept unchanged.
6. **A timeout refutation replays only from the dispute's latest state.**
   `_validateTimeoutCalldataPostedProof` checks, before the replay
   ([#L652-L664](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L652-L664)), that the proof's latest state snapshot is the one the dispute's
   latest proved block commits to (or the fork's genesis snapshot) with
   `_isSnapshotLinkedToLatestBlock`, that the snapshot's `stateMachineStateHash` equals the hash of
   the machine state the replay starts from, and that the posted block's `previousBlockHash` is the
   hash of the latest proved block's signed bytes, `keccak256(encodedBlock)` (or of that genesis
   snapshot at genesis). The signed bytes are the block identity, as in the state proof's chain
   linkage and the client's `Block.hash`; hashing the re-encoded fields would reject an honest
   block built on a non-canonical but accepted encoding. The calldata-posted grace check compares
   the same signed-bytes hash. The blamed author signs
   and posts the block itself, so without these links it could post a block built on a made-up
   pre-state, name that pre-state in the proof, replay it successfully, and refute an honest timeout
   dispute, which slashes the honest disputer. A proof that fails a link returns `false`, so the
   submitter is slashed like any failed refutation. The same predicate backs the auditor's
   `validateTimeoutCalldataPostedProof` preflight, so an honest auditor never submits such a proof.
   The posted block's author signature is still not verified here
   ([`FIND-TIMEOUT-2-J7S0TS`](../../../../../audit/open-findings.md#find-timeout-2-j7s0ts)).

## Specification contradictions

- **A failing proof with a zero declared target kills a valid dispute**
  ([`FIND-SECURITY-1-6SAJ4E`](../../../../../audit/open-findings.md#find-security-1-6saj4e)).
  `applyDisputeFraudProofs` kills the dispute when the handler's verdict equals the declared
  participant
  ([#L27-L31](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L27-L31)).
  Every handler returns `address(0)` for a failing proof
  ([#L99-L101](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L99-L101)),
  and the dispatcher does not reject a zero declared participant. So any caller that declares
  `address(0)` with a failing proof kills a valid committed dispute and slashes its disputer. This
  contradicts [`REQ-DIS-3-C4KYSF`](../../../../../specification/disputes/disputes.md#req-dis-3-c4kysf),
  which lets only an invalid committed dispute be killed.

- **The timeout replay rebuilds a snapshot clients never sign**
  ([`FIND-TIMEOUT-4-5YNPT3`](../../../../../audit/open-findings.md#find-timeout-4-5ynpt3)).
  The `TimeoutCalldataPosted` replay numbers the posted block's snapshot
  `latestStateSnapshot.blockHeight + 1` and never applies the block's inbound `messageBlocks`
  ([#L683-L702](../../../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L683-L702)). Clients keep a first block at the genesis height 0 and apply
  inbound blocks to the inbound head and `totalDeposits`. So an honest posted block that is a first
  block or carries inbound messages fails the hash compare and cannot refute the timeout. This
  contradicts [`REQ-DIS-10-SAHJBN`](../../../../../specification/disputes/disputes.md#req-dis-10-sahjbn).
