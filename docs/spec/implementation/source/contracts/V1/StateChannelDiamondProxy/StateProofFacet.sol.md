## Responsibility and observable boundary

Exposes the state-proof walk and counter predicates over shared internal walk logic. It verifies milestone evidence and reports retained positions; it does not execute application transitions or mutate escrow.

## Key design decisions

`verifyMilestones` selects the same-fork non-genesis anchor or fork genesis. A matching anchor may
be inside a milestone. Entire obsolete milestones and pre-anchor blocks are skipped. Empty
milestones mean genesis; an all-skipped nonempty walk may succeed but a below-anchor claim remains
counterable. The common walk owns signer unions, consumed inbound JOINs and block checks.

`isStateProofStepInvalid` verifies only the pointed milestone or block step with authenticated start
snapshots; it does not re-walk earlier hops. The facet also owns below-anchor, timeout supersession,
final-state conflict and block-challenge eligibility predicates. Conflict compares exactly the
proved final height and can name an anchor block. Block-specific tail challenges instead protect
the greater of the last milestone's first block and matching anchor, with the genesis-zero
exception. Whole-proof data binding still grows with supplied proof size.
