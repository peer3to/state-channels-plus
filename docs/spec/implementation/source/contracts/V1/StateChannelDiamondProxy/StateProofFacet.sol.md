## Responsibility and observable boundary

The routed state-proof entry points. A `StateProof` is only a list of milestones; the latest state
is the last block of the last milestone, and an empty proof is the fork genesis
([ProofTypes.sol](../types/ProofTypes.sol.md)). This facet owns no walk logic: every finality
and linkage answer comes from the one walk `_walkStateProof` in
[StateChannelCommon](./StateChannelCommon.sol.md). The facet exposes:

- `verifyMilestones(ProofWalkInput) → ProofWalkResult` ([#L91](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L91)): the walk
  with finality, from the start that this contract's storage holds;
- `isStateProofLinked(channelId, forkId, stateProof, genesisData)` ([#L96](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L96)):
  the same walk in linkage-only mode;
- `getAnchorSnapshot(channelId, forkId)` ([#L82](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L82)): the on-chain
  snapshot and whether a proof of that fork can start from it;
- `isBlockChallengeEligible(dispute, blockIndex)` ([#L114](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L114)): whether a
  block challenge may name that block of the last milestone;
- `verifyStateProof(dispute, auditingData)` ([#L40](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L40)): the full dispute
  check against posted auditing data;
- `isCorrectLatestState(dispute, genesisData)` ([#L8](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L8));
- the input-only block-structure predicates `isInvalidBlockStructureInStateProof`
  ([#L143](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L143)) and `findFirstInvalidBlockStructureInStateProof`
  ([#L156](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L156));
- `isMilestoneFinal` ([#L192](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L192)) for one milestone against one threshold set.

Dispute fraud proofs, the snapshot-update path, the SDK prover and auditor, and spectator sync read
these same entries.

## Key design decisions

1. **One walk, two modes, one owner.** `verifyMilestones` calls `_walkStateProof(input,
stateSnapshots[channelId], true)` ([#L92](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L92)) and
   `isStateProofLinked` calls it with `checkFinality` false and no milestone snapshots
   ([#L103](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L103)–[#L104](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L104)).
   The walk itself lives in [StateChannelCommon](./StateChannelCommon.sol.md), so the dispute fraud
   proofs ([DisputeFraudProofFacet](./DisputeFraudProofFacet.sol.md)), the same-fork snapshot update
   ([StateSnapshotFacet](./StateSnapshotFacet.sol.md)) and the local trusted-start entry
   ([LocalDiamond](./LocalDiamond.sol.md)) cannot disagree with it. Why a linkage-only mode: the
   `DisputeInvalidStateProof` fraud proof without milestone snapshots still has to show that every
   kept run links ([DisputeFraudProofFacet](./DisputeFraudProofFacet.sol.md)); in that mode only
   `valid` is usable.
2. **The anchor is public and read from storage.** `getAnchorSnapshot` wraps
   `_getAnchorSnapshot` ([#L87](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L87)): the stored
   snapshot and `canUseOnChainSnapshot`, true when it is on the fork and is not that fork's genesis.
   No block commits to the genesis, so a proof cannot start from it; the walk then starts from the
   fork genesis. The SDK reads this one answer instead of deriving it. Production entries always walk from storage; only
   [LocalDiamond](./LocalDiamond.sol.md) can supply another start, and no production route exists
   for it ([StateChannelManagerProxy](./StateChannelManagerProxy.sol.md)).
3. **`verifyStateProof` is a fixed sequence of checks over the posted data.** The auditing data must
   hash to the dispute's `disputeAuditingDataHash` ([#L46](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L46));
   the walk over the dispute's proof and the posted milestone snapshots must be valid
   ([#L57](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L57)); the posted finalized state must hash to the state-machine-state
   commitment of the walk's finalized snapshot ([#L63](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L63)–[#L68](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L68));
   `isCorrectLatestState` must hold ([#L70](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L70)); and
   the posted latest snapshot must be the one the dispute commits
   ([#L75](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L75)).
   The former public auditing-data commitment helper is gone; this first check is its only owner.
   There is no separate genesis check: the walk checks the genesis data only when it reads it, so a
   proof from a usable on-chain anchor needs no genesis data
   ([StateChannelCommon](./StateChannelCommon.sol.md)).
   A proof whose every milestone ends below a same-fork on-chain start is a valid walk (its
   milestones are dropped), so `verifyStateProof` accepts it; the dedicated
   `DisputeStateProofBelowOnChainAnchor` fraud proof counters such a dispute
   ([DisputeFraudProofFacet](./DisputeFraudProofFacet.sol.md)).
   Why the finalized-state check: every auditor replays the unfinal tail from the posted finalized
   state, so it must be the state the chain's walk proves final. It is the state of the snapshot where
   the walk from the stored start ends: the on-chain anchor when the anchor run holds the start and no
   later milestone is proven, else the last threshold-proven milestone snapshot, or the fork genesis.
   Another state of the same fork, also an earlier proven one, and empty bytes answer false, and
   `DisputeInvalidStateProof` then kills the dispute. The walk's start is read at verification time,
   so a posting built against an older start can stop matching
   ([`OQ-SPEC-POSTED-STATE-RACE-1-1ZM6XN`](../../../../../specification/open-questions.md#oq-spec-posted-state-race-1-1zm6xn), deferred by the engineer).
4. **The latest state is the last block of the last milestone, or the genesis.** `isCorrectLatestState`
   takes the last block through `_getLatestSignedBlock` ([utils/DisputeUtils](./utils/DisputeUtils.sol.md))
   and compares the state commitment of that block with the claim
   ([#L18](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L18)).
   For an empty proof it rebuilds the fork genesis snapshot (data linked to the fork, timestamp from
   `_getGenesisTimestamp`) and compares its hash ([#L31](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L31)..[#L37](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L37)).
   An undecodable last block answers false; it never reverts.
5. **Structure checks are input-only and address the last milestone.**
   `isInvalidBlockStructureInStateProof(stateProof, blockIndex)` judges block `blockIndex` of the
   last milestone of the submitted proof; an empty proof or an index past that milestone is no
   offense ([#L148](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L148)–[#L150](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L150)).
   `_isInvalidBlockStructureInStateProof` ([#L169](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L169)) flags a
   block that is not author-signed ([#L175](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L175)) and,
   after the first block of the run, one that does not decode or does not link to its predecessor by
   hash and height + 1 ([#L188](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L188)).
   The first block of a run needs no predecessor: a compact proof may start a run anywhere. No chain
   storage is read, so the answer does not depend on the walk start. Why: a malformed or forged block
   is never honest history, so the fraud proof that uses this predicate needs no walk.
6. **`findFirstInvalidBlockStructureInStateProof` scans the last milestone only** and returns
   `(found, blockIndex)` ([#L162](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L162)..[#L164](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L164)).
   Only the last milestone can hold the dispute submitter's unfinal blocks, and the structure fraud
   proof accepts only that milestone ([DisputeFraudProofFacet](./DisputeFraudProofFacet.sol.md)), so a
   finding elsewhere could not be used. The index gives fraud-proof construction its objective
   citation ([`REQ-ENFPROOF-3-EEDR2Y` (Falsifying detail on failure)](../../../../../specification/enforcement/proof-verification.md#req-enfproof-3-eedr2y)).
7. **Block-challenge eligibility reads no walk.** `isBlockChallengeEligible(dispute, blockIndex)`
   ([#L114](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L114)) answers true only when the proof has a milestone, `blockIndex` is
   inside the last milestone, the last milestone's first block and the challenged block decode
   ([#L116](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L116)–[#L123](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L123)), `blockIndex` is at or after the tail start
   ([#L134](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L134)), and, when the proof can start from the on-chain anchor, the challenged
   block's height is above the anchor height ([#L135](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L135)). The tail start is
   `anchor height - first height + 1` when the anchor is usable and the last milestone's first height
   is at or below it, 0 when the only milestone starts at block 0 (the anchor is not usable), else 1
   ([#L128](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L128)–[#L133](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L133)). Why: only the dispute submitter's unfinal tail can
   punish the submitter. Every milestone before the last and the first block of the last are
   threshold-final, and blocks up to the anchor are final on chain. A sole milestone from genesis
   block 0 has no final point before it, so block 0 is eligible even when it is threshold-final.
   Whether the whole proof is valid is `DisputeInvalidStateProof`'s concern, so no walk runs. The
   check is a public `view` so the SDK reads the same answer; the fraud-proof facet delegatecalls it
   ([DisputeFraudProofFacet](./DisputeFraudProofFacet.sol.md)).
8. **`isMilestoneFinal` reuses the run walker.** It walks the whole milestone with the given
   threshold set through `_walkMilestoneBlocks` and reports final when every set member signed
   ([#L198](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L198)..[#L200](../../../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L200)).
   An unlinked or undecodable milestone answers `(false, 0)` instead of reverting.

## Inputs, outputs, state, and side effects

| Aspect       | Contents                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------ |
| Inputs       | Routed calls from the manager (delegatecall context): proofs, walk inputs, dispute and auditing data.              |
| Outputs      | Verdicts, the `ProofWalkResult`, the anchor, and the first invalid structure position.                             |
| Owned state  | None declared (shared layout via inheritance); reads the stored snapshot, dispute windows and inbound blocks only. |
| Side effects | None: every entry is `view` except `verifyStateProof` and `isMilestoneFinal`, which write nothing.                 |

## Assumptions, dependencies, trust boundaries, and limits

- Executes only in the manager's delegatecall context (except UtilityFacet's plain calls).
- Deployment-size budget applies per deployable ([architecture view](../../../../views/architecture/contracts/architecture.md) §3 measurements).
- The walk has no gas bound: a very large proof can exceed the call's gas (the open `TODO` in
  `_walkMilestoneBlocks`, [StateChannelCommon](./StateChannelCommon.sol.md)).
- The walk trusts the stored snapshot as final. The stored snapshot cannot advance on a disputed
  fork ([StateSnapshotFacet](./StateSnapshotFacet.sol.md)), so every check of one dispute game sees
  the same walk start.

## Specification adherence

- Operation semantics per the owning protocol documents; composition rules per [contracts.md](../../../../../specification/enforcement/contracts.md).
- Every entry answers `false` (or an invalid `ProofWalkResult`) for undecodable or malformed input
  instead of reverting, so a verdict never depends on a revert.
