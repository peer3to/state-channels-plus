## Responsibility and observable boundary

The ordered predicate chain of serialized validation: channel, channel-open, author-membership
(local anchor with on-chain fallback), conflict classification (double-sign / invalid-transition
/ wrong-genesis / unattributable), live gates, linkage, scheduled-leader, and the time rules —
objective timestamp via the canonical predicate with calldata-timestamp recovery retry, on-chain
post timing, and the subjective agreement window (live only, never evidence). A dispute-replay entry
carries its predecessor on the dispute's own chain; author membership, linkage and the time rules
judge it from that predecessor, and every other entry from the stored history below its height.

## Key design decisions

Confirmation classification catches recovery failure per signature and collects unrecoverable values for the strategy; successful recoveries populate Block's existing cache. One bad confirmation cannot abort classification of the remaining good ones. Block's existing recovery cache remains the primitive. Author authentication stays separate, and each pipeline invokes its strategy hook with the computed rejected set. See [normalizeConfirmationSignatures](../../../../../../../src/stateManager/ingest/ValidationService.ts#L56-L71).

Every strategy receives an out-of-window subjective outcome. The strategy owns acceptance or refusal and its diagnostic log; the shared pipeline retains objective timing checks. See [ValidationService.ts](../../../../../../../src/stateManager/ingest/ValidationService.ts#L672-L673).

Subjective timestamp outcomes are owned by the selected strategy. Proof replay accepts historical suffixes through its override; live validation retains its timing refusal. See [ValidationService.ts](../../../../../../../src/stateManager/ingest/ValidationService.ts#L664-L673).

Failed time-check metadata moves to LoggerUtils with the already-captured now value. Validation thresholds, strategy instanceof policy and return values remain here. See [ValidationService.ts](../../../../../../../src/stateManager/ingest/ValidationService.ts#L559-L568).

After the conflict check finds no stored block at the block's height, a height below the next expected height lies under the installed history. With the live ordering gates on, the pipeline calls `blockIsBelowInstalledHistory` and continues only on `SUCCESS`; the future-height gate runs first. See [ValidationService.ts](../../../../../../../src/stateManager/ingest/ValidationService.ts#L160-L176).

1. **Every predicate against one pre-state** under the caller's mutex ([`REQ-BLOCK-PIPE-2-PCXNT6` (Complete pre-execution validation)](../../../../../specification/block-progression/block-processing.md#req-block-pipe-2-pcxnt6)).
2. **Objective time checks run the exact fraud-proof struct through the mirrored predicate** — the check and the future proof cannot disagree ([`REQ-MIRROR-1-XCY9CB` (Constrained equivalence)](../../../../../specification/enforcement/local-mirror.md#req-mirror-1-xcy9cb)).
3. **Retroactive legitimization:** a failing timestamp first triggers predecessor-calldata recovery and a re-run — an on-chain post can grant the window that makes it valid.
4. **Conflict taxonomy decides attribution:** same author → double-sign; linked-to-our-predecessor → author's invalid transition; height-0 → wrong genesis; unlinked → nobody to slash. An identical stored block (same hash) is no conflict ([#L460-L466](../../../../../../../src/stateManager/ingest/ValidationService.ts#L460-L466)): live ingest merges a stored block before validation, so only dispute replay re-judges one, and its honest author must not be charged a double sign. The conflict check keeps its stored-history linkage ([#L478-L492](../../../../../../../src/stateManager/ingest/ValidationService.ts#L478-L492)): a replayed block of another history is conflicting-but-not-linked, which the dispute strategy continues.
5. **The subjective window judges live arrivals only.** SpectatingValidationStrategy accepts the subjective timing outcome for a verified synchronization proof; every objective check still runs. The replayed suffix is proven history
   and, by construction of the block queue's expiry probe, at least one window old, so parking it left a
   participant's recovery unable to apply the suffix ([synchronization.md](../../../../../specification/peer-communication/synchronization.md) step 13).
6. **No block decoding or author authentication here.** Stage-1 authentication — `Codec` decoding
   through `Block.tryFromBlockConfirmation` and the author check `Block.isAuthentic` — runs where a
   confirmation enters: [BlockQueueManager](BlockQueueManager.ts.md) for network intake and
   [BlockIngestService](BlockIngestService.ts.md) for struct/proof replay (engineer decision
   2026-09-27, review item LO3: `Codec` owns decoding, `ValidationService` has no part in it). The
   former `isBlockConfirmationAuthentic` (a local EVM call to the removed `isBlockAuthentic`) is
   gone. This file applies the contracts' signature acceptance rule only to confirmation
   signatures: `normalizeConfirmationSignatures` ([#L61](../../../../../../../src/stateManager/ingest/ValidationService.ts#L56-L71)) recovers each through
   `Block.signatureToAddress`, so an encoding the contracts reject fails recovery and is stripped
   and charged to its supplier like any unrecoverable signature (the signature carve-out of
   [`INV-MIRROR-1-VAF778` (Single implementation)](../../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778)).
7. **One owner for "what a block is judged from".** `previousOf(entry)` ([#L341-L350](../../../../../../../src/stateManager/ingest/ValidationService.ts#L341-L350)) returns the
   entry's replay predecessor, else `Storage.getPreviousBlockAndSnapshot` (the stored block below
   the block's height and its snapshot, the fork genesis at height 0). The author check
   ([#L357](../../../../../../../src/stateManager/ingest/ValidationService.ts#L357)), the linkage check ([#L179](../../../../../../../src/stateManager/ingest/ValidationService.ts#L179)) and the time rules ([#L523](../../../../../../../src/stateManager/ingest/ValidationService.ts#L523), through
   `FraudProofService.buildInvalidTimestampProof`, [#L538](../../../../../../../src/stateManager/ingest/ValidationService.ts#L538)) all read it. Why: on an alternate
   history the stored block at the same height is not the block a dispute's block extends; judging
   from it made an honest auditor unable to judge the dispute's chain.
8. **A strategy SUCCESS from the author check continues the chain** ([#L102-L115](../../../../../../../src/stateManager/ingest/ValidationService.ts#L102-L115)). The live
   strategies return `DISCONNECT`, so live behavior is unchanged; the dispute strategy returns
   `SUCCESS` when the block's resulting snapshot is not held, and the later checks (leader,
   transition, participant union) judge the outsider author.
9. **The leader check reads the machine as positioned by the caller** ([#L195-L210](../../../../../../../src/stateManager/ingest/ValidationService.ts#L195-L210)). Live
   pipelines execute in order and already hold the predecessor state; dispute replay is positioned
   at the predecessor's state by [BlockIngestService](BlockIngestService.ts.md). No strategy hook
   positions the machine.
