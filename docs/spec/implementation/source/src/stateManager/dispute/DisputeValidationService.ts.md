## Responsibility and observable boundary

Audits a committed dispute, returning valid or storing one supported counter and returning invalid. Missing required evidence and execution/RPC failures throw. Audit does not advance the active view or sign replayed blocks.

## Key design decisions

Availability, below-anchor and verified-final-state conflict checks can end audit before the
normal proof tiers. The conflict counter compares the block at exactly the verified final height;
it does not infer old ancestry. Exact-height proofs retain later virtual votes and include stored audit-final points above the active view. The same conflict check runs after each successful asynchronous walk, before replay, and after a refused proof persistence, so
concurrent audits retain one final block and counter the conflicting dispute rather than throwing
on a storage collision ([post-walk conflict check](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L246)).
Shared AgreementManager tiers own proof verification. Replay uses
the successful tier's verified snapshot/state and retries from the chain anchor after a completed
local replay failure. Thrown failures never become false verdicts or fallback triggers.

Block-specific counters use positions in the original last milestone and canonical eligibility.
Malformed retained bytes are invalid evidence; raw-struct logging must not throw while describing
them. Skipped prefixes are neither accused nor persisted. Balance validation uses the latest
claimed state, while an older dispute may be answered with newer evidence without backward replay.
Required missing replay state or counter snapshots are fatal. Canonical predicates and preflight
prevent a local stale answer from becoming an unsupported on-chain accusation.

## Assumptions, dependencies, trust boundaries, and limits

- Kill-window deadlines inherit chain-observation freshness; staleness-sensitive checks re-verify against the chain.
- A local answer that clears the dispute is accepted without a chain read. A lagging mirror that
  wrongly clears a fraudulent dispute makes this auditor miss the challenge; every other honest
  auditor still audits it (the residual stated in [`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).
- Shared proof tiers distinguish completed false results from thrown failures; local and chain errors propagate without storing a counter.

## Specification adherence

- Ordered complete verification with no later-step legitimization ([`REQ-DISPUTE-PIPE-2-MJRJV1` (Ordered complete verification)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-2-mjrjv1)); auditor equivalence by construction ([`INV-DISPUTE-PIPE-1-BN0K81` (Equivalent audit)](../../../../../specification/disputes/dispute-processing.md#inv-dispute-pipe-1-bn0k81)).
- The contract-owned inbound-anchor predicate runs against the verified posted snapshot or the
  snapshot stored under the dispute's pinned hash before local auditing reconstruction and the
  linkage/output shortcut, so linked auditing data cannot hide a stale claimed anchor.
- Every audit predicate reads the local diamond first, accepts only the answer that clears the
  dispute, and lets the chain decide the answer that would produce a fraud proof; no thrown failure becomes a verdict ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).
