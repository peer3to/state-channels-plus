## Responsibility and observable boundary

The auditor: the 17-check ordered audit (inbound-tip reality, proof decode with the unjudgeable
split, header match, block structure, posted-data verification vs final-anchor + local-anchor
availability, suffix replay through the pipeline, latest-state consistency, slash-subset with
chain re-check, balance invariant, disputer-latest-state, the five timeout checks with self-
slash preflight, stated reason, output correctness). Returns invalid iff exactly one dispute
fraud proof was stored.

## Key design decisions

The always-true local conjunct is removed. Every actual dispute validation condition and strategy outcome remains required. See [DisputeValidationService.ts](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L50).

1. **Every predicate with an on-chain twin runs by staticCall against the canonical logic** so the auditor can never disagree with the apply-handler ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)). The call goes to the local diamond first; only the answer that would make this node act against the disputer is confirmed on-chain ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)). The stateful predicates — last milestone final by everyone, correct latest state, balance invariant — run through private helpers built on `preferLocal` that accept a local `true` and let the chain confirm a `false` before a fraud proof is built ([#L857-L916](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L857-L916)); state-proof verification does the same ([#L254-L283](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L254-L283)). The pure `hasStateProofHeaderMismatch` runs on the local diamond only: it reads no replicated state, so the mirror computes exactly what the chain would ([#L94](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L94)).
2. **Unjudgeable-skipped-as-valid:** undecodable-without-posted-data and locally-unanchored disputes are abstained from, never killed on ignorance — honest-peer coverage carries them.
3. **Preflight before self-slashing proof types** (`validateTimeoutCalldataPostedProof.staticCall`) — an auditor never submits a proof that would slash itself. The local mirror's "invalid" is accepted (the proof is not pursued, no chain read); its "valid" is confirmed on-chain before the proof is stored ([#L690-L702](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L690-L702)).
4. **Stop at the first failure with exactly one stored proof;** invalid-without-proof throws as an internal error. The abort log names the refused confirmation with `LoggerUtils.getBlockConfirmationStructMetadata`
   on the raw struct ([#L315-L323](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L315-L323)), not a decoded `Block`: the replayed bytes may not decode, and a decode
   throw in the log would turn a stored fraud proof into an internal error.
5. **The pinned inbound anchor is checked before linkage shortcuts.** After state-proof replay,
   the validator uses the verified posted snapshot or the snapshot stored under the dispute's
   pinned hash. When that snapshot is available, it is checked before rebuilding local auditing
   data, so supplied auditing data cannot replace the anchor used by the objective predicate. If a
   non-posted snapshot is unavailable, the auditor first rejects an inconsistent pinned hash, then
   abstains without constructing a proof when the commitment itself is consistent.

## Assumptions, dependencies, trust boundaries, and limits

- Kill-window deadlines inherit chain-observation freshness; staleness-sensitive checks re-verify against the chain.
- A local answer that clears the dispute is accepted without a chain read. A lagging mirror that
  wrongly clears a fraudulent dispute makes this auditor miss the challenge; every other honest
  auditor still audits it (the residual stated in [`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).
- `tryVerifyStateProof` returns "invalid" only for a chain revert (`ethers.isError(error, "CALL_EXCEPTION")`)
  and rethrows every other error ([#L272-L282](../../../../../../../src/stateManager/dispute/DisputeValidationService.ts#L272-L282)). A local revert has already fallen back to
  the chain inside `preferLocal`; a transport failure, a disposed runtime, or a non-revert local
  failure is no verdict and surfaces as an audit error instead of a `DisputeInvalidStateProof`
  (resolved [`FIND-MIRROR-1-YECYEQ`](../../../../../audit/open-findings.md#find-mirror-1-yecyeq)).

## Specification adherence

- Ordered complete verification with no later-step legitimization ([`REQ-DISPUTE-PIPE-2-MJRJV1` (Ordered complete verification)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-2-mjrjv1)); auditor equivalence by construction ([`INV-DISPUTE-PIPE-1-BN0K81` (Equivalent audit)](../../../../../specification/disputes/dispute-processing.md#inv-dispute-pipe-1-bn0k81)).
- The contract-owned inbound-anchor predicate runs against the verified posted snapshot or the
  snapshot stored under the dispute's pinned hash before local auditing reconstruction and the
  linkage/output shortcut, so linked auditing data cannot hide a stale claimed anchor.
- Every audit predicate reads the local diamond first, accepts only the answer that clears the
  dispute, and lets the chain decide the answer that would produce a fraud proof; no failure other
  than a chain revert becomes a verdict ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).
