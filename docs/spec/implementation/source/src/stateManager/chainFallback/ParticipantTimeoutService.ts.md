# ParticipantTimeoutService.ts — Source Report

> **Source:** [ParticipantTimeoutService.ts](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Dispute pipeline](../../../../views/architecture/sdk/dispute-pipeline.md)

## Responsibility and observable boundary

Schedules checks for a silent writer, recovers relevant calldata and constructs a timeout only while its evidence remains valid. The existing scheduler also owns the fresh check after a chain-time refusal, and the one forced check a rejecting chain-committed validation asks for.

## Key design decisions

Scheduling, retry admission and the final pre-store check use the same live-fork predicate. A block accepted while timeout construction awaits its chain read prevents timeout storage. See [ParticipantTimeoutService.ts](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L37).

1. [scheduleCheck](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L31) refuses disposed runtimes and obsolete forks before allocating a timer. Every scheduled callback enters the same timeout check.
2. [tryTimeoutParticipant](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L54) checks current membership, accepted blocks, local deadline, window creation and predecessor/target calldata. A local deadline or pending validation causes a scheduled recheck; an older dispute window stops the claim.
3. [createTimeOutDispute](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L367) builds the timeout from stored predecessor evidence and rechecks fork/disposal and accepted-block state after awaited reads, before storing the claim and calling the normal dispute owner.
4. A check that meets a posted commitment for its slot hands that calldata back to the block pipeline and returns ([onPostedCommitment](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L329)); only a check marked forced — which none but the rejecting chain-committed validation asks for — submits a timeout over a commitment, and only while the target is still the next writer at the next unfilled height, decided under the state mutex. The forced flag rides through every self-reschedule, so a forced check that waits stays forced.
5. A check whose height has no stored predecessor block or genesis snapshot returns ([tryTimeoutParticipant](../../../../../../../src/stateManager/chainFallback/ParticipantTimeoutService.ts#L54)): the check armed for the predecessor's own slot judges it, and reading a deadline from absent evidence would throw inside a scheduled task.
6. DisputeManager owns decoding the refused transaction, clearing its marker and releasing its mutex. It passes the attempted slot and the chain timestamp difference to this existing scheduler. This service reconstructs evidence on wake-up; it never resends an old transaction.

## Inputs, outputs, state, and side effects

Constructor: StateManager and child logger. scheduleCheck takes fork, height, participant, delay and reason. tryTimeoutParticipant reads membership, block/snapshot storage, Clock, timeout configuration, calldata recovery and mirror commitments. scheduleTimeoutParticipantRetry delegates the existing one-second validation retry. createTimeOutDispute stores a TimeoutStruct and awaits dispute submission. Timer ownership remains TimeoutManager; the service adds no retry counter or second queue.

## Assumptions, dependencies, trust boundaries, and limits

The chain remains authoritative for timestamp and window admission. Local Clock is an estimate; repeated refusals may need repeated checks. A retry is not guaranteed to succeed after one second. Membership, calldata and stored-block checks remain the ordinary timeout path. The scheduler does not change protocol timing or make an old window eligible.

## Specification adherence

A posted commitment alone never forces: the block goes back to the pipeline and the verdict decides. A timestamp refusal re-enters the ordinary timeout decision with current state. Completed block arrival, disposal and fork replacement stop obsolete work.
