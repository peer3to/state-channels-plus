# StateApplicationService.ts — Source Report

> **Source:** [src/stateManager/snapshotUpdate/StateApplicationService.ts](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts) > **Status:** Authored — engineer verification pending.

## Responsibility and observable boundary

Participation status remains protective: an installed local participant becomes PARTICIPATING; a missing signer becomes SYNCED only if chain membership is absent too. Successful fork replacement settles the previous reduction and schedules the existing timeout/readiness follow-ups. Caller verification remains required.

## Key design decisions

An unlisted pending signer stays pending while its unobserved join may still land (`MembershipService.canOwnJoinStillLand`); an observed join already landed. Installation checks this before publishing status. Seating calls onJoinSeated to clear force-join tracking; unlisted state becomes SYNCED only when the authorization is closed. Existing failure rollback and abort order remain. See [StateApplicationService.ts](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts#L203).

Successful snapshot/genesis application replaces the plain off-chain member set. The publication call passes only participant addresses.

Both installs share one staged path. Prepare saves the previous VM state, writes the candidate and makes the participant/status/next-author reads; nothing in storage, fork or status changes yet, but the VM already holds the new state, and a reader outside the mutex can see it ([`FIND-STATE-2-4BH3Y1`](../../../../../audit/open-findings.md#find-state-2-4bh3y1)). A failed read restores the VM and throws. Commit then persists the snapshot and state, swaps the fork, publishes eligibility, recomputes the status and schedules follow-ups with no await in between. General adoption takes an optional `persistHistory` step from its caller and runs it first in the commit, so a sync's history becomes visible in the same synchronous step as the fork swap; when that step stores nothing (a proof conflict found at commit) the VM is restored and nothing is committed (false). Reduction genesis keeps its final shouldCommit guard and its abort on a failed read; only committed genesis publishes the new eligibility set. Cancellation does not publish membership or fork. A later replay failure of the sync is not rolled back here. See [unsafeSetLatestState](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts#L51).

Reduction application accepts the prepared genesis snapshot without rebuilding it. Ordinary reductions obtain it from `ReductionManager.prepareReducedGenesis`; final disputes supply their own snapshot with the dispute-creation timestamp. The prepare, commit guard and follow-up order are unchanged.

Signer membership reads delegate to MembershipService; this file carries no duplicate address comparison. See [StateApplicationService.ts](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts#L196).

The on-chain signer lookup delegates to the membership union predicate and retains the existing local short-circuit. See [StateApplicationService.ts](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts#L195-L196).

Error text delegates to the dependency-free errorMessage helper. Existing catch policy, stack fields, log messages and error propagation remain at this call site. See [StateApplicationService.ts](../../../../../../../src/stateManager/snapshotUpdate/StateApplicationService.ts#L8).

## Inputs, outputs, state, and side effects

Accepts the prepared snapshot/application inputs and applies them to the live state manager through the existing ordered update flow. Failure reporting uses the same error text and preserves its original error and stack handling.

## Assumptions, dependencies, trust boundaries, and limits

The unsafe methods require verified snapshot inputs and the caller's mutex. Inspection failure restores the prior VM state before anything is published. Reduction read failure retains its existing abort policy. SpectateService passes its verified history as `persistHistory`, so nothing of a sync is stored before the install commits; tail replay after the install is not rolled back on a later failure, and the install is not cancelled when an admission candidate expires.
