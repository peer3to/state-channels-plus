## Responsibility and observable boundary

The participant's central coordinator and the serialized half of the block pipeline: the
execution mutex; `onBlockConfirmation` (fork re-check, authenticate, ordered validation via the
validation service, VM-snapshot execute-and-restore, commitment comparison, signer-union check);
`playTransaction` (local authoring); `success()` (status/join promotion, persist-then-sign-then-
gossip commit order, exit path, calldata-post and next-author-timeout scheduling);
`tryMergeStoredBlockConfirmation`; `tryTimeoutParticipant` (timeout detection with calldata race
checks); `setLatestState`/`unsafeSetGenesisState` (fork transition); status/lifecycle, the non-terminal
`resetChannel()` that hands the runtime back to its pre-channel state, and disposal.

## Key design decisions

Disposal releases the state-manager logger subtree without cascading to its parent root logger. Parent/root cleanup owns that parent; independent discovery diagnostics must survive state-manager cleanup.

The public active-fork predicate requires both a live runtime and equality with its current fork; disposal and a real successor transition are separate component obligations. See [StateManager.ts](../../../../../../src/stateManager/StateManager.ts#L298).

isActiveFork owns the shared live-runtime and current-fork predicate. Live arrivals select the live strategy for pending and participating peers. Proof replay uses the shared spectating strategy, which delegates committed-peer fraud reactions to the live strategy. See [StateManager.ts](../../../../../../src/stateManager/StateManager.ts#L298).

Error text delegates to the dependency-free errorMessage helper. Existing catch policy, stack fields, log messages and error propagation remain at this call site. See [StateManager.ts](../../../../../../src/stateManager/StateManager.ts#L1).

1. **One mutex, three acquisition sites** (`onBlockConfirmation`, `playTransaction`, `setLatestState`) — application of state transitions is the only serialized regime; everything else runs as scheduled tasks outside it ([`REQ-BLOCK-PIPE-5-WJ31RG` (Pre-execution merge layer)](../../../../specification/block-progression/block-processing.md#req-block-pipe-5-wj31rg) boundary).
2. **VM snapshot-and-restore around execution.** Any non-success exit restores the pre-transition state before the mutex releases; once the block persists, the restore is disarmed so post-commit side-effect failures never rewind committed state ([`INV-BLOCK-PIPE-1-1AB2ME` (Atomic ordered commit)](../../../../specification/block-progression/block-processing.md#inv-block-pipe-1-1ab2me)).
3. **Persist before sign before gossip.** Signing reads resulting participants from storage; gossip strictly follows persistence so echoes merge as duplicates ([`REQ-BLOCK-PIPE-7-FYE9VJ` (Commit before publish)](../../../../specification/block-progression/block-processing.md#req-block-pipe-7-fye9vj)).
4. **The forfeit rule in `shouldSignBlock`:** never sign a calldata-posted block when we are the next author — signing would surrender the extra time the post granted ([time.md](../../../../specification/protocol-model/time.md)); the full sign-condition set implements [`REQ-BLOCK-PIPE-10-PHAKE2` (Counter-signing policy)](../../../../specification/block-progression/block-processing.md#req-block-pipe-10-phake2).
5. **Timeout detection with race recovery:** recover the predecessor's posting first (may grant the target time), then the target slot's commitment — commitment-without-accepted-block yields a _forced_ claim ([`REQ-DIS-10-SAHJBN`](../../../../specification/disputes/disputes.md#req-dis-10-sahjbn)).
6. **Fork transition is the single re-anchoring point:** `setLatestState` swaps fork id, recomputes status from the new participant set (exclusion aborts), reschedules timeouts, and drains queues.
7. **Custom RPC disposal precedes dependency teardown.** The root may settle waits that still need timeout and P2P services, so its rejection is retained while the remaining runtime cleanup completes and is rethrown only afterward.
8. **The contract owns live join eligibility.** The composed
   `MembershipService.getOnChainThresholdSet` delegates to the manager contract and returns its
   address set to SDK callers. TypeScript does not maintain a second snapshot ∪ pending − slashed
   formula.
9. **Discovery is a no-channel lifecycle.** The canonical member meanings live beside the `Status`
   enum; this class stores and transitions that value without repeating the taxonomy. `DISCOVERING`
   means one active caller topic and no selected channel ID. `NOT_OPENED` has no active lobby and may
   be clean with no ID or hold one concrete pre-open target. Setting a channel ID remains explicit;
   discovery never clears an existing role or ID on the caller's behalf.
10. **`resetChannel()` releases a channel without retiring the runtime** ([#L311](../../../../../../src/stateManager/StateManager.ts#L311)).
    The order is load-bearing and is the reason this is one method rather than a set of cleanup
    calls at the leave site: producers stop first (`blockQueueManager.reset()`,
    `reductionManager.reset()`), then `clearChannelId()` detaches the provider log filter and
    unbinds the dispute manager and event sync, then already scheduled chain-log work is drained
    through `stateChannelEventListener.drain()` ([#L333](../../../../../../src/stateManager/StateManager.ts#L333)) — the same bounded wait
    `stop()` uses, and now a checked one: a drain that ran out of its bound with work still running
    throws ("Chain-log work for the channel left did not finish; the runtime cannot be reused"),
    because a handler that outlives the bound would resume against the next channel, and the caller
    turns that throw into a terminal shutdown rather than handing the runtime on — then the
    event-sync and event-handler dedupe maps go, then peers and
    channel-scoped RPC state through `p2pManager.resetChannel()` (the manager remembers the
    channel's discovery key itself), then `timeoutManager.cancelAllTasks()`, and only last, under
    the block-work mutex, `storage.clear()` and the `NOT_OPENED` status ([#L348](../../../../../../src/stateManager/StateManager.ts#L348)). Clearing storage earlier would
    let an ingest or block production already in flight read a half-cleared store or write into
    the next channel's. The runtime then reads as pre-channel: zero fork id, `NOT_OPENED`. The
    leader flag is not touched: it is application-owned with a single writer, so the application
    that set it is the one that clears it. Nothing here retires the signer, provider, clock, swarm,
    contract bindings, custom RPC root, or local EVM — those belong to `dispose()`, which stays the
    terminal operation. Three steps bracket that order. First, before any await, the reset advances
    `channelGeneration` ([#L318](../../../../../../src/stateManager/StateManager.ts#L318), getter [#L499](../../../../../../src/stateManager/StateManager.ts#L499)): async work begun for the old
    channel captures the generation and stands down when it has moved on, so work that resumes during or
    after the reset cannot write into the returned runtime or speak for the next channel. A leave from a
    non-committed runtime resets at once, possibly while that channel's initial sync is still waiting on
    its peer, which is why the fence is needed. Second, still before any await and before
    `reductionManager.reset()`, it retires the old fork (`latestForkId = NULL`,
    [#L324](../../../../../../src/stateManager/StateManager.ts#L324)). A chain-log handler for the old channel can still be running during the drain;
    with the fork retired, `isActiveFork(oldFork)` is false and `reductionManager.tryReduce(oldFork)`
    returns without creating a reduction. Retired any later, that handler could start a reduction whose
    timer the task drain then cancels, leaving it waiting forever (a drain timeout plus a hung detached
    promise), and a reduction created after `reductionManager.reset()` would not be settled by it. Last, after the mutex section that sets `NOT_OPENED`,
    the reset calls `p2pManager.rearmInitialSync()` ([#L357](../../../../../../src/stateManager/StateManager.ts#L357)): the initial-sync latch settles on
    any status change out of `OPENED`, so re-arming it any earlier would let the reset's own
    `OPENED` → `NOT_OPENED` transition settle the next channel's wait as failed.
11. **A disposed runtime cannot be reset** ([#L312](../../../../../../src/stateManager/StateManager.ts#L312)). Reset is a return to service,
    so asking for it after shutdown is a caller error rather than a silent no-op; the throw is the
    observable boundary between the non-terminal and terminal halves of the lifecycle.

Abort marks participation inactive, emits onAbort, changes status to OPENED and invokes the owning root disposal callback. It does not create a second child cleanup algorithm.

Shutdown preparation calls the event listener’s `stop()` and drains scheduled work while dependencies remain available. Final disposal removes that listener; the host closes its owned provider between preparation and final disposal.

## Inputs, outputs, state, and side effects

| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Inputs       | Eligible block entries; local transactions; fork transitions; lifecycle calls (reset, dispose, abort).                                                                                                                                                              |
| Outputs      | Committed state + events; counter-signatures; gossip; escalations; scheduled tasks.                                                                                                                                                                                 |
| Owned state  | The live application-state authority: status, current fork, mutex, channel generation; everything durable via storage.                                                                                                                                              |

## Assumptions, dependencies, trust boundaries, and limits

- Single-threaded task interleaving; the mutex is the only execution serializer.
- Chain freshness for timeout/calldata checks inherits the mirror fallback rules ([`REQ-MIRROR-3-THD7K8` (Cache, never authority)](../../../../specification/enforcement/local-mirror.md#req-mirror-3-thd7k8)).

## Specification adherence

- Ordered one-at-a-time application on the current fork ([`REQ-BLOCK-PIPE-6-XQ0RTT` (Total-order application)](../../../../specification/block-progression/block-processing.md#req-block-pipe-6-xq0rtt)).
- Evidence stored before every live escalation; subjective lateness never escalates ([`REQ-BLOCK-PIPE-8-N529VH` (Evidence precedes escalation)](../../../../specification/block-progression/block-processing.md#req-block-pipe-8-n529vh)).
- Temporary validation/replay work cannot reach durable state without commit ([`REQ-SDK-ARCH-4-GTN7QN` (Execution isolation)](../../../../specification/runtime/sdk.md#req-sdk-arch-4-gtn7qn)).
- The composed `MembershipService.getOnChainThresholdSet` exposes the contract's slash-excluding
  join eligibility set without a parallel SDK derivation
  ([`REQ-JOINSIG-2-RR2G4Q` (All-or-nothing unanimity)](../../../../specification/peer-communication/join-authorization.md#req-joinsig-2-rr2g4q)).
- `resetChannel()` implements the non-terminal half of the ordered lifecycle: intake stops before
  the feed is detached, the feed is drained before its bookkeeping is dropped, peers and scheduled
  tasks go before retained state, and the method ends with the runtime able to accept another
  channel ([#L311](../../../../../../src/stateManager/StateManager.ts#L311), [`REQ-SDK-ARCH-2-QBZAT8` (Ordered lifecycle)](../../../../specification/runtime/sdk.md#req-sdk-arch-2-qbzat8)).
- After the reset the runtime is observationally pre-channel: zero channel id, zero fork id,
  `NOT_OPENED`, and empty channel-scoped storage ([#L348](../../../../../../src/stateManager/StateManager.ts#L348)), which is
  what lets the same instance select another channel under
  [`REQ-LIF-10-QR8NQ9` (Runtime departure and channel reuse)](../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9).
  The leader flag stays where the application left it; it is not channel state the reset owns.
- The old fork stops being active as soon as the reset starts ([#L324](../../../../../../src/stateManager/StateManager.ts#L324)), so old-channel
  chain-log work that resumes during the drain cannot start reduction work for it
  ([`REQ-LIF-10-QR8NQ9` (Runtime departure and channel reuse)](../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9)).
- The channel generation advances before the reset's first await ([#L318](../../../../../../src/stateManager/StateManager.ts#L318)) and the initial-sync
  latch is re-armed only after the status change ([#L357](../../../../../../src/stateManager/StateManager.ts#L357)), so work begun for the channel left
  neither changes the returned runtime nor completes the next channel's initial synchronization
  ([`REQ-LIF-10-QR8NQ9` (Runtime departure and channel reuse)](../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9)).
- Reset on a disposed runtime throws instead of partially running ([#L312](../../../../../../src/stateManager/StateManager.ts#L312)), keeping
  shutdown terminal.
- A reset that cannot drain the chain feed within the bound throws rather than completing
  ([#L333](../../../../../../src/stateManager/StateManager.ts#L333)), so the runtime is never handed to another channel with
  old-channel log work still running; the terminal shutdown that follows belongs to the caller
  ([`REQ-SDK-ARCH-2-QBZAT8` (Ordered lifecycle)](../../../../specification/runtime/sdk.md#req-sdk-arch-2-qbzat8),
  [`REQ-LIF-10-QR8NQ9` (Runtime departure and channel reuse)](../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9)).

## Related source reports

## Channel leave and reset ownership

The state manager constructs and disposes `LeaveChannelService`; internal `setChannelId` remains available only
to lifecycle owners. `resetChannel()` is the counterpart the leave service calls once departure has settled: it
is what clears the selected ID, so a completed leave — and only a completed leave — releases the single-channel
ownership that otherwise rejects a different target. This contributes to [`REQ-TJOIN-6-0HEVYH` (Single-channel runtime ownership)](../../../../specification/peer-communication/targeted-channel-join.md#req-tjoin-6-0hevyh) and [`REQ-TJOIN-7-NNGTAY` (Channel leave and runtime reuse)](../../../../specification/peer-communication/targeted-channel-join.md#req-tjoin-7-nngtay).

## Targeted connect contribution

`setChannelId` installs the provider-backed listener before targeted matching. Authoritative refresh governs
preflight and observed-open handoff. Targeted unsigned cleanup skips `clearChannelId`, so the same target and
listener survive; ordinary derived-ID cleanup clears both. Before disposal tears down P2P state, it lets the
local signer settle an active connect exactly once with `false`. Fatal observer sync uses the existing abort
and disposal branch, while pending or participating operational failure preserves state.
