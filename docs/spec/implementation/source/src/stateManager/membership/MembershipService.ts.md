# MembershipService.ts — Source Report

> **Source:** [src/stateManager/membership/MembershipService.ts](../../../../../../../src/stateManager/membership/MembershipService.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [join channel](../../../../views/architecture/sdk/rpc/join-channel.md)

## Responsibility and observable boundary

Owns local membership lifecycle operations and authoritative on-chain participant/threshold reads.
It also owns cached authorization for block contributions; it does not announce membership or control connection engagement.

## Key design decisions

`publishOnChainSnapshot()` replaces snapshot membership and retains unconsumed JOINs from existing inbound storage. `observeInboundMembership()` adds delivered joiners. Neither operation reads the chain or LocalDiamond. `refreshOnChainEligibility()` invokes EventSyncService only on an explicit pull or lookup miss; recovered state passes through the event handlers before the result is used. Concurrent misses await one shared refresh promise, cleared in `finally` after success or failure. There is no invalidation counter or retry loop. A failed read leaves the previous mirror intact. `SourceEligibility` has three enum values: `ELIGIBLE`, `SLASHED` and `ABSENT`. After refreshing a miss, resolution returns the set lookup directly. Tests use these production eligibility methods; there is no diagnostic cache-state accessor.

Source eligibility is the inclusive OR of the chain current/pending cache and the current verified off-chain union, with known slashes first. Positive lookups perform no chain or VM read. Each miss awaits one pinned state read and any missing-event recovery and then checks membership again. Commits and state adoption publish complete local sets synchronously. Membership is stored in three plain address sets: chain members, local members and known slashes. Lookups have no channel/fork metadata checks. Channel changes and shutdown clear cached sets. This gate authorizes gossip contributions; post-handshake engagement and chain dispute standing remain different operations. An unobserved chain change can remain stale on positive hits. See [getCachedSourceEligibility](../../../../../../../src/stateManager/membership/MembershipService.ts#L91).

Both authored-exit fallback paths report a missing dispute marker or a thrown upload error to `LeaveChannelService.onExitFallbackFailed` after logging. A snapshot post that resolves `false` (the chain refused it on a disputed fork, already logged at warn by the post, or the same-fork update waits on an inbound message, such as a pending join, that the latest snapshot has not consumed) or throws (logged at error) first attempts the dispute; a failure of that fallback rejects pending leave, except an evidence-expired refusal, which leaves it awaiting settlement.

startSelfRemovalDispute sets force-exit, invokes normal dispute construction and returns the resulting marker. Terminal leave turns a missing marker into failure; membership fallbacks log and notify the matching authored leave on failure. Signer membership predicates name the local set or the on-chain union; pending-only event checks remain pending-only. See [MembershipService.ts](../../../../../../../src/stateManager/membership/MembershipService.ts#L222).

Committed membership classification uses the shared two-status predicate. Force-exit starters and public parameters stay unchanged. See [MembershipService.ts](../../../../../../../src/stateManager/membership/MembershipService.ts#L357).

1. **Chain observations are authoritative.** A successful join updates local status through the
   existing event/state flow; it sends no peer-supplied admission hint.
2. **Submitted joins require local protection.** The signer moves to `PENDING_PARTICIPANT` synchronously
   before the contract method is invoked. A proven failed receipt or decoded pre-submission rejection restores
   `SYNCED`; an uncertain submission keeps pending protection and reconciles against the on-chain union.
3. **Force join requires authoritative eligibility; a refusal ends it.** The height marker is retained
   until the signer appears in the on-chain participant union. Both triggers call one private
   `startForceJoinDispute(trigger)` ([#L555](../../../../../../../src/stateManager/membership/MembershipService.ts#L555)), which owns every gate and returns `"started"`, `"deferred"`
   or `"refused"`. A membership or chain read that cannot decide returns `"deferred"` ([#L572](../../../../../../../src/stateManager/membership/MembershipService.ts#L572), [#L579](../../../../../../../src/stateManager/membership/MembershipService.ts#L579), [#L599](../../../../../../../src/stateManager/membership/MembershipService.ts#L599),
   [#L614](../../../../../../../src/stateManager/membership/MembershipService.ts#L614)); only the deadline re-arms on it, and the block bound simply tries again on a later block. A
   dispute window whose evidence period ended returns `"refused"`: it records the fired bound, cancels
   the deadline and logs `Force join dispute refused: dispute evidence window expired; not retried`
   ([#L620](../../../../../../../src/stateManager/membership/MembershipService.ts#L620)–[#L631](../../../../../../../src/stateManager/membership/MembershipService.ts#L631)). A start records the fired bound, cancels the deadline, logs `Force join dispute
triggered: the join was not included in time` with the `trigger` field, and requests the dispute
   ([#L635](../../../../../../../src/stateManager/membership/MembershipService.ts#L635)–[#L642](../../../../../../../src/stateManager/membership/MembershipService.ts#L642)). Either fired outcome ends both bounds for this submission. Why no retry: the refusal means
   the fork already has a window, which reduces; an admitted dispute carries the latest inbound head and
   no join lands on a disputed fork, so that reduction consumes the join (engineer decision).
   Rejected alternative: resetting the fired flag and re-arming the deadline after a refusal. The block
   bound in `maybeInitiateForceJoinDispute` fires at `block.height >= countingFromHeight + participants
    - 1`([#L407](../../../../../../../src/stateManager/membership/MembershipService.ts#L407)), where`countingFromHeight` is the first counted block (decision 8).
4. **A named set of join reverts is terminal, and it is a set, not a default.** Six decoded error
   names abort the state manager after restoring `SYNCED` and clearing the force-join marker
   ([#L327](../../../../../../../src/stateManager/membership/MembershipService.ts#L327)):
   `RaceConditionJoinChannelExpired`, `RaceConditionSnapshotForkMismatch`,
   `RaceConditionJoinChannelSnapshotMismatch`, `RaceConditionJoinChannelForkDisputed`,
   `ErrorJoinChannelInvalidSignature` and `ErrorJoinChannelConfirmationNotThresholdSigned`. Each
   says the confirmation the joiner already signed can never be accepted — the deadline passed, the
   snapshot or fork it pinned is gone, the fork is disputed, the joiner's own signature does not
   verify, or the eligibility set grew after signing so the collected signatures no longer meet the
   threshold. Retrying would need a new confirmation, so the join is not retried: the state manager
   aborts and the caller starts over. Every other revert leaves the signer at `SYNCED` and
   retryable.
5. **Decoded-error log metadata comes from the shared helper.** Both revert logs pass the decoded
   error through `LoggerUtils.getCustomEvmErrorMetadata`
   ([#L338](../../../../../../../src/stateManager/membership/MembershipService.ts#L338),
   [#L375](../../../../../../../src/stateManager/membership/MembershipService.ts#L375)) instead of
   assembling `{name, args}` by hand. An ethers `Result` serializes positionally, so the hand-built
   object logged the new error operands as a bare array; the helper converts them to the ABI's own
   field names.
6. **One owner for "may I sign or relay this block".**
   [`isSignerInBlockUnion`](../../../../../../../src/stateManager/membership/MembershipService.ts#L81)
   answers from the block's previous/resulting participant union. `BlockCommitService` uses it for
   the signing decision and the commit gossip, and `BlockValidationStrategy` for the growth
   rebroadcast, so a leaver whose exit is still pending stops relaying at the same point it stops
   signing.

7. **A time bound for a join no block includes.** The block bound needs blocks, so a table whose writers
   author none would hold the join forever. `armForceJoinDeadline` ([#L419](../../../../../../../src/stateManager/membership/MembershipService.ts#L419)) schedules one
   `force join deadline` task of `N × timeoutWaitTime(timeConfig, joinSubmissionHeight + 1)` seconds,
   `N` = local participants + 1 ([#L423](../../../../../../../src/stateManager/membership/MembershipService.ts#L423), [#L444](../../../../../../../src/stateManager/membership/MembershipService.ts#L444)): the same `N` turns as the block bound, each the full window a
   writer gets before it can be timed out (`p2pTime + agreementTime + chainFallbackTime` plus the first-block
   grace). An honest table that is merely slow still includes the join first. When the task runs, it does
   nothing unless the runtime is still `PENDING_PARTICIPANT` for the same submission height with no fired
   bound ([#L432](../../../../../../../src/stateManager/membership/MembershipService.ts#L432)); only a `"deferred"` start re-arms another full period ([#L441](../../../../../../../src/stateManager/membership/MembershipService.ts#L441)). A seated join cancels the task
   (decision 10). Rejected alternative: a time bound shorter than a full writer window, which would race
   honest inclusion. Approved answer to [`OQ-SPEC-FORCE-JOIN-1-J4QZ2V` (Force-join trigger when no blocks arrive)](../../../../../specification/open-questions.md#oq-spec-force-join-1-j4qz2v).
8. **Both force-join bounds start when the joiner observes its own join.** `observeInboundMembership`
   ([#L132](../../../../../../../src/stateManager/membership/MembershipService.ts#L132)) calls `onOwnJoinObserved` ([#L143](../../../../../../../src/stateManager/membership/MembershipService.ts#L143)) when a decoded `JOIN_CHANNEL_MESSAGE` names this signer.
   `onOwnJoinObserved` ([#L456](../../../../../../../src/stateManager/membership/MembershipService.ts#L456)) acts only while a join submission is recorded, no grace is set yet, and
   the runtime is `PENDING_PARTICIPANT`. It tells the leave service ([#L466](../../../../../../../src/stateManager/membership/MembershipService.ts#L466)), records
   `countingStartsAt = now + agreementTime` ([#L467](../../../../../../../src/stateManager/membership/MembershipService.ts#L467)), and arms the deadline ([#L471](../../../../../../../src/stateManager/membership/MembershipService.ts#L471)). `joinChannel` arms
   and starts nothing: a receipt, an "already a participant" refusal, or an uncertain outcome does not prove
   that the writers can see the join, and only the inbound message does. A join that never reaches the
   chain therefore starts neither bound. `maybeInitiateForceJoinDispute` ([#L384](../../../../../../../src/stateManager/membership/MembershipService.ts#L384)) returns while no grace is
   recorded or this joiner's own `Clock` is before it when it commits the block ([#L398](../../../../../../../src/stateManager/membership/MembershipService.ts#L398)); block timestamps play
   no part, so a block authored before the grace counts when this joiner commits it after the grace. The first counted block becomes `countingFromHeight`
   and starts no dispute ([#L403](../../../../../../../src/stateManager/membership/MembershipService.ts#L403)); the dispute fires at `countingFromHeight + participants + 1` ([#L407](../../../../../../../src/stateManager/membership/MembershipService.ts#L407)). Why:
   the table's writers observe the join on chain only within `agreementTime`, and a fast table authored
   the `N + 1` blocks before its writers could include the join
   ([`INV-MEMBERSHIP-PENDING-1-2H1T75` (Submitted joins are locally)](../../../../../specification/peer-communication/join-authorization.md#inv-membership-pending-1-2h1t75)). The rule is the joiner's `Clock`, regardless of its
   perception of block time (engineer decision, 2026-10-04). Rejected alternatives: starting at the receipt,
   which raced the writers' own observation; comparing each block's own timestamp, which made the count
   depend on the joiner's perception of block time.
9. **One owner for "can my join still land".** `joinChannel` records the confirmation's
   `deadlineTimestamp` as the join authorization deadline ([#L259](../../../../../../../src/stateManager/membership/MembershipService.ts#L259)). `isJoinAuthorizationOpen` ([#L514](../../../../../../../src/stateManager/membership/MembershipService.ts#L514)) is true
   while the latest chain block's timestamp is at most that deadline ([#L517](../../../../../../../src/stateManager/membership/MembershipService.ts#L517)), the same inclusive rule the
   contract applies at submission. `getOwnJoinState` ([#L521](../../../../../../../src/stateManager/membership/MembershipService.ts#L521)) is the single owner of the answer:
   `"none"` (no join tracked), `"landed"` (observed, or listed on chain once the authorization closed),
   `"open"` with `secondsUntilExpiry` (not observed and still admissible), or `"expired"` (closed and not
   listed) ([#L522](../../../../../../../src/stateManager/membership/MembershipService.ts#L522)–[#L535](../../../../../../../src/stateManager/membership/MembershipService.ts#L535)). `LeaveChannelService` and the signer read (`getOwnJoinState` on the signer
   surfaces) delegate to it; `StateApplicationService` reads `isJoinAuthorizationOpen` for its status rule.
   `isOwnJoinObserved` ([#L480](../../../../../../../src/stateManager/membership/MembershipService.ts#L480)) reports whether the bounds started. `abandonUnobservedJoin` ([#L488](../../../../../../../src/stateManager/membership/MembershipService.ts#L488)) drops the
   tracking and returns `PENDING_PARTICIPANT` to `SYNCED`; the leave service calls it only for an
   `"expired"` or `"none"` join ([LeaveChannelService](LeaveChannelService.ts.md)).
10. **Seating ends the join.** `onJoinSeated` ([#L499](../../../../../../../src/stateManager/membership/MembershipService.ts#L499)) clears all join tracking and cancels the deadline
    (`resetJoinTracking`, [#L538](../../../../../../../src/stateManager/membership/MembershipService.ts#L538)), then tells the leave service that the join arrived. `BlockCommitService`
    calls it when a committed block lists the signer, and `StateApplicationService` when an installed
    state (including a reduction genesis) lists it, so no bound or deadline of a finished join survives
    into a later join.

## Assumptions, dependencies, trust boundaries, and limits

Deferred by the engineer: [`OQ-IMPL-RPC-COOLDOWN-1-XMSNR7` (Cooldown for on-demand RPC queries)](../../../../open-questions.md#oq-impl-rpc-cooldown-1-xmsnr7).

- The join authorization check reads the latest chain block's timestamp (`Clock.getBlockchainTime`); a lagging provider makes the join look open longer, never shorter. `secondsUntilExpiry` is an estimate from the local clock and only schedules the next check.
- The force-join deadline runs on the local `TimeoutManager` timer, not on chain time. It only decides when the joiner asks for the dispute; the chain adjudicates the dispute. The deadline handle and the force-join marker are held in memory.
- Chain reads/events and verified current off-chain state define the two admission caches. Unverified remote claims are not authority. Positive cache hits may remain stale until a chain change is observed.

## Specification adherence

- Identity-only handshake engagement remains separate from gossip contribution eligibility and historical block membership.

## Targeted connect contribution

`joinChannel` remains the sole first-join transaction owner. It sets `PENDING_PARTICIPANT` before invoking
transaction submission. It restores `SYNCED` only when a decoded rejection or failed receipt proves no
commitment exists. An uncertain outcome keeps pending status and the force-join marker; an authoritative
on-chain membership read can reconcile it as success. A duplicate result proving the participant already
exists returns success while preserving pending state.
`topUpBalance` is the one receipt-gated update
for a supplied balance on pending or participating state; failure preserves that committed runtime. A first join refused
with `RaceConditionJoinChannelForkDisputed` ([#L331](../../../../../../../src/stateManager/membership/MembershipService.ts#L331)) aborts and returns `false`; a top-up refused on a
disputed fork with the same error returns `false` through its decoded-error branch ([#L373](../../../../../../../src/stateManager/membership/MembershipService.ts#L373)). Omitted
balance reuse sends no transaction in the signer wrapper. This service never receives matcher `timeoutMs`.

# Terminal leave contribution

The fully signed exit path now waits for snapshot submission. If it fails, it preserves self-removal and starts the existing dispute path. This contributes to [`REQ-LIF-10-QR8NQ9` (Terminal runtime departure)](../../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9).
