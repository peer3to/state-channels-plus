# LeaveChannelService.ts

> **Source:** [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts) > **Design views:** [architecture.md](../../../../views/architecture/sdk/architecture.md) > **Status:** Authored implementation report.

## Responsibility and observable boundary

This service owns one channel leave operation for a state manager. It captures the participant count and
fork at entry, sets self-removal before dispute input construction, substitutes the local leave-turn hook,
counts committed blocks, owns the local watchdog, and resolves only after local removal plus either the
settled snapshot or the on-chain reduced-fork commitment that removed the signer — and then, as the second
half of the same promise, after `StateManager.resetChannel()` has handed the runtime back its pre-channel
state. It does not author application exit calldata, and a leave that runs to completion does not dispose the
outer runtime: leaving is non-terminal. The one exception is a reset that fails after a settled departure,
where this service does retire the runtime — see the memo below.

## Key design decisions

`onExitFallbackFailed` acts only on an existing `exit-authored` operation on the same fork; missing operations, awaiting-exit operations and stale fork notifications are ignored. A `RaceConditionDisputeEvidencePeriodExpired` refusal moves the operation to `awaiting-settlement`: the chain raises it only for a window that already holds commitments, so that window's reduction reaches `onSettledStateObserved`, which resolves the leave or re-arms it on the successor fork ([LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L191)). Every other fallback error rejects the promise without changing the watchdog phase.

A confirmed dispute settlement short-circuits before chain membership reads. Explicit runtime disposal rejects pending leave and does not wait for an in-flight dispute upload. The upload may finish later; its original rejection remains in the detached diagnostic collector, while the leave failure route cannot resettle the disposed operation. Graceful exit uses leaveChannel; disposal is local shutdown. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L236).

The watchdog and block bound route fallback errors through the same observer to fail the leave operation. Settlement reads chain membership only after local removal at SYNCED. The production watchdog remains 15 seconds, intentionally allowing fallback before a healthy exit turn. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L270).

Committed membership uses the shared status predicate. Local and chain signer membership use MembershipService; leave sequencing, settlement and error wrapping remain local. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L5).

One stored promise makes leave idempotent and gates new channel work. The first `N + 1`-block or watchdog
bound starts the existing dispute path. A dispute already active on the entry fork is awaited; after settlement,
the operation either completes if the signer is absent or rearms on the next active fork. Disposal cancels the
watchdog and rejects an unfinished operation.

One memo. `operation` is the settled-departure state machine, and it carries the outer promise callers
receive as `LeaveOperation.completion` ([#L24](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L24)): `settleAndReset` — departure, then
`stateManager.resetChannel()` ([#L123](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L123)) — built into the operation literal itself
([#L90](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L90)), from the departure promise alone, so the operation is fully typed at construction
with no cast and no field assigned afterwards. Repeated calls return that same `completion`
([#L78](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L78)), so a caller never starts a second departure and never observes a runtime that is only
half-returned. `settleAndReset` clears `operation` only after the reset succeeded
([#L134](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L134)), which is what makes the runtime able to leave its _next_ channel. A rejected
_departure_ deliberately keeps the operation: membership is then indeterminate, so the same failure
must be handed to every later caller and `assertOperationAllowed`
([#L69](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L69)) must keep blocking channel work — "… is unavailable while a channel leave is
pending" — rather than let it start against a half-left channel.

A reset that throws _after_ departure already settled is the opposite case and is handled separately
([#L124](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L124)): the failure is logged, `stateManager.abort()` retires the runtime, and the
original error is rethrown so the leave rejects. Keeping the operation would not help here — the departure is
done, so there is nothing left to retry — and leaving the runtime alive would let a half-returned instance
serve another channel, which is exactly what the reset's own ordering exists to prevent. Terminal shutdown is
what a leave did before runtimes were reusable, so this is the pre-reuse behavior as the failure mode rather
than a new one.

## Inputs, outputs, state, and side effects

LeaveChannelState exposes the operation phase, fork and captured bound through the state getter. The operation owns its promise, watchdog handle and progress; failure rejects that promise and disposal cancels unfinished work.

The public leave operation coordinates committed membership, outbound removal, receipt and completion. Its existing operation promise and hooks prevent duplicate work; results and status changes retain their lifecycle order.

## Assumptions, dependencies, trust boundaries, and limits

Only pending and participating states count as committed membership. The extracted status predicate does not change snapshot membership, channel pins or receipt/abort behavior.

## Specification adherence

The service covers the local state-machine part of the channel leave, and it is the caller that turns settled
departure into a reusable runtime by awaiting `StateManager.resetChannel()` inside the promise it returns
([#L123](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L123)), per [`REQ-TJOIN-7-NNGTAY` (Channel leave and runtime reuse)](../../../../../specification/peer-communication/targeted-channel-join.md#req-tjoin-7-nngtay).
Snapshot posting, dispute construction, chain observation, and port transport remain with their existing
owners; runtime shutdown is no longer part of the successful route. It remains this route's failure mode for
one case only: a reset that throws after a settled departure is logged, aborts the runtime, and rethrows
([#L124](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L124)), so the leave rejects and no half-returned runtime is offered another channel
([`REQ-LIF-10-QR8NQ9` (Runtime departure and channel reuse)](../../../../../specification/settlement/lifecycle.md#req-lif-10-qr8nq9),
[`REQ-SDK-ARCH-2-QBZAT8` (Ordered lifecycle)](../../../../../specification/runtime/sdk.md#req-sdk-arch-2-qbzat8)).
