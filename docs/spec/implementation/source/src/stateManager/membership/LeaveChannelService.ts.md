# LeaveChannelService.ts

> **Source:** [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts) > **Design views:** [architecture.md](../../../../views/architecture/sdk/architecture.md) > **Status:** Authored implementation report.

## Responsibility and observable boundary

This service owns one terminal leave operation for a state manager. It captures the participant count and
fork at entry, sets self-removal before dispute input construction, substitutes the local leave-turn hook,
counts committed blocks, owns the local watchdog, and resolves only after local removal plus either the
settled snapshot or the on-chain reduced-fork commitment that removed the signer.
It does not author application exit calldata or dispose the outer runtime.

## Key design decisions

`onExitFallbackFailed` acts only on an existing `exit-authored` operation on the same fork; missing operations, awaiting-exit operations and stale fork notifications are ignored. Every error it receives rejects the promise without changing the watchdog phase ([LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L177)). A self-removal lost to a window already covering the fork never arrives here as an error: `startSelfRemovalDispute` absorbs that refusal and the fallback reports it through `onExitSelfRemovalNotStarted` ([#L153](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L153)). That method, like the bound and watchdog fallback, reads the fork's dispute window on chain through `awaitCoveringWindow` ([#L336](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L336)): when a window covers the fork the operation moves to `awaiting-settlement` and that window's reduction reaches `onSettledStateObserved`, which resolves the leave or re-arms it on the successor fork; when none does, the leave fails.

A self-removal dispute that did not land fails the leave only when no dispute window covers the fork. `awaitCoveringWindow` ([#L341](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L341)) reads `isForkDisputed` for the fork the attempt targeted: a covering window means another participant won the race to upload for it, so the operation moves to `awaiting-settlement` and `onSettledStateObserved` later completes the leave or re-arms it on the settled fork, where the bound or watchdog retries the self-removal once. The chain read is the test because a window on the fork settles it whatever refused this upload, a lost race included; with no window the refusal still fails the leave with the same error as before. The bound and watchdog fallback reaches it from `startDisputeFallback`, and the authored-exit fallbacks through `onExitSelfRemovalNotStarted` ([#L154](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L154)), which keeps their failure on `fail` rather than a rejected detached promise. `startDisputeFallback` captures the fork before the upload ([#L313](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L313)): a settlement during the upload re-arms the operation on a newer fork with its own attempt, so a result that returns for the older fork changes nothing.

A confirmed dispute settlement short-circuits before chain membership reads. Explicit runtime disposal rejects pending leave and does not wait for an in-flight dispute upload. The upload may finish later; its original rejection remains in the detached diagnostic collector, while the leave failure route cannot resettle the disposed operation. Graceful exit uses leaveChannel; disposal is local shutdown. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L203).

The watchdog and block bound route fallback errors through the same observer to fail the leave operation. Settlement reads chain membership only after local removal at SYNCED. The production watchdog remains 15 seconds, intentionally allowing fallback before a healthy exit turn. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L228).

Committed membership uses the shared status predicate. Local and chain signer membership use MembershipService; leave sequencing, settlement and error wrapping remain local. See [LeaveChannelService.ts](../../../../../../../src/stateManager/membership/LeaveChannelService.ts#L5).

One stored promise makes leave idempotent and gates new channel work. The first `N + 1`-block or watchdog
bound starts the existing dispute path. A dispute already active on the entry fork is awaited; after settlement,
the operation either completes if the signer is absent or rearms on the next active fork. Disposal cancels the
watchdog and rejects an unfinished operation.

## Inputs, outputs, state, and side effects

LeaveChannelState exposes the operation phase, fork and captured bound through the state getter. The operation owns its promise, watchdog handle and progress; failure rejects that promise and disposal cancels unfinished work.

The public leave operation coordinates committed membership, outbound removal, receipt and completion. Its existing operation promise and hooks prevent duplicate work; results and status changes retain their lifecycle order.

## Assumptions, dependencies, trust boundaries, and limits

Only pending and participating states count as committed membership. The extracted status predicate does not change snapshot membership, channel pins or receipt/abort behavior.

## Specification adherence

The service covers the local state-machine part of terminal leave. Snapshot posting, dispute construction,
chain observation, port transport, and outer disposal remain with their existing owners.
