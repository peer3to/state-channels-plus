## Responsibility and observable boundary

The audit-replay context for one block of the last milestone's unfinal tail: live gates off,
deviations mapped to dispute fraud proofs (apply and author-not-participant classes), and a
discovered double-sign stores ordinary evidence without aborting the replay. Each strategy carries
the dispute, the block's `blockIndex` in the dispute's last milestone, and the block's
`predecessor` on the dispute's own chain (the block it extends, or none for the fork genesis, with
that block's resulting snapshot and state). Every allegation it stores is addressed by that index
and built from that predecessor. Before it stores an allegation it asks
`DisputeValidationService.isBlockChallengeEligible`. The strategy never abstains: a deviation that
the replay can reach yields a fraud proof (result `DISPUTE`) or continues as valid, and a hook that
the replay must not reach throws.

## Key design decisions

Sourceless historical replay strips irrelevant unrecoverable confirmations and continues the objective pipeline. It does not invent a signer or construct a fraud proof from an unrecoverable signature. Required proof evidence remains subject to the canonical on-chain verifier; historical membership is not replaced by today's network source filter. See [malformedConfirmationSignatures](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L128-L134).

`blockIsBelowInstalledHistory` throws: dispute replay enforces no live ordering gate (`enforcesLiveForkAndOrderingGates` is false), so the hook is never called. See [blockIsBelowInstalledHistory](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L272-L280).

1. **Kill only on a provable failure:** a local decode or authentication gap alone must not kill an
   honest dispute. The structure of the last milestone is decided once by the audit's canonical
   structure check before replay, so `authenticateBlockFailed` returns `SUCCESS` ([#L110-L115](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L110-L115)) ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)).
2. **Replay survives discovered double-signs** (the dispute may still be honest); the proof is stored
   for separate enforcement ([#L197-L205](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L197-L205)).
3. **The block is judged from the predecessor the replay passes.** The constructor takes
   `(storage, dispute, blockIndex, predecessor, disputeValidation, logger)` ([#L27-L50](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L27-L50)): `blockIndex`
   is the block's position in the last milestone, `predecessor` is a `BlockPredecessor`
   ([QueueStorage](../../storage/QueueStorage.ts.md)) on the dispute's own chain, and
   `disputeValidation` is `Pick<DisputeValidationService, "isBlockChallengeEligible">`.
   `invalidStateTransitionDetected` ([#L206-L215](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L206-L215)) and `objectiveInvalidTimestampDetected`
   ([#L290-L300](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L290-L300)) hand the predecessor to the [FraudProofService](../utils/FraudProofService.ts.md)
   builders; both author-not-participant paths hand it to `createDisputeBlockAuthorNotParticipant`
   ([#L152-L159](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L152-L159), [#L188-L195](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L188-L195)). Why: on an alternate history the block stored at the same height is
   not the block the dispute's block extends; a proof built from the auditor's own history would
   fail on chain or slash the wrong author ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)). The state machine is positioned at the
   predecessor's state by [BlockIngestService](../ingest/BlockIngestService.ts.md), not by this
   strategy.
4. **An allegation is stored only when the chain makes it eligible; an ineligible one throws.**
   `allege` asks `isBlockChallengeEligible(dispute, blockIndex)` right before the store and throws
   when it answers false ([#L62-L74](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L62-L74)). The apply class (`invalidStateTransitionDetected`,
   `wrongGenesisDetected`, `forgedInboundMessageBlockDetected`, `objectiveInvalidTimestampDetected`)
   goes through `applyFraudProof` ([#L76-L92](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L76-L92)); the author-not-participant class goes through
   `allege` too. Why: the on-chain handler runs the same predicate and accepts only a block of the
   last milestone's unfinal tail; the replay starts at the first block the chain makes eligible
   ([DisputeValidationService](../dispute/DisputeValidationService.ts.md)), so an ineligible
   allegation is an invariant violation, not a reason to abstain ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)).
5. **A missing proof is an invariant violation.** `applyFraudProof` throws when the builder returns
   no proof ([#L79-L82](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L79-L82)). Why: dispute replay always passes a predecessor with its snapshot and
   state, so the builder can always build one; an honest auditor never abstains.
6. **An unlinked block cannot reach this strategy unnoticed.** `conflictingButNotLinkedBlockDetected`
   returns `SUCCESS` ([#L247-L253](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L247-L253)): the block extends another history than the one stored at its
   height, and the replay judges it from its own predecessor. `blockIsNotLinkedAndIsNotFirstBlock`
   throws ([#L281-L289](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L281-L289)): linkage is checked against the passed predecessor, and the replay passes
   the previous block of the structure-checked run, so a replayed block is always linked.
7. **Outsider authors are judged where the evidence exists.** `blockAuthorIsNotParticipant`
   returns `SUCCESS` when the block's resulting snapshot is not held ([#L185-L187](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L185-L187)): the replay
   continues, and the leader check or the participant-union check judges the author.
   `notAllSingersAreParticipants` with the author signature throws without the executed participant
   snapshots ([#L148-L151](../../../../../../../src/stateManager/validationStrategy/DisputeValidationStrategy.ts#L148-L151)): the ingest pipeline always passes them.

## Assumptions, dependencies, trust boundaries, and limits

- Hooks run under the caller's execution boundary; consequences must not assume otherwise.
- The eligibility check reads the chain; a chain transport failure there surfaces as an audit error.
- The predecessor is trusted input from the dispute audit, which takes it from the dispute's own
  structure-checked chain (or the fork genesis) and holds its snapshot and state.
