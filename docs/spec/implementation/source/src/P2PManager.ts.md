## Responsibility and observable boundary

The frame dispatcher, correlation owner, and sole post-handshake connection promoter. `onRpc` runs stages 1–4 of the ingress order (16 MiB
UTF-8 byte gate before parsing, response-first classification, envelope verification, service
resolution) before handing to the service base; `sendRpcRequest` owns the pending-request table,
per-call timeouts, authenticated response routing before transport retirement,
late-response silent ignore, and disconnect settlement; plus broadcast/addressed delivery and
ordinary connection registry. Completed handshakes are routed from the local lifecycle: `DISCOVERING`
hands authenticated transports to lobby matching without ordinary promotion or connection notification;
commitment later promotes only the selected profile. A replacement authenticated for that profile during
negotiation handoff is promoted through the same path instead of being rejected as late lobby traffic. An
opened channel performs the participant read and sync.

## Key design decisions

1. **Response-first classification** keeps response frames out of service dispatch entirely ([`REQ-RPC-6-E60S4J`](../../../specification/peer-communication/rpc.md#req-rpc-6-e60s4j)).
2. **Settlement by peer identity, not transport identity** — a WebRTC upgrade cannot orphan pending requests; a response from any _other_ peer penalizes the responder ([`REQ-RPC-2-SZDTTM`](../../../specification/peer-communication/rpc.md#req-rpc-2-szdttm)).
3. **Unknown/late responses are penalty-free by design** (must therefore stay cheap; bounded by the frame gate).
4. **Service resolution uses the shared public-shape predicate.** A valid custom root loaded from a separate application module graph reaches the same guard and dispatch pipeline; constructor identity is not part of the wire contract ([#L228](../../../../../src/P2PManager.ts#L228)).
5. **Handshake promotion has one owner.** The handshake hook reads local status once. Lobby transports
   enter the session-local matching set, while ordinary statuses promote directly. Lobby commitment calls
   the same promotion primitive only for the selected profile. Opened-channel participant lookup and sync
   failures stay confined without relying on peer-supplied membership.
6. **Disposal is visible to detached work.** `isDisposed` exposes the manager lifetime so guards and
   other pending callbacks can stop without replaying or applying late consequences.
7. **One discovery-key boundary is transport-only.** Channel callers use the exact bytes32 channel ID as
   their canonical key and lobby
   callers pass their exact topic into the same validated join/leave primitive. It establishes connectivity
   but does not set lifecycle, select a peer, or start negotiation.
8. **Lobby admission is session-bound.** The lobby service owns the active caller topic and validates
   it on every lobby payload. Transports own authenticated identity and connection lifecycle, not a
   second copy of the lobby topic.
9. **Discovery is self-contained.** Public lobby and channel joins call the same complete
   local-discovery adapter from `P2PManager`; it exposes no harness-only mode. Node fixtures implement
   `autoConnect: false` by selecting channel state without invoking the public join. Leaving a
   rendezvous stops discovery without closing an established channel transport.
10. **Peer penalties require attributable faults.** Invalid frames, envelopes, services, and
    endpoints from an authenticated peer blacklist that address and close both the reporting
    transport and any current transport for the same profile. Transport loss, timeouts, send
    failures, cleanup, and unclassified local handler failures remain disconnect-only.
11. **The initial sync wait is bounded before a request exists.** The one initial sync request carries a
    two-agreement-window timeout, but an uncommitted observer could previously wait forever for the first
    participant handshake that produces that request. `joinDiscoveryKey` now arms the same two-window
    deadline; if no participant completes a handshake in time, the observer aborts and its connect settles
    as `false`, exactly as a timed-out request would. A cooperating peer must arrive within the window; the
    runtime never waits for a later one.

## Targeted connect contribution

Handshake routing recognizes an active matcher attempt without requiring `DISCOVERING`. While the runtime
is uncommitted, the first connected peer proven by authoritative chain state to be a participant starts one
ordinary sync call with a two-window timeout. `P2PManager` aborts on a false result.
Successful matched opening promotes and preserves the participant transport for first sync; observed-open
loser handling joins only the selected raw topic and does not promote the loser. Pending RPC records retain
their original transport; retiring it rejects the request. A response from a foreign peer is rejected.

[`UNIT-TEST-P2P-MANAGER-1-9DNSRZ.P25`](P2PManager.ts.md#unit-test-p2p-manager-1-9dnsrz.p25) means original-transport retirement rejects its pending request even when a replacement exists; `.P3` remains foreign-responder rejection.
