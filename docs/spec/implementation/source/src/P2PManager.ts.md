## Responsibility and observable boundary

Owns connections, discovery, profiles, peer penalties and post-handshake promotion. It is the single
owner of a transport-scoped close: every caller states a `DisconnectPolicy`
([DisconnectPolicy.ts](./DisconnectPolicy.ts.md)) and this file switches on it. Each manager constructs one [NetworkRpcRouter](rpc/router/NetworkRpcRouter.ts.md) before constructing its services. That router owns ingress, broadcast and network timeout/response hooks; its [ARpcRouter](rpc/router/ARpcRouter.ts.md) base owns the only pending-request registry. RPC callers use this router directly; the manager exposes no routing delegates. Completed handshakes are routed from the local lifecycle: `DISCOVERING`
hands authenticated transports to lobby matching without ordinary promotion or connection notification;
commitment later promotes only the selected profile. A replacement authenticated for that profile during
negotiation handoff is promoted through the same path instead of being rejected as late lobby traffic. An
opened channel performs the participant read and sync.

## Key design decisions

Cleanup delegates to [runCleanup.ts](utils/runCleanup.ts.md), which attempts all ordered steps before reporting the first failure. Caller-owned disposal promises and acknowledgement rules remain in this owner.

Disposal closes registered transports through ProfileManager once, then clears openConnections. The live disconnectAll operation remains available to leave and dispute callers; it is not a second disposal pass.

- The router receives the manager (including its optional debug proxy) after logger initialization and before service construction. Its constructor does no active work. The manager dependency remains explicit because routing uses its live connections, root, logger, timeout manager and peer-policy operations. See [constructor](../../../../../src/P2PManager.ts#L64).

The [close entry point](../../../../../src/P2PManager.ts#L380) takes the policy as a required argument
and owns the whole switch. It first collapses the bounded tier onto a constant one: `ALLOW_RETRY`
asks [ProfileManager](./ProfileManager.ts.md) to count the close against the peer's single session
counter, keyed by the profile's key — the proven EVM address, or the Hyperswarm key the transport
presented before proof — and becomes `SUSPEND` on the close that reaches the stated bound (the
policy's default of three when the caller names none) and `ALLOW` on every earlier one. A transport
with no profile key at all is not counted and stays `ALLOW`, since there would be nothing to bar on
reconnect, and so does a transport this node already closed: that close stated its own policy, and a
request it rejected on the way out (the initiator's own handshake request after a responder-side
rejection) is not a second event. An address with no profile is counted by that address. The profile a
transport's fault is charged to comes from [`ProfileManager.getProfileForFault`](./ProfileManager.ts.md):
the proven identity's profile when the transport carries one, else the transport's own. `BLACKLIST` then records the
verdict with its stated reason and `SUSPEND` bars the peer for the session; a caller may name the
EVM address a transport already proved but has not registered, so a suspension reached on that
transport bars the identity too. Both punitive tiers close every live transport of the profile and
then fall into the same close as `ALLOW`; the close itself
([`closeConnection`](../../../../../src/P2PManager.ts#L421)) is private and never punitive. The
[transport](../../../../../src/P2PManager.ts#L399) and [address](../../../../../src/P2PManager.ts#L403)
blacklist helpers are thin delegates that log the target before mutation, so no caller reaches the
profile registry behind the switch. The address helper cannot route through the transport-scoped
switch — an identity with no live transport is still excluded, there is simply nothing to close.

Both engagement checks use the status predicate that includes SYNCED as well as committed membership. See [P2PManager.ts](../../../../../src/P2PManager.ts#L111).

The network router parses inbound frames once with response-first precedence after the byte-size gate. Connected peer projection remains transport-first with profile fallback and insertion-order deduplication. See [P2PManager.ts](../../../../../src/P2PManager.ts#L462).

1. **Response-first classification** keeps response frames out of service dispatch entirely ([`REQ-RPC-6-E60S4J` (Ordered ingress verification)](../../../specification/peer-communication/rpc.md#req-rpc-6-e60s4j)).
2. **Settlement by peer identity, not transport identity** — a WebRTC upgrade cannot orphan pending requests; a response from any _other_ peer penalizes the responder ([`REQ-RPC-2-SZDTTM` (Request lifecycle)](../../../specification/peer-communication/rpc.md#req-rpc-2-szdttm)).
3. **Unknown/late responses are penalty-free by design** (must therefore stay cheap; bounded by the frame gate).
4. **Service resolution uses the shared public-shape predicate.** A valid custom root loaded from a separate application module graph reaches the same guard and dispatch pipeline; constructor identity is not part of the wire contract ([#L226](../../../../../src/P2PManager.ts#L222)).
5. **Handshake promotion has one owner.** The handshake hook reads local status once. Lobby transports
   enter the session-local matching set, while ordinary statuses promote directly. Lobby commitment calls
   the same promotion primitive only for the selected profile. Opened-channel participant lookup and sync
   failures stay confined without relying on peer-supplied membership.
6. **Disposal is visible to detached work.** `isDisposed` exposes the manager lifetime so guards and
   other pending callbacks can stop without replaying or applying late consequences.
7. **One discovery-key boundary is transport-only.** Channel callers use the exact bytes32 channel ID as
   their canonical key and lobby
   callers pass their exact topic into the same validated join/leave primitive. It establishes connectivity
   but does not set lifecycle, select a peer, or start negotiation.
8. **Lobby admission is session-bound.** The lobby service owns the active caller topic and validates
   it on every lobby payload. Transports own authenticated identity and connection lifecycle, not a
   second copy of the lobby topic.
9. **Discovery is self-contained.** Public lobby and channel joins call the same complete
   local-discovery adapter from `P2PManager`; it exposes no harness-only mode. Node fixtures implement
   `autoConnect: false` by selecting channel state without invoking the public join. Leaving a
   rendezvous stops discovery without closing an established channel transport.
10. **Peer penalties require attributable faults, and every close names its own.** Invalid frames and
    envelopes from an authenticated peer blacklist that address and close both the reporting transport
    and any current transport for the same profile. A service or endpoint name this build does not
    have is also blacklisted: the router treats a failed dispatch as an authenticated wire-contract
    violation, and version skew is expected to be refused before protected calls
    ([`REQ-RPC-8-44XECF` (Compatibility before protected calls)](../../../specification/peer-communication/rpc.md#req-rpc-8-44xecf)).
    Transport loss, send failures, cleanup, and unclassified local handler failures remain
    disconnect-only. The policy is a required argument rather than a default, so a close can never
    inherit an unrelated caller's decision, and `disconnectAll` states `ALLOW` explicitly like every
    other caller. Timing and silence failures state the bounded tier instead, so a skewed clock or a
    missing reply costs a peer its connection but not its standing until the bound is reached
    ([`REQ-AUTH-4-JWCF71` (Penalty requires proof, and clock faults are not proof)](../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).
11. **The initial sync wait is bounded before a request exists.** The one initial sync request carries a
    two-agreement-window timeout, but an uncommitted observer could previously wait forever for the first
    participant handshake that produces that request. `joinDiscoveryKey` now arms the same two-window
    deadline; if no participant completes a handshake in time, the observer aborts and its connect settles
    as `false`, exactly as a timed-out request would. A cooperating peer must arrive within the window; the
    runtime never waits for a later one.
12. **The initial sync wait settles on any exit from `OPENED`.** One private settlement helper cancels the
    deadline, records the outcome, and resolves the wait once; nothing else touches the resolver. The
    manager subscribes once to the status hook: a real `OPENED → other` transition settles `true` for
    `SYNCED`, `PENDING_PARTICIPANT`, or `PARTICIPATING` and `false` otherwise, whether or not the sync
    request has started. `dispose` and the abort hook settle `false`. `joinDiscoveryKey` races the discovery join against
    the armed wait itself: the wait settles on abort and on disposal, so a disposed manager settles
    `false` and returns at once, letting the pending connect reply leave before the disposal that
    follows the abort closes the port, while the join finishes in the background under that
    disposal; any other settlement keeps waiting for the join. It re-checks the
    status after the discovery join, the deadline task settles instead of returning when the status has
    left `OPENED`, and `syncConnectedParticipant` ignores a false remote result once the wait is settled
    or the status has moved, so chain genesis landing during the join or during an active request can
    neither hang the connect nor abort an already synced runtime.

Disposal shares one promise. It attempts Holepunch cleanup even when profile transport cleanup fails, then preserves the first failure.

## Assumptions, dependencies, trust boundaries, and limits

- Operates inside the participant runtime; untrusted input arrives only through the documented ingress paths.

## Specification adherence

- Stages 1–4 with authenticated frame, envelope, service-name, and endpoint-name exclusion, neutral
  local-failure disconnects, and correlation single-settlement.
- One close entry point with a required policy, so every stage's consequence is stated at its call
  site and expected or upgrade closes are explicitly the reconnect-allowed outcome
  ([`REQ-RPC-6-E60S4J` (Ordered ingress verification)](../../../specification/peer-communication/rpc.md#req-rpc-6-e60s4j)).

## Specification contradictions

None demonstrated.

## Missing behavior

Per-peer rate limiting is the designated missing admission control ([`OQ-6-4JPNE5` (P2P gossip rate limiting)](../../../specification/open-questions.md#oq-6-4jpne5)); request cancellation API absent (timeout-only) — documented limitation.

## Targeted connect contribution

Handshake routing recognizes an active matcher attempt without requiring `DISCOVERING`. While the runtime
is uncommitted, the first connected peer proven by authoritative chain state to be a participant starts one
ordinary sync call with a two-window timeout. `P2PManager` aborts on a false result.
Successful matched opening promotes and preserves the participant transport for first sync; observed-open
loser handling joins only the selected raw topic and does not promote the loser. Pending RPC records retain
their original transport; retiring it rejects the request. A response from a foreign peer is rejected.

[`UNIT-TEST-P2P-MANAGER-1-9DNSRZ.P25`](P2PManager.ts.md#unit-test-p2p-manager-1-9dnsrz.p25) means original-transport retirement rejects its pending request even when a replacement exists; `.P3` remains foreign-responder rejection.

Shared operation owners: [errorMessage.ts.md](utils/errorMessage.ts.md), [bytes32.ts.md](utils/bytes32.ts.md).

Runtime disposal also invokes the profile manager cleanup inventory, so unauthenticated connections are closed before logger teardown. Loopback close remains a no-op so disposal invoked through it can return its response.
