## Responsibility and observable boundary

The Block domain model: decode/encode against the canonical struct, identity hash, coordinates,
signature-set expansion (dedup by recovered signer), `didEveryoneSign`, relevant-timestamp logic
(author-signed vs posted), and equality.

## Key design decisions

acceptedSignerAddresses collects only signatures accepted by the contract encoding rule and deduplicates signer addresses. Malformed peer signatures contribute no signer. Strict signatureToAddress remains strict; safe metadata uses the accepted set. See [Block.ts](../../../../../../src/models/Block.ts#L277).

Constructors, author signing, expansion and removal share SignatureUtils byte normalization. Equivalent hex casing and byte arrays use the same stored bytes and recovery-cache key. Actual v bytes, compact values and malformed envelopes are preserved for validation. mergeFrom retains the first author envelope and the established defined-timestamp semantics; the queue delegates those rules here. See [normalizeSignature](../../../../../../src/models/Block.ts#L49).

Same-block copy merging belongs to Block: expand confirmation signatures, then copy a defined on-chain timestamp, including zero. Callers remain responsible for block identity and trust policy. See [mergeFrom](../../../../../../src/models/Block.ts#L289).

1. **Signature expansion dedups by recovered signer**, so encoding malleability cannot double-count ([`REQ-ID-1-3Q2KB9` (Recoverable signatures over canonical targets)](../../../../specification/protocol-model/identity.md#req-id-1-3q2kb9) malleability rule).
2. **Relevant timestamp encodes the forfeit rule's data side:** the author-signed predecessor uses block time; a posted one the on-chain time.
3. **Author authenticity is a pure model predicate under the contracts' signature rule.** `isAuthentic`
   ([#L254](../../../../../../src/models/Block.ts#L254)) recovers the original signature through
   [`recoverSigner`](../cache/SignerRecoveryCache.ts.md) and compares it with the header participant:
   the same EIP-191 scheme over `keccak256(encodedBlock)` as the contracts' `retrieveSignerAddress`,
   and only the signature encodings OpenZeppelin ECDSA accepts. Any encoding the contracts reject,
   and any malformed signature, yields `false`, never an exception. It needs no EVM call and no
   mirrored state (engineer decision 2026-09-26; the signature carve-out of
   [`INV-MIRROR-1-VAF778` (Single implementation)](../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778)). Confirmation signatures go through the same
   `signatureToAddress` ([#L322](../../../../../../src/models/Block.ts#L322)), so they follow the same acceptance rule. Intake
   ([BlockQueueManager](../stateManager/ingest/BlockQueueManager.ts.md)) and proof replay
   ([BlockIngestService](../stateManager/ingest/BlockIngestService.ts.md)) read it on the block they
   decoded.
4. **The queue's author-signed copy shares the decode instead of repeating it.** `authorSignedCopy()`
   ([#L83-L101](../../../../../../src/models/Block.ts#L83-L101)) exists because the queue keeps the author-signed block apart from the
   confirmations it merges. It returns the block with its author signature, its on-chain timestamp
   and no confirmation signatures, sharing the decoded struct, the encoded bytes and the cached hash rather
   than decoding and hashing again. The copy gets its own confirmation set. Because the struct is
   shared, the caller must own the instance; [QueueStorage](../storage/QueueStorage.ts.md)
   `createEntry` calls it on the per-call copy the storage boundary makes, and `mergeEntry` calls it
   on the target entry's block, so a signature merge never decodes again.
5. **`Codec` is the only block decoder.** `fromBlockConfirmation`/`fromSignedBlock` decode the
   signed bytes with `Codec` (a plain ABI decode), and `tryFromBlockConfirmation`/`tryFromSignedBlock`
   ([#L103](../../../../../../src/models/Block.ts#L103), [#L117](../../../../../../src/models/Block.ts#L117)) turn a decode failure into `null` so a caller can refuse the
   confirmation as inauthentic. The model applies no canonical-encoding rule and never asks the
   contracts' decoder (engineer decision 2026-09-27, review item LO3). The client decoder and the
   contracts' Solidity decoder can therefore disagree on non-canonical bytes; that deviation is the
   open finding [`FIND-DECODE-1-FD1V6V`](../../../../audit/open-findings.md#find-decode-1-fd1v6v).

## Assumptions, dependencies, trust boundaries, and limits

- Operates inside the participant runtime; untrusted input arrives only through the documented ingress paths.

## Specification adherence

- Canonical encoding round-trips; identity = hash of canonical encoding.

## Specification contradictions

- Envelope decoding runs in client code (`Codec`), outside the signature carve-out of
  [`INV-MIRROR-1-VAF778` (Single implementation)](../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778), and can accept or reject byte encodings the contracts' decoder treats
  differently. Known and open: [`FIND-DECODE-1-FD1V6V`](../../../../audit/open-findings.md#find-decode-1-fd1v6v).

None demonstrated.
