# InternalRpcRouter.ts — Source Report

> **Source:** [src/rpc/router/InternalRpcRouter.ts](../../../../../../../src/rpc/router/InternalRpcRouter.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Binds common request settlement and service dispatch to one runtime root. It admits replies only from their exact connection, classifies responses before requests, and returns bounded correlated ingress errors when enough request identity is recoverable.

## Key design decisions

- Ingress awaits shared service dispatch, including asynchronous endpoint completion. Responses are still correlated before dispatch. Transport callbacks start each invocation independently, preserving concurrent and reentrant traffic.

- Failed error-response delivery reports through the owning root, without a separate router callback.

- Receive-after-close filtering is internal-only and runs at the router entry. Both direct ingress and common transport forwarding ignore a closed internal sender. Network receive-after-close behavior is unchanged.

- Internal response admission uses exact connection identity ([`InternalRpcRouter.ts`](../../../../../../../src/rpc/router/InternalRpcRouter.ts#L23)).
- Responses enter settlement before any service dispatch ([`InternalRpcRouter.ts`](../../../../../../../src/rpc/router/InternalRpcRouter.ts#L30)).
- Recoverable malformed requests receive one error; uncorrelatable garbage is ignored ([`InternalRpcRouter.ts`](../../../../../../../src/rpc/router/InternalRpcRouter.ts#L36)).
- Endpoint setup installs execution context around ingress; services stamp endpoint errors before serialization. The router owns no invocation wrapper.

The internal router overrides the common error-restoration hook with the shared internal error codec. Callers do not pass a separate restoration function.

## Assumptions, dependencies, trust boundaries, and limits

The router has no blacklist, peer profile, address lookup, broadcast or logger traversal. Cross-realm configuration and same-realm link ownership belong to the root and factories. Unknown one-way endpoints are not converted into request acknowledgements. Browser connection lifetime remains explicitly owner-managed.
