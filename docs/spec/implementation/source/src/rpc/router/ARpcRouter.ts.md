## Responsibility and observable boundary

Owns awaited service dispatch, request IDs, registration, deadlines, send-failure cleanup, admitted response correlation and rejection by connection or whole owner. Each router has its own pending map. Network and runtime specializations provide admission and default scheduling; domain services provide error preparation/restoration.

Pending state stores the same request envelope sent to the transport, including the generated request ID. Deadline, remote-error and send failures are the router's own errors and carry the failure kind on the standard `Error` `cause`. A transport closure rejects with the reason its caller supplied, unchanged in identity, class and fields; the router records those reasons so the same kind is read back from them.

## Key design decisions

- `dispatchRpc` awaits the service’s boolean consumed verdict. Endpoint execution and response construction belong together in [RpcDispatch](../RpcDispatch.ts.md); guards and domain policies stay with services.
- One-way calls also await completion internally. Each transport callback starts an independent invocation; no shared queue blocks another message. Synchronous throws and rejected promises retain their separate network failure policies.

- A pending entry and its timer are installed before send, including synchronous loopback replies ([`ARpcRouter.ts`](../../../../../../../src/rpc/router/ARpcRouter.ts#L160)).
- Response admission runs before consuming a pending entry ([`ARpcRouter.ts`](../../../../../../../src/rpc/router/ARpcRouter.ts#L194)).
- Settlement deletes the entry and cancels its timer before resolving or rejecting ([`ARpcRouter.ts`](../../../../../../../src/rpc/router/ARpcRouter.ts#L201)).
- Failure causes distinguish deadline, remote error, transport closure and send failure as a small named union, so a caller branches on the kind instead of matching message text ([`ARpcRouter.ts`](../../../../../../../src/rpc/router/ARpcRouter.ts#L12)).
- The kind lives on the standard `Error` `cause` only for the errors the router itself creates. A close reason belongs to the caller that closed the transport, so rewriting or mutating it would cost the caller its error class, fields and object identity; the rejected reasons are recorded in a module-level weak set that the kind is read back from instead ([`ARpcRouter.ts`](../../../../../../../src/rpc/router/ARpcRouter.ts#L28)).

Pending state stores the exact outgoing envelope, including requestId. Error restoration has one protected router hook; each router category owns its restoration policy, with no per-request override.

## Assumptions, dependencies, trust boundaries, and limits

Timeout defaults remain with NetworkRpcRouter (using the manager time configuration) or InternalRpcRouter. The router does not authenticate peers, choose recipients, retry calls, serialize independent domains, restart workers or cancel side effects. Network replacement admission and exact internal identity are specialization hooks. Error restoration is supplied by the domain connection.
