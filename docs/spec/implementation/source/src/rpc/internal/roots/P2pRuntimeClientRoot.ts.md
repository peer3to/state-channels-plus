# P2pRuntimeClientRoot.ts — Source Report

> **Source:** [src/rpc/internal/roots/P2pRuntimeClientRoot.ts](../../../../../../../../src/rpc/internal/roots/P2pRuntimeClientRoot.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Owns client communication with the host: one registered connection, incoming events and errors, bridge handoff and communication cleanup. P2pInstance keeps a direct reference. Application configuration, contracts, signers, deployments and logger ownership belong to setup and P2pInstance.

The parameterless start() contains domain initialization. Common creation supplies parent attachment, parent-close cleanup and readiness; this root does not wire them.

Port closure still triggers local client cleanup. When the child handle already records a fatal cause, RootErrorService owns its notification and the close callback omits the generic error.

## Key design decisions

The common createRoot logger option supplies the owned application child. The client local dependency bag no longer contains a logger. Base construction handles attachment; domain event and bridge diagnostics use the common root logger.

The client root receives its owned child logger. It supplies a separate child to the WebRTC broker. Shared root disposal releases each logger without disposing surviving relatives.

Common createRoot calls start and awaits host communication readiness. The root installs receivers and creates its host child with parent: this, retaining the registry's connection object. Application setup can use that connection for deployment after root creation returns. No application objects or deployment functions are required to create this communication root.

Startup failures use common cleanup. Common lifecycle disposes children; local cleanup releases bridge and connection resources. The root owns its supplied child; the original application logger remains separate. Host errors retain peer attribution and existing listener behavior. A parented root sends its disposal response before closing the parent connection.

| Inputs       | Serializable host setup payload, signer address and worker options; optional local logger, execution context and observation hooks.      |

## Assumptions, dependencies, trust boundaries, and limits

Application contracts and deploy functions stay in setup. Root arguments describe host communication and use the normal structured-clone boundary in child placement; local domain hooks remain local dependencies. Missing connection options reject before allocation. Parented disposal keeps its reply connection open until acknowledgement.

The browser close callback remains best-effort. Contract event replay retains the existing indexed-filter limitation because topics are not forwarded. Host errors restore prepared fields, then receive the owning peer stamp; no-subscriber post-ready errors remain observable unhandled rejections.
