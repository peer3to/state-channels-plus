# P2pRuntimeHostRoot.ts — Source Report

> **Source:** [src/rpc/internal/roots/P2pRuntimeHostRoot.ts](../../../../../../../../src/rpc/internal/roots/P2pRuntimeHostRoot.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Owns host startup, provider and signer dependencies, the executor child, runtime state, event forwarding and host cleanup. Its start method completes the deployment-capable host; sdkSetup.deployComplete later assembles the state manager from two independent deployed contract addresses. Optional parent attachment never fabricates a client recipient.

The parameterless start() contains domain initialization. Common creation supplies parent attachment, parent-close cleanup and readiness; this root does not wire them.

Each fallback host creates its own WebRTC bridge factory and binds it to its manager’s WebRTC setup service. Multiple inline hosts in the same worker keep independent handles and peer maps.

## Key design decisions

Startup reads the bound manager's maximum participant count and rejects nonpositive or unsafe integer values before constructing storage. The same value reaches the queue and admission limits. No independent four-times signature cap remains. Node and browser deployment callers pass the same effective N to the reference math machine. See [maxChannelParticipants](../../../../../../../../src/rpc/internal/roots/P2pRuntimeHostRoot.ts#L131).

The root reports what the peer spent on chain once, at disposal, before the provider is destroyed and while its logger is still alive. The report goes through the recorder's settle-then-snapshot, so the receipts a shutdown's own transactions are still waiting for are in it; that wait is bounded by `GAS_USAGE_SETTLE_MS`, because disposal must not hang on the chain. Right after the report the root disposes the recorder, which ends every receipt wait still running as not counted, before the provider that would never end them closes. The root has no gas usage read of its own: callers read the table through the chain-signer service. See [dispose](../../../../../../../../src/rpc/internal/roots/P2pRuntimeHostRoot.ts#L399).

Handler execution context comes from common root startup. The optional local host dependencies do not override it.

Worker configuration is restored before base construction. Startup updates peer identity on the automatic root logger rather than constructing or attaching another logger. Provider startup therefore already has logging available.

Worker monitoring runs through the common root lifecycle. For an inline executor, the host supplies an owned child logger; a worker executor creates its own logger.

The root owns the startup implementation formerly in the free P2pRuntimeHost function. Runtime state is stored on the root and services receive explicit domain dependencies. Common creation attaches the root before asynchronous loading, so partial startup cleanup can always find it. The host awaits its executor before readiness; later deployment assembly is a separate domain milestone.

The concrete dispose implementation stops StateManager producers and drains work while the executor is available, then invokes shared recursive child disposal. After preparation drains host work and children finish disposal, final cleanup destroys the owned provider before removing its event listener. State-manager cleanup, discovery, event forwarding and logger cleanup still run after earlier failures. Providers owned by Clock remain open. The first failure is preserved. Event forwarding is removed after dependent cleanup.

Worker entries and executor selection are internal. HostContext retains the runtime construction dependency; scripted workers and root observation live in test infrastructure. A worker-side WebRTC bridge is a child root, with its main-thread broker as its child. The SDK service forwards the port upward. The RuntimeHost creates the worker bridge root and attaches its handle to the network adapter; the network service selects that adapter through its original factory fallback. Broker installation is not a readiness condition; negotiation waits for attachment.

The host reads handler execution context from its base root start context; HostContext contains only the executor factory dependency. Its isDisposed override also observes StateManager abort, which can precede completion of root disposal.

## Assumptions, dependencies, trust boundaries, and limits

This root does not duplicate the runtime state machine or peer MainRpcService composition. Full SDK setup owns executor construction. P2P-only methods use the readiness accessor before decoding input, while allowed raw signing and deployment address reads retain their pre-deployment behavior.
