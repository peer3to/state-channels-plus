# ContractExecutorRoot.ts — Source Report

> **Design views:** [Runtime and concurrency](../../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

The same start initializes standalone and parented executors. Parent attachment is optional; executor loading always completes before readiness. Standalone has no parent notification.

The parameterless start() contains domain initialization. Common creation supplies parent attachment, parent-close cleanup and readiness; this root does not wire them.

## Key design decisions

The base constructor owns rootLogger. This root restores worker config before calling the base and passes rootLogger to the executor service. It has no private logger field or logger-only local argument. Detached reporting uses the logger error path once, without a second global flush.

The executor root owns its supplied child logger or creates one. Common root disposal releases that logger unconditionally. Worker monitoring belongs to the common root start/dispose path; the concrete root has no ownership flags or monitor options.

The root passes the automatic rootLogger to the executor service. It restores worker config. Shared root lifecycle owns monitoring and logger cleanup. Disposing this root preserves its caller's separate logger.

The root supplies the same instance `start` operation for inline and worker placement. The explicit worker entry invokes common bootstrap, which installs the worker error funnel before attachment and transport readiness. Inline construction keeps the supplied logger and execution context; createRoot initializes worker-only globals before loading dependencies, with no root-specific import or call.

- Common root startup attaches the parent and signals readiness after executor initialization. The concrete root disposes its engine; shared lifecycle coordination closes connections after the reply attempt and shuts down a dedicated worker.

- Uses base-owned logging; initialization timing is unchanged.

- The executor uses no default RPC timeout ([`ContractExecutorRoot.ts`](../../../../../../../../src/rpc/internal/roots/ContractExecutorRoot.ts#L18)).
- Detached errors are projected once and sent through the parent SDK callback service ([`ContractExecutorRoot.ts`](../../../../../../../../src/rpc/internal/roots/ContractExecutorRoot.ts#L40)).
- Readiness is emitted after executor initialization and all child readiness promises complete ([`ContractExecutorRoot.ts`](../../../../../../../../src/rpc/internal/roots/ContractExecutorRoot.ts#L47)).

## Assumptions, dependencies, trust boundaries, and limits

The SDK factory must supply the owning parent endpoint. The worker bootstrap installs its error funnel before start. Inline construction passes the live handler execution context locally and creates no worker config or monitor. Successful init and post-response shutdown remain the executor service's responsibility.
