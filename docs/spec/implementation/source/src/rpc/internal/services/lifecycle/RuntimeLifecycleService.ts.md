# RuntimeLifecycleService.ts — Source Report

> **Source:** [src/rpc/internal/services/lifecycle/RuntimeLifecycleService.ts](../../../../../../../../../src/rpc/internal/services/lifecycle/RuntimeLifecycleService.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../../../views/architecture/sdk/runtime-and-concurrency.md)

Both disposal directions await final acknowledgement. Parent-requested cleanup first posts its domain response; if the parent closes after that response, closure also confirms shutdown. A child disposal acknowledgement confirms domain cleanup. For an inline child, shared finalization awaits both cached domain disposal and final reply closure before notifying parent close observers, so the acknowledgement can arrive and local connections finish closing.

## Responsibility and observable boundary

Owns per-child readiness, per-call quiescence and response-before-close coordination. The root owns recursive disposal and concrete cleanup. SDK deployment completion remains in its domain service.

## Key design decisions

The service opts out of the root's disposal drain (`awaitedByDisposalDrain` is false): a parent-requested disposal runs as one of its handlers and replies only after the disposal that drains the domain handlers, so waiting on it would wait on itself.

A closed or absent parent still allows final child cleanup without an acknowledgement. The creation owner marks expected worker shutdown before closing its port, so this path cannot race the later parent cleanup into a false exit report.

Cleanup delegates to [runCleanup.ts](../../../../utils/runCleanup.ts.md), which attempts all ordered steps before reporting the first failure. Caller-owned disposal promises and acknowledgement rules remain in this owner.

Readiness state distinguishes success from failure. An early notification satisfies later waiters; startup failure or connection closure rejects only that child's wait. Required initialization is awaited by createRoot. A forwarded WebRTC broker may attach later, so installation is excluded from readiness; negotiation waits for the broker.

Quiescence uses the root's child handles and then drains the existing runtime-wide DetachedPromises collection. The operation drains on every call. Concurrent callers share only the active drain; settlement clears that promise. An already disposed domain collects settled work rather than waiting for cancelled cleanup promises.

The service has no disposal algorithm or caller-facing disposeChild operation. Its dispose endpoint invokes the concrete root. After the response, an admitted parent request closes its connection once. A rejected upward request cannot close the parent.

Locally initiated disposal requests acknowledgement from its parent and waits before closing or exiting. This ensures the parent starts expected worker shutdown before the worker can exit, even while the parent event loop is busy. Parent-requested disposal waits until its response has been attempted, including a failed post. Admission is retained by sender identity even after the parent connection is removed. Only a child may announce disposal. The parent posts the acknowledgement before retiring the child handle and starting its cached platform cleanup. Parent-requested disposal uses the original reply and sends no second disposal request.

## Assumptions, dependencies, trust boundaries, and limits

Readiness is sent one-way to the parent. The root owns recursive disposal and domain cleanup. This service coordinates the disposal reply attempt and final closure, even if posting fails or the admitted parent has disappeared. Quiescence shares concurrent callers, drains again on later calls and uses settled-only local collection once the root is disposed. Disposal does not invoke quiesce. Request versus send is selected explicitly by the caller. The service adds no peer admission policy, transport-specific error codec or router-wide queue.
