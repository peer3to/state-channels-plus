# LoggerService.ts — Source Report

> **Source:** [LoggerService.ts](../../../../../../../../../src/rpc/internal/services/logger/LoggerService.ts) > **Status:** Authored — engineer verification pending.

## Responsibility and observable boundary

One root's optional upload coordination service. It tracks actual stores and upload callbacks, not logger instances. Logger families own attachment and local uploading; this service owns gossip and context propagation over its root's live connections.

## Key design decisions

- One scalar upload index, one coalescing window and at most one pending timer per service. The default window is 3,000 ms, separate from HTTP jitter.
- Fresh local triggers advance the index; higher incoming values are adopted before forwarding unchanged. Equal/older values are ignored regardless of elapsed time. Invalid or exhausted indexes cannot wrap.
- Local triggers exclude the initiating store's already-scheduled upload. Remote triggers schedule local stores without originating another generation. The uploader bounds active work and one follow-up.
- Inline and worker roots use the same connection traversal. No static store registry, process-wide root scan, per-origin counter or distributed acknowledgment exists.
- Existing context exchange synchronizes generations on new connections without claiming an upload occurred. Channel context propagates without echoing the update to its inbound connection; this prevents queued old and new channel values from bouncing between roots. Peer identity flows from a remote parent; physical thread names stay local.
- Disposal cancels the timer and detaches stores. Surviving logger families clear their optional service reference and keep local upload support.

## Inputs, outputs, state, and side effects

Inputs are store attachments, local upload notifications, incoming index/reason and context. The upload endpoint returns no distributed result. The store map is keyed by the actual shared LogStore; callbacks retain the family's upload facility and detach operation. Sends are fire-and-forget. Closed neighbours do not stop other sends or local uploads.

## Assumptions, dependencies, trust boundaries, and limits

Gossip is normally faster than the coalescing window. Delayed or duplicate generations can leave newer entries for a later trigger. Counters measure scheduled attempts, not success. HTTP retries, delta cursors and compression remain in LogUploader. No result promises delivery by a remote root. Services with disabled stores still relay triggers.

## Specification adherence

The implementation follows the engineer's best-effort generation model. A store belongs to at most one service; children share that reference. A root using a supplied logger family retains its existing attachment rather than registering that store twice.

## Specification contradictions

None identified for the current gossip contract. The earlier per-origin aggregate-result contract is replaced.

## Missing behavior

Remote delivery is intentionally unacknowledged. This is a contract limit, not an incomplete acknowledgment implementation.
