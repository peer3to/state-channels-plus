# ContractExecutorService.ts — Source Report

> **Source:** [src/rpc/internal/services/contractExecutor/ContractExecutorService.ts](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Owns the receiving executor instance and its domain initialization. Both inline and dedicated executors receive operations through the same service. The canonical engine retains its mutex; this service adds no operation queue.

## Key design decisions

Disposal clears the executor reference and invokes its own disposal, releasing the executor child logger. The enclosing root owns and disposes its separate runtime logger.

Clock selection uses request.clockAdjustmentSeconds when defined, including zero; otherwise it reads the initialized shared Clock, or retains time zero when neither exists. Configuration, logger ownership and monitoring belong to ContractExecutorRoot.

Disposal clears the executor in both placements. Logger and monitor cleanup belong to the root; service disposal only clears the executor.

The service owns executor initialization and domain operations. Root diagnostics use common RPC metadata without inspecting executor arguments. Shared RemoteRoot lifetime owns observer installation and removal. No service-specific observeConnection operation remains.

Application manifests load before readiness. The supplied inline logger remains caller-owned; a root-created logger is disposed with the root. Common root error and lifecycle services carry startup, detached errors and disposal.

## Assumptions, dependencies, trust boundaries, and limits

Production construction requires the SDK owner. The service receives a logger directly and has no placement or monitoring options. The receiving methods reach the engine only after init. Functions and live resources in manifest options cannot cross structured clone. The common bootstrap installs the worker error funnel; the root awaits executor initialization before signaling readiness.
