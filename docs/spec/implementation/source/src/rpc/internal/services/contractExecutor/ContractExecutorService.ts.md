# ContractExecutorService.ts — Source Report

> **Source:** [src/rpc/internal/services/contractExecutor/ContractExecutorService.ts](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Owns the receiving executor instance, its domain initialization, and admission of executor operations during shutdown. Both inline and dedicated executors receive operations through the same service. The canonical engine retains its mutex; this service adds no operation queue, only a set of admitted operations that shutdown waits for.

## Key design decisions

Disposal clears the executor reference and invokes its own disposal, releasing the executor child logger. The enclosing root owns and disposes its separate runtime logger.

Clock selection uses request.clockAdjustmentSeconds when defined, including zero; otherwise it reads the initialized shared Clock, or retains time zero when neither exists. Configuration, logger ownership and monitoring belong to ContractExecutorRoot.

Disposal clears the executor in both placements. Logger and monitor cleanup belong to the root; service disposal only clears the executor.

The service owns executor initialization and domain operations. Root diagnostics use common RPC metadata without inspecting executor arguments. Shared RemoteRoot lifetime owns observer installation and removal. No service-specific observeConnection operation remains.

`ContractExecutorInitialization.callGasLimit` is an optional decimal string ([#L23-L25](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L23-L25)); `init` passes `BigInt(callGasLimit)` to the executor, or nothing when absent so the executor keeps the EVM default ([#L82-L88](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L82-L88)). A string keeps the value exact across structured clone in both placements ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)).

`init` passes the exact local executor root, already exposed as `this.router.rpcRoot`, to `createEvm` as a separate local argument ([#L52-L69](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L52-L69)). Custom precompile factories therefore receive their owner during executor startup, before readiness, and can create children under it; the reference never leaves this realm, and a worker executor supplies its own worker-side root. The service keeps no second owner field and its constructor is unchanged ([EvmFactory](../../../../evm/EvmFactory.ts.md)).

Shutdown admission and drain live here; endpoints delegate to it. `admit(operation)` rejects with `Contract executor is shutting down` once admission has closed, without entering the EVM ([#L100-L103](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L100-L103)). Otherwise it starts the operation, including one that then waits on the `ContractExecutor` mutex, and returns a new caller-facing promise rather than the operation's own. The operation's settlement and a caller rejection are wired to one settle-once latch: the operation's result or error settles the caller unless the caller was already rejected, and the admitted map keeps the tracked settlement as key and the caller rejection as value until the operation settles ([#L97-L119](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L97-L119)). `closeAdmission()` closes admission and races every tracked settlement against `IN_FLIGHT_REPLY_DRAIN_MS`, the five-second limit imported from [AInternalRpcRoot](../../AInternalRpcRoot.ts.md) that also bounds in-flight reply handlers at root disposal; repeated calls share one completion ([#L129-L142](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L129-L142)). Operations that settle within the limit settle their callers with their own result or error before any child is disposed. When the limit expires first, the service logs `Contract executor shutdown abandoned admitted operations` at debug with the abandoned count, then rejects every caller still waiting with `Contract executor shut down before the operation finished` and resolves, so disposal proceeds ([#L143-L151](../../../../../../../../../src/rpc/internal/services/contractExecutor/ContractExecutorService.ts#L143-L151)). The abandoned operation is not cancelled. When it later succeeds or fails, including mutex-queued work released only after the limit, the latch drops that outcome: the caller keeps the disposal rejection and no error reaches the host, because nothing uses that result after shutdown. [ContractExecutorRoot](../../roots/ContractExecutorRoot.ts.md) runs `closeAdmission` as the disposal preparation step, so admitted EVM work that may call a precompile child settles, or has its caller rejected at the limit, before children are disposed.

<a id="oq-impl-executor-drain-1-5d71ym"></a>

### OQ-IMPL-EXECUTOR-DRAIN-1-5D71YM — Resolved executor admission drain bound

Engineer decision, recorded 2026-09-29: the executor's admission drain at shutdown is bounded by the same constant as the in-flight reply drain, `IN_FLIGHT_REPLY_DRAIN_MS` (five seconds), now exported from [AInternalRpcRoot](../../AInternalRpcRoot.ts.md). Work still admitted at the limit is abandoned internally, children are disposed, and no host error is raised. Engineer decision, recorded 2026-09-29 after the second implementation review (option a): every caller still waiting at the limit always receives the disposal rejection `Contract executor shut down before the operation finished`, and the operation's later success or failure is dropped internally, so it never replaces that rejection; work that finishes within the limit keeps its own result or error. Strongest rejected alternative: keep the drain unbounded, so admitted work always finishes before its children close; it was rejected because one precompile call that never returns would keep executor disposal, and every owner disposal that waits for it, pending indefinitely. A separate executor constant and a worker-only bound were also rejected: one shutdown limit keeps both disposal waits aligned. Consequences: an admitted operation that runs past the limit may later succeed, or fail against a closed child, and either outcome is discarded while its caller keeps the disposal rejection; the `RuntimeLifecycle` worker disposal case with a held executor call completes again. Affected layers: specification ([`REQ-RUNTIME-3-VQXW59` (Lifecycle convergence)](../../../../../../../specification/runtime/execution.md#req-runtime-3-vqxw59)), this report and [ContractExecutorRoot](../../roots/ContractExecutorRoot.ts.md), the runtime view, the verification reports for `EvmFactory` and `RuntimeLifecycle`, and the implementation, verification, and security audits.

Application manifests load before readiness. The supplied inline logger remains caller-owned; a root-created logger is disposed with the root. Common root error and lifecycle services carry startup, detached errors and disposal.

## Assumptions, dependencies, trust boundaries, and limits

Production construction requires the SDK owner. The service receives a logger directly and has no placement or monitoring options. The receiving methods reach the engine only after init. Functions and live resources in manifest options cannot cross structured clone. The common bootstrap installs the worker error funnel; the root awaits executor initialization before signaling readiness.
