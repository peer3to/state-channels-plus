## Responsibility and observable boundary

The authenticator: drives the initiator half of the challenge/response exchange (fresh keccak
challenge, RTT/skew bounds, signature recovery under the domain tag, ack send) and owns
finalization — the idempotent gate requiring local verification AND the peer's ack before the
verified address is written to the exact transport and the completion hook fires. `ProfileManager` may refuse a fallback
transport after identity verification; refused transports close without publishing completion.
Connection promotion and sync belong to `P2PManager`; this service retains the WebRTC-upgrade
tie-break. Per-transport negotiation state lives in WeakMaps/WeakSets.

## Key design decisions

1. **Challenges are closure-scoped.** The random challenge never enters shared state — unguessable, single-use, exchange-bound ([`REQ-AUTH-2-BQ5CRG` (Fresh single-use challenges)](../../../../../../../specification/peer-communication/handshake.md#req-auth-2-bq5crg)).
2. **Completion requires both roles.** Verified-peer AND received-ack, checked in one idempotent finalizer, because each direction of the mutual exchange proves only one side ([`REQ-AUTH-3-ZV74KB` (Completion requires both roles)](../../../../../../../specification/peer-communication/handshake.md#req-auth-3-zv74kb)).
3. **Transport-keyed weak negotiation state.** Negotiation remains per connection; finalization
   authenticates and indexes the profile created with the transport instead of creating identity state elsewhere.
4. **Deterministic upgrade tie-break** (lower address initiates WebRTC) removes offer glare at completion.
5. **Policy refusal stops finalization.** An excluded identity or suppressed bootstrap fallback is
   closed by `ProfileManager`; no transport address, upgrade, hook, or barrier signal follows. When the
   response signer is an identity this node already excluded, the close
   [re-applies the exclusion](../../../../../../../../../src/rpc/network/services/initHandshake/InitHandshakeService.ts#L232) rather than closing plainly: the peer arrived on a new
   connection with a new bootstrap handle, and a plain close would leave that handle unbanned, so the
   peer re-dials and runs the whole handshake again. The write is idempotent on the profile.
6. **Completion releases only the same transport.** The barrier predicate reads that transport's
   verified address, so one replacement cannot release another pipe's guarded queue.
7. **Timing failures close, they do not punish.** The [round-trip](../../../../../../../../../src/rpc/network/services/initHandshake/InitHandshakeService.ts#L174) and
   [clock-difference](../../../../../../../../../src/rpc/network/services/initHandshake/InitHandshakeService.ts#L187) refusals close with reconnect allowed: a clock that disagrees
   is an environment fault, and refusing the session is already the whole defence
   ([`REQ-AUTH-4-JWCF71` (Penalty requires proof and an attributable fault)](../../../../../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).
8. **The ack timeout closes, whether or not the address was verified.** The
   [timeout task](../../../../../../../../../src/rpc/network/services/initHandshake/InitHandshakeService.ts#L383) now takes one branch. A late ack is a load or clock symptom rather
   than proof of a fault, so there is nothing to attribute even once verification has produced an
   address; the address is kept for the log only. The branch it replaced could not work anyway: no
   profile exists for an address that is verified but not yet authenticated, so excluding by address
   left the transport open.

## Assumptions, dependencies, trust boundaries, and limits

- Timing bounds derive from the agreement window (../../../../../../specification/protocol-model/time.md); the signer is the confined runtime signing authority ([`REQ-ID-3-KR0BE3` (Confined signing authority)](../../../../../../../specification/protocol-model/identity.md#req-id-3-kr0be3)).

## Specification adherence

- Only signature-over-own-challenge authenticates; acks carry no authority ([`INV-AUTH-1-J0PRYA` (Signature is the only proof)](../../../../../../../specification/peer-communication/handshake.md#inv-auth-1-j0prya)).
- Penalty only after proven identity: response timeout drops without exclusion; invalid timing,
  response shape, or signature from an already authenticated address excludes that address;
  verified-but-silent completion also excludes by address
  ([`REQ-AUTH-4-JWCF71` (Penalty requires proof and an attributable fault)](../../../../../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).

## Specification contradictions

None demonstrated.

## Missing behavior

Protocol-version binding into the handshake ([`REQ-RPC-8-44XECF` (Compatibility before protected calls)](../../../../../../../specification/peer-communication/rpc.md#req-rpc-8-44xecf)) is undesigned — [`OQ-34-FY08V2` (RPC boundary decisions)](../../../../../../../specification/open-questions.md#oq-34-fy08v2) coupled to [`OQ-29-EFY4NF` (Signature domain separation)](../../../../../../../specification/open-questions.md#oq-29-efy4nf).
