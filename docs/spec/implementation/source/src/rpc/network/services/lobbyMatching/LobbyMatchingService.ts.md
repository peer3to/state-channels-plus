# LobbyMatchingService.ts — Source Report

> **Source:** [src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts) > **Status:** Authored — engineer verification pending.

## Responsibility and observable boundary

`LobbyMatchingService` is the sole owner of one active caller-topic matching phase and its authenticated transport set. It owns lifecycle entry, matching cancellation, optional caller timeout, monotonic roles and epochs, candidates, one selector request, one advertiser reservation, mutual commitment, profile-loss recovery, and idempotent cleanup. A successful internal `match()` promotes only the selected profile, leaves the discovery topic, then closes the non-selected transports with reconnect allowed, and resolves one committed transcript without selecting a channel ID. The host signer consumes that transcript immediately, runs negotiation, and starts every unsigned retry from a fully closed, freshly joined session before returning the public join result.

### Stale commit cancellation

When profile loss makes an in-flight commit stale, the catch path counts one close against the absent peer
first (the commit was already sent, so the loss is an agreement-window liability) and then runs the existing
cleanup owner when cancellation is pending. The counted close keeps reconnect allowed and never records a
verdict. Cancellation resolves `true`, matching resolves without a match, and no matcher resource stays
active.

### Targeted connect contribution

The service is a generic caller-topic matcher. It returns only `LobbyMatch | undefined`, admits negotiation
traffic from a peer that owns an active matcher attempt, applies the optional local `shouldMatchPeer` filter,
and never starts negotiation. Unmatched timeout and both public cancellation wrappers share one cleanup owner.
`finishMatch` cancels the timer before resolving. `completeLobby` preserves a handed-off participant;
`releaseNegotiationHandoff` releases targeted loser or failed-attempt ownership without rematching.

Shared operation owners: [bytes32.ts.md](../../../../utils/bytes32.ts.md).

## Key design decisions

The self/filter gate is shared after each endpoint's existing input checks. Cleanup has only its transport-preservation option and still awaits topic leave before settling match and cancellation promises. See [LobbyMatchingService.ts](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L304).

1. Discovery requires a clean state manager. The service sets `DISCOVERING` before joining the exact 32-byte topic and supplies no default.
2. Two `none` peers use the existing canonical address comparison for opposite bootstrap roles. Later role periods use configurable one-to-two-second jitter.
3. Availability is the only one-way message. `pick` and `commit` use the shared request-response path.
4. An advertiser accepts one current-epoch picker atomically. Concurrent explicit pickers receive `busy`; no busy broadcast exists.
5. Final profile loss is neutral only while a pick is unanswered. After an accepted lease it is an agreement-window liability: `onProfileDisconnected` keeps the advertiser's reservation and its expiry running, so [`expireReservation`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L697) bars the absent selector at the bound, and keeps the selector's in-flight selection in place, so the rejected commit's catch path bars the absent advertiser at once, before the pending-cancellation cleanup runs. A burned agreement window is a matching fault, not a connection fault, so it closes with reconnect allowed and bars instead of excluding.
6. A correlated pick received after this session stopped matching returns `rejected`; it is not silent and does not make an honest selector punish the completed peer.
7. Omitted or null match timeout means no deadline. `cancelMatching` returns true only while matching is active; after commitment it returns false without touching negotiation.
8. Authenticated lobby transports never enter the ordinary connection set. Commitment promotes only the selected profile, including a healthy replacement authenticated during negotiation handoff; every other success or failure path closes all lobby-owned transports. An unsigned retry leaves and rejoins the same topic instead of retaining the prior mesh.
9. [`handoffSelectedPeer`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L857) collects the non-selected transports, awaits the topic leave, and only then closes them, and [`cleanup`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L769) follows the same order for cancellation, timeout, disposal, and unsigned retry. Closing a transport does not stop discovery, so the previous order — cut, then leave — had every loser re-dialled and re-cut for the duration of that negotiation. The leave stops this node from dialling; a peer still matching on the topic may reconnect once more and is closed again with reconnect allowed. [`leaveJoinedTopic`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L889) is the single owner of the leave, guarded by [`joinedTopic`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L81) so it runs at most once per session, and it reports a failed leave instead of throwing: making the handoff wait on a leave it cannot complete would cost more than the redial it prevents.
10. Every matching fault is a counted close on the shared disconnect ladder, and nothing else. [`recordRejectedRpc`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L271) blacklists bounded abuse with its reason; a burned window, an abandoned reservation, and a committed peer lost mid-handoff call [`disconnectConnection`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L896) with `allowRetry()`, so the peer stays selectable below the bound and [ProfileManager](../../../../ProfileManager.ts.md) refuses it at authentication once suspended. There is no session-local set to consult or clear: [`isMatchablePeer`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L943) checks only self and the caller policy.
11. Session start waits for the previous cleanup and owns its own state. [`match`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L132) awaits [`cleanupInFlight`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L87), the promise of a cleanup that is still leaving its topic, so a new session never loses its transports or its caller-set status to an old cleanup; [`runCleanup`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L770) skips the status reset while a session is waiting. [`startMatching`](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L483) clears the remembered peer role epochs, because a peer met in an earlier session would otherwise send its bootstrap availability at an epoch this map already holds and be read as a repeat.

## Inputs, outputs, state, and side effects

Inputs are caller topics/timeouts, authenticated transports and availability/pick/commit traffic. State includes roles, candidates, reservations, selected transports and cancellation. Output is a committed transcript or undefined; effects include discovery join/leave, scheduled expiry, and reconnect-allowed or counted transport closes. The public availability snapshot also reports whether the topic is still joined.

## Assumptions, dependencies, trust boundaries, and limits

The shared peer predicate runs only after the original input guards. Matching owns its transports until handoff; cleanup awaits discovery leave before settling promises. Signed opening lifetime belongs to negotiation.

## Specification adherence

The source contribution is limited to the linked requirements and operation described above; surrounding policy remains in the related owners.

- `reset()` runs the same `cleanup()` as disposal but leaves matching available ([#L236](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L236)), so an attempt or handed-off transport belonging to the channel just left is settled and released while the service keeps serving the next channel. It passes `keepStatus: true`, which skips the `NOT_OPENED` restoration at the end of `cleanup` ([#L751](../../../../../../../../../src/rpc/network/services/lobbyMatching/LobbyMatchingService.ts#L751)), so the reset's owner — `StateManager.resetChannel()` — is the one that sets the status last. Contributes to [`REQ-SDK-ARCH-2-QBZAT8` (Ordered lifecycle)](../../../../../../../specification/runtime/sdk.md#req-sdk-arch-2-qbzat8).
