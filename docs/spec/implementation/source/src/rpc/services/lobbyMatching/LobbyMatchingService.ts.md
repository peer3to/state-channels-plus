## Responsibility and observable boundary

`LobbyMatchingService` is the sole owner of one active caller-topic matching phase and its authenticated transport set. It owns lifecycle entry, matching cancellation, optional caller timeout, monotonic roles and epochs, candidates, one selector request, one advertiser reservation, mutual commitment, profile-loss recovery, punishment, and idempotent cleanup. A successful internal `match()` closes non-selected transports, promotes only the selected profile, and resolves one committed transcript without selecting a channel ID. The host signer consumes that transcript immediately, runs negotiation, and starts every unsigned retry from a fully closed, freshly joined session before returning the public join result.

### Stale commit cancellation

When profile loss makes an in-flight commit stale, the catch path blacklists the absent peer first (the
commit was already sent, so the loss is an agreement-window liability) and then runs the existing cleanup
owner when cancellation is pending. Cancellation resolves `true`, matching resolves without a match, and no
matcher resource stays active.

### Targeted connect contribution

The service is a generic caller-topic matcher. It returns only `LobbyMatch | undefined`, admits negotiation
traffic from a peer that owns an active matcher attempt, applies the optional local `shouldMatchPeer` filter,
and never starts negotiation. Unmatched timeout and both public cancellation wrappers share one cleanup owner.
`finishMatch` cancels the timer before resolving. `completeLobby` preserves a handed-off participant;
`releaseNegotiationHandoff` releases targeted loser or failed-attempt ownership without rematching.

Shared operation owners: [bytes32.ts.md](../../../utils/bytes32.ts.md).

## Key design decisions

The self/filter gate is shared after each endpoint's existing input checks. Cleanup has only its transport-preservation option and still awaits topic leave before settling match and cancellation promises. See [LobbyMatchingService.ts](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L296).

1. Discovery requires a clean state manager. The service sets `DISCOVERING` before joining the exact 32-byte topic and supplies no default.
2. Two `none` peers use the existing canonical address comparison for opposite bootstrap roles. Later role periods use configurable one-to-two-second jitter.
3. Availability is the only one-way message. `pick` and `commit` use the shared request-response path.
4. An advertiser accepts one current-epoch picker atomically. Concurrent explicit pickers receive `busy`; no busy broadcast exists.
5. Final profile loss is neutral only while a pick is unanswered. After an accepted lease it is an agreement-window liability: `onProfileDisconnected` keeps the advertiser's reservation and its expiry running, so `expireReservation` blacklists the absent selector at the bound, and keeps the selector's in-flight selection in place, so the rejected commit's catch path blacklists the absent advertiser at once, before the pending-cancellation cleanup runs. Agreement-window silence or malformed committed work blacklists and disconnects the responsible peer.
6. A correlated pick received after this session stopped matching returns `rejected`; it is not silent and does not make an honest selector punish the completed peer.
7. Omitted or null match timeout means no deadline. `cancelMatching` returns true only while matching is active; after commitment it returns false without touching negotiation.
8. Authenticated lobby transports never enter the ordinary connection set. Commitment promotes only the selected profile, including a healthy replacement authenticated during negotiation handoff; every other success or failure path closes all lobby-owned transports. An unsigned retry leaves and rejoins the same topic instead of retaining the prior mesh.
9. **Closing a lobby transport is a pause unless the peer is also suspended, so both unwanted-peer
   closes go through `disconnectForSession`** ([#L877](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L877)). The peer still shares the
   topic, so discovery re-dials it, the handshake reruns, and the same rejection repeats. The
   suspension does not stop the re-dial — it refuses the peer at handshake admission instead, so the
   rerun never reaches the lobby again. The two call
   sites are the non-selected candidates at commitment handoff ([#L860](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L860)) and a
   transport past the ignored-traffic bound ([#L261](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L261)). The suspension is a reconnect
   ban, never a blacklist: neither peer did anything provable, and the session simply does not want more
   of them ([`REQ-LOBBY-9-N894C0`](../../../../../../specification/peer-communication/lobby-matching.md#req-lobby-9-n894c0)).
10. **Cleanup leaves the topic before closing that session's transports, and only then lifts the bans**
    ([#L771](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L771)). Closing first while the topic is still observed queues a redial that the
    leave then races; leaving first makes every close final. The bans are lifted in the same branch that
    performs the leave, so a session that never left the topic never lifts a ban it may still need, and a
    session that did leave ends with no peer suspended and none excluded. `reconnectBannedPeers`
    ([#L65](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L65)) is session-scoped precisely so the lift is exact: only peers this session
    suspended are released, never a ban placed by something else.
11. **A suspension is placed only while a session exists to lift it.** `disconnectForSession` gates
    ban placement on `activeTopic` ([#L879](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L879)). Rejected lobby traffic still routes here
    after `completeLobby`/`leaveLobby`, and the lift branch runs only when there was a topic to leave —
    so a ban placed with no session would stand with nothing left to release it. Without a topic the
    plain close is already final, because nothing observes the rendezvous any more
    ([`REQ-LOBBY-9-N894C0`](../../../../../../specification/peer-communication/lobby-matching.md#req-lobby-9-n894c0)).
12. **One cleanup at a time, and `match` waits for it.** `cleanup`
    ([#L732](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L732)) publishes the running teardown as `cleanupInFlight`
    ([#L91](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L91)) and `match` settles it before starting a session
    ([#L138](../../../../../../../../src/rpc/services/lobbyMatching/LobbyMatchingService.ts#L138)). Cleanup clears `activeTopic` before it suspends on the discovery
    leave, so without this wait a concurrent `match` reads "no session", starts a new one into the same
    instance-wide `sessionTransports`/`reconnectBannedPeers`/`handedOffTransports`, and the older
    cleanup then closes the new session's transports, drops its suspensions, and resets its status when
    it resumes. The tracker clears itself once settled, so the ordinary path adds no wait
    ([`REQ-LOBBY-9-N894C0`](../../../../../../specification/peer-communication/lobby-matching.md#req-lobby-9-n894c0)).

## Assumptions, dependencies, trust boundaries, and limits

The shared peer predicate runs only after the original input guards. Matching owns its transports until handoff; cleanup awaits discovery leave before settling promises. Signed opening lifetime belongs to negotiation.

- Operates inside the participant runtime; lobby payloads are untrusted until the topic, epoch,
  attempt, and role checks pass.
- A reconnect ban is local and in-memory. It stops this node from admitting the peer; it leaves both
  sides dialing, it does not stop the peer from dialing a third party, and it does not survive the
  session.
- Lifting the ban admits the next attempt immediately — the attempts never stopped — so a peer that
  exhausted the ignored-traffic bound in one session can return in the next; that is the intended
  weakness of a non-exclusion.

## Specification adherence

The source contribution is limited to the linked requirements and operation described above; surrounding policy remains in the related owners.

- Every deviation the lobby answers with a close also suspends the peer's reconnects, so the redials
  that follow are refused before they reach the lobby again, and neither edge records a fault.
- Cleanup's leave-then-close ordering is explicit, not incidental.
