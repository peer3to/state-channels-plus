## Responsibility and observable boundary

The authenticator: drives the initiator half of the challenge/response exchange (fresh keccak
challenge, RTT/skew bounds, signature recovery under the domain tag, ack send) and owns
finalization — the idempotent gate requiring local verification AND the peer's ack before the
verified address is written to the exact transport and the completion hook fires. `ProfileManager` may refuse a fallback
transport after identity verification; refused transports close without publishing completion.
Connection promotion and sync belong to `P2PManager`; this service retains the WebRTC-upgrade
tie-break. Per-transport negotiation state lives in WeakMaps/WeakSets.

## Key design decisions

1. **Challenges are closure-scoped.** The random challenge never enters shared state — unguessable, single-use, exchange-bound ([`REQ-AUTH-2-BQ5CRG`](../../../../../../specification/peer-communication/handshake.md#req-auth-2-bq5crg)).
2. **Completion requires both roles.** Verified-peer AND received-ack, checked in one idempotent finalizer, because each direction of the mutual exchange proves only one side ([`REQ-AUTH-3-ZV74KB`](../../../../../../specification/peer-communication/handshake.md#req-auth-3-zv74kb)).
3. **Transport-keyed weak negotiation state.** Negotiation remains per connection; finalization
   authenticates and indexes the profile created with the transport instead of creating identity state elsewhere.
4. **Deterministic upgrade tie-break** (lower address initiates WebRTC) removes offer glare at completion.
5. **Policy refusal stops finalization.** An excluded identity or suppressed bootstrap fallback is
   closed by `ProfileManager`; no transport address, upgrade, hook, or barrier signal follows.
6. **Verification refuses on two standings, and only the exclusion touches the handle.** One
   `refusal` value ([#L216](../../../../../../../../src/rpc/services/initHandshake/InitHandshakeService.ts#L216)) covers both a blacklisted and a reconnect-banned signer,
   so the refusal reason is logged distinctly while the outcome — no session, no address written — is
   identical. Only the exclusion branch calls `banTransportReconnect`
   ([#L239](../../../../../../../../src/rpc/services/initHandshake/InitHandshakeService.ts#L239)): an excluded peer can rotate the discovery key it announces and arrive on
   a fresh handle, so exclusion must ban the handle the attempt came in on or it degrades into a pause.
   A suspension does nothing to the handle. It is a local, liftable refusal, so the suspended peer
   stays discoverable and keeps arriving here to be refused until the session that placed the
   suspension lifts it; banning its handle instead would make the refusal outlive the session on an
   object the later `allowReconnect` cannot reach
   ([`REQ-AUTH-4-JWCF71`](../../../../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).
   Neither branch writes a blacklist mark, so refusing a suspended peer never escalates into an exclusion.
7. **Completion releases only the same transport.** The barrier predicate reads that transport's
   verified address, so one replacement cannot release another pipe's guarded queue.
8. **The ack timeout only punishes an open transport.** The scheduled task returns before any
   consequence when `transport.isClosed`
   ([#L375](../../../../../../../../src/rpc/services/initHandshake/InitHandshakeService.ts#L375)),
   logging the same `ack-timeout` message with the reason `transport closed before the handshake
ack`. A closed transport cannot carry the ack, so its absence is explained by the close and
   attributes nothing to the peer; the exclusion is for a peer that stays connected and withholds
   the ack. The refusal paths of decision 6 are exactly the case this protects: the peer that
   refuses us — an exclusion, or a session reconnect suspension it placed — closes without acking,
   so without this gate the refused side excludes the refuser and a one-sided local suspension
   becomes a mutual permanent exclusion
   ([`REQ-AUTH-4-JWCF71`](../../../../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).

## Assumptions, dependencies, trust boundaries, and limits

- Timing bounds derive from the agreement window (../../../../../../specification/protocol-model/time.md); the signer is the confined runtime signing authority ([`REQ-ID-3-KR0BE3`](../../../../../../specification/protocol-model/identity.md#req-id-3-kr0be3)).

## Specification adherence

- Only signature-over-own-challenge authenticates; acks carry no authority ([`INV-AUTH-1-J0PRYA`](../../../../../../specification/peer-communication/handshake.md#inv-auth-1-j0prya)).
- Penalty only after proven identity: response timeout drops without exclusion; invalid timing,
  response shape, or signature from an already authenticated address excludes that address;
  verified-but-silent completion also excludes by address, but only while that transport is still
  open
  ([`REQ-AUTH-4-JWCF71`](../../../../../../specification/peer-communication/handshake.md#req-auth-4-jwcf71)).
- Refusal is not penalty: an already-excluded or reconnect-banned signer is refused at verification with
  no new consequence recorded against the identity, and the refused peer records none either — the
  refusal closes the transport, and a closed transport's missing ack ends the timeout task without a
  disconnect or a blacklist.
