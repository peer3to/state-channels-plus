# NetworkTransport.ts — Source Report

> **Source:** [src/transport/NetworkTransport.ts](../../../../../../src/transport/NetworkTransport.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Owns network transport identity, profile registration, trust defaults, JSON frames, and peer retirement policy. Concrete local, Holepunch, WebRTC and loopback transports inherit this category. Internal runtime ports have no network transport type or peer identity slot.

## Key design decisions

- Construction requires the owning manager’s `NetworkRpcRouter`; the manager accessor derives from that router. Profile registration timing and close/log/event ordering are unchanged. The default `onMessage` converts host input with `toString()` and calls `router.onRpc`; concrete adapters override conversion where their host format differs.

- The peer-address property exists as undefined before authentication, including across module graphs ([`NetworkTransport.ts`](../../../../../../src/transport/NetworkTransport.ts#L18)).
- Same-peer comparison accepts identical objects or two authenticated checksum addresses ([`NetworkTransport.ts`](../../../../../../src/transport/NetworkTransport.ts#L33)).
- Close preserves logging, listener notification, unexpected-disconnection hooks, manager retirement and concrete cleanup order ([`NetworkTransport.ts`](../../../../../../src/transport/NetworkTransport.ts#L58)).
- Network sends retain JSON serialization and its raw-bigint rejection ([`NetworkTransport.ts`](../../../../../../src/transport/NetworkTransport.ts#L72)).

| Aspect       | Boundary                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| Inputs       | Peer manager, logical RPC requests/responses, raw network frames, close classification and structural predicate candidates. |

| Owned state  | Network transport type, explicit peerAddress slot and owning peer manager; neutral close state is inherited.                |
| Side effects | Profile registration, network logging, disconnection hooks, manager retirement and concrete send/close.                     |

## Assumptions, dependencies, trust boundaries, and limits

Structural recognition is category detection, not authentication. Profile admission alone sets a remote peer address; trusted loopback names itself and retains synchronous JSON re-entry and no-op close. Conversion, serialization and concrete send errors remain synchronous. This category cannot be replaced by a neutral or internal transport in recipient selection.
