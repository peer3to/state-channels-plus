## Responsibility and observable boundary

The SDK's one owner of state proofs, plus the agreement and reduce-data reads over storage. Every
SDK component that builds or describes a state proof, or verifies it locally first, calls this
file. Two callers read the chain's own judgment of a proof directly instead:
[DisputeManager](../disputeManager/DisputeManager.ts.md) reads the chain's walk
(`verifyMilestones`) to pick the auditing data's finalized state, and
[DisputeValidationService](../stateManager/dispute/DisputeValidationService.ts.md) checks posted
auditing data with the chain's `verifyStateProof`.

- `buildStateProof(forkId, height, {stopAtThresholdCompletion?})` ([#L112](../../../../../../src/agreementManager/AgreementManager.ts#L112)–[#L176](../../../../../../src/agreementManager/AgreementManager.ts#L176)) builds a compact
  proof from the local proof start: one milestone per participant change above the start, the latest
  threshold milestone, then the unfinal tail up to `height` appended to the last milestone (or one run
  from the start block when no milestone exists). `-1` is the empty proof. It returns the proof with
  its walk evidence (`startSnapshot`, one `milestoneSnapshots` entry per milestone) and the builder
  walk's `finalizedSnapshot` (`BuiltStateProof`, [#L39](../../../../../../src/agreementManager/AgreementManager.ts#L39)–[#L47](../../../../../../src/agreementManager/AgreementManager.ts#L47)).
- `describeStateProof(forkId, proof)` ([#L179](../../../../../../src/agreementManager/AgreementManager.ts#L179)–[#L188](../../../../../../src/agreementManager/AgreementManager.ts#L188)) returns the same walk evidence for a foreign
  proof, without a walk.
- `verifyStateProof(proof, evidence)` ([#L196](../../../../../../src/agreementManager/AgreementManager.ts#L196)–[#L256](../../../../../../src/agreementManager/AgreementManager.ts#L256)) answers `valid` (with the start,
  finalized snapshot and `replayBlockIndex`, the start of the last milestone's unfinal tail; the last
  milestone's length means no tail), or `invalid` (`StateProofVerification`, [#L49](../../../../../../src/agreementManager/AgreementManager.ts#L49)–[#L58](../../../../../../src/agreementManager/AgreementManager.ts#L58)). Any read error throws.
- Proof readers: `getSnapshotFromMilestone` ([#L259](../../../../../../src/agreementManager/AgreementManager.ts#L259)–[#L269](../../../../../../src/agreementManager/AgreementManager.ts#L269)), `getLatestSnapshotFromStateProof` (genesis
  for an empty proof, [#L271](../../../../../../src/agreementManager/AgreementManager.ts#L271)–[#L290](../../../../../../src/agreementManager/AgreementManager.ts#L290)), `getLastBlockFromMilestone`, `getLatestBlockFromStateProof`
  ([#L292](../../../../../../src/agreementManager/AgreementManager.ts#L292)–[#L304](../../../../../../src/agreementManager/AgreementManager.ts#L304)).
- Agreement and reduction reads: `getLatestSignedBlockByParticipant` ([#L74](../../../../../../src/agreementManager/AgreementManager.ts#L74)–[#L92](../../../../../../src/agreementManager/AgreementManager.ts#L92)),
  `didEveryoneSignBlock` against the participant union ([#L94](../../../../../../src/agreementManager/AgreementManager.ts#L94)–[#L103](../../../../../../src/agreementManager/AgreementManager.ts#L103)), `getForkDisputeConfirmations` /
  `getForkDisputes` ([#L306](../../../../../../src/agreementManager/AgreementManager.ts#L306)–[#L331](../../../../../../src/agreementManager/AgreementManager.ts#L331)), and `getReduceData` ([#L333](../../../../../../src/agreementManager/AgreementManager.ts#L333)–[#L398](../../../../../../src/agreementManager/AgreementManager.ts#L398)), which returns `undefined`
  when the inbound run the reduce applied is not locally available ([#L374](../../../../../../src/agreementManager/AgreementManager.ts#L374)–[#L390](../../../../../../src/agreementManager/AgreementManager.ts#L390)).

The boundary: this file never writes storage and never sends a transaction. It reads storage, the
local diamond (`getAnchorSnapshot`, `verifyMilestones`, `verifyMilestonesFromTrustedStart`) and,
for the last verification tier only, the chain (`verifyMilestones`, `getAnchorSnapshot`).

## Key design decisions

1. **One owner for build, describe and verify.** [DisputeManager](../disputeManager/DisputeManager.ts.md), [DisputeValidationService](../stateManager/dispute/DisputeValidationService.ts.md), [SnapshotUpdateService](../stateManager/snapshotUpdate/SnapshotUpdateService.ts.md) and [SpectateService](../rpc/network/services/spectate/SpectateService.ts.md) call only
   `buildStateProof`, `describeStateProof` and `verifyStateProof` for proof construction and
   local-first verification. Where the chain's own answer is the oracle (the finalized state the
   chain's `verifyStateProof` binds, a posted-data check), the caller reads the contract directly
   and this file is not involved (decision 10). Why: the proof start, the milestone-snapshot
   mapping and the tier order are one rule each; a copy in a caller could drift from the contract
   walk and build or accept proofs the chain judges differently ([`REQ-SP-8-9PK9TS`](../../../../specification/disputes/dispute-processing.md#req-sp-8-9pk9ts)).
2. **The start comes from the walk's own predicate.** The private `getAnchorSnapshot` reads the
   diamond's `getAnchorSnapshot` on the local diamond once per operation ([#L407](../../../../../../src/agreementManager/AgreementManager.ts#L407)–[#L419](../../../../../../src/agreementManager/AgreementManager.ts#L419)): the on-chain
   anchor when `canUseOnChainSnapshot` (same fork, not the genesis), else the stored fork genesis. A missing genesis throws `Fork not found` ([#L454](../../../../../../src/agreementManager/AgreementManager.ts#L454)–[#L460](../../../../../../src/agreementManager/AgreementManager.ts#L460)).
   There is no TypeScript start rule. Why: the contract recognizes the genesis by its data, not its
   height; a second rule could disagree with it.
3. **Compact proofs: change milestones, latest threshold milestone, unfinal tail.**
   `buildThresholdMilestones` starts above a non-genesis start and seeds the threshold with the start
   snapshot ([#L471](../../../../../../src/agreementManager/AgreementManager.ts#L471)–[#L479](../../../../../../src/agreementManager/AgreementManager.ts#L479)). It builds one milestone per change point while each builds, because each
   proven set proves the next ([#L490](../../../../../../src/agreementManager/AgreementManager.ts#L490)–[#L508](../../../../../../src/agreementManager/AgreementManager.ts#L508)), then the latest milestone, built downward from the
   requested height ([#L510](../../../../../../src/agreementManager/AgreementManager.ts#L510)–[#L519](../../../../../../src/agreementManager/AgreementManager.ts#L519)). Blocks between threshold points are not part of the proof. The
   unfinal tail above the last milestone is appended to it; with no milestone it is one run from the
   start block ([#L128](../../../../../../src/agreementManager/AgreementManager.ts#L128)–[#L140](../../../../../../src/agreementManager/AgreementManager.ts#L140)). Why: the walk proves each milestone's first block by threshold from
   the last verified set and replays only the last milestone's tail ([`REQ-SP-2-ST4JJ4`](../../../../specification/disputes/state-proofs.md#req-sp-2-st4jj4), [`REQ-SP-3-SP1JG4`](../../../../specification/disputes/state-proofs.md#req-sp-3-sp1jg4), [`INV-SP-6-GNW74H`](../../../../specification/disputes/state-proofs.md#inv-sp-6-gnw74h)).
4. **Virtual voting as accumulation.** `tryBuildMilestone` collects one linked run and counts a later
   block's signatures toward the lowest block until the union of the previous set and the lowest
   block's resulting set has signed ([#L581](../../../../../../src/agreementManager/AgreementManager.ts#L581)–[#L607](../../../../../../src/agreementManager/AgreementManager.ts#L607)); `filterBlocksForMilestoneThreshold` keeps only the
   needed signatures up to the last contributing block ([#L636](../../../../../../src/agreementManager/AgreementManager.ts#L636)–[#L672](../../../../../../src/agreementManager/AgreementManager.ts#L672)) ([`REQ-FIN-3-9P9J4Q`](../../../../specification/protocol-model/finality.md#req-fin-3-9p9j4q), [`REQ-SP-1-9YABY1`](../../../../specification/disputes/state-proofs.md#req-sp-1-9yaby1)).
5. **A milestone is one linked run.** `tryBuildMilestone` stops at the first stored neighbor that is
   not exactly one height away or does not link by hash ([#L565](../../../../../../src/agreementManager/AgreementManager.ts#L565)–[#L577](../../../../../../src/agreementManager/AgreementManager.ts#L577)), and stops below a block that
   commits the previous threshold snapshot ([#L609](../../../../../../src/agreementManager/AgreementManager.ts#L609)–[#L615](../../../../../../src/agreementManager/AgreementManager.ts#L615)).
6. **Required history throws, never a weaker proof.** `buildStateProof` throws for a height below the
   start ([#L120](../../../../../../src/agreementManager/AgreementManager.ts#L120)–[#L123](../../../../../../src/agreementManager/AgreementManager.ts#L123)), `buildThresholdMilestones` for a missing participant-change block
   ([#L491](../../../../../../src/agreementManager/AgreementManager.ts#L491)–[#L496](../../../../../../src/agreementManager/AgreementManager.ts#L496)), and `collectLinkedRun` for a missing or unlinked tail block ([#L525](../../../../../../src/agreementManager/AgreementManager.ts#L525)–[#L546](../../../../../../src/agreementManager/AgreementManager.ts#L546)). Why: a
   proof with a gap is a proof the chain refuses; the caller decides what a failed build means
   ([`REQ-DISPUTE-PIPE-13-W73B2F` (Proof construction from the local start)](../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-13-w73b2f)).
7. **`stopAtThresholdCompletion` drops the unfinal tail** ([#L115](../../../../../../src/agreementManager/AgreementManager.ts#L115)–[#L116](../../../../../../src/agreementManager/AgreementManager.ts#L116), [#L128](../../../../../../src/agreementManager/AgreementManager.ts#L128)). A snapshot post
   proves final state only, so [SnapshotUpdateService](../stateManager/snapshotUpdate/SnapshotUpdateService.ts.md) asks for the threshold milestones alone.
8. **The builder walks its own proof once.** With every milestone snapshot stored, `buildStateProof`
   walks the proof on the local diamond with `verifyMilestonesFromTrustedStart` from the start it built
   from, and sets `finalizedSnapshot` only on a valid walk ([#L151](../../../../../../src/agreementManager/AgreementManager.ts#L151)–[#L175](../../../../../../src/agreementManager/AgreementManager.ts#L175)). A missing snapshot returns
   the evidence without a walk ([#L157](../../../../../../src/agreementManager/AgreementManager.ts#L157)). Why: the spectator payload needs the
   walked final state. Dispute auditing data does not use it: [DisputeManager](../disputeManager/DisputeManager.ts.md) reads the chain's
   walk instead, because the chain binds the posted finalized state to the snapshot its own walk ends
   at and the local start can lag it.
9. **`getMilestoneSnapshots` maps every milestone to its first block's snapshot** ([#L421](../../../../../../src/agreementManager/AgreementManager.ts#L421)–[#L427](../../../../../../src/agreementManager/AgreementManager.ts#L427)):
   the stored resulting snapshot of the milestone's first block, or `undefined` when storage lacks it,
   with no special case for the run that holds the on-chain start. The walk never reads that run's
   entry: it skips the run that holds the start and every run that ends below it. Callers set
   `startSnapshot` themselves ([#L151-L155](../../../../../../src/agreementManager/AgreementManager.ts#L151-L155), [#L183-L191](../../../../../../src/agreementManager/AgreementManager.ts#L183-L187)), and the tier-one point of
   `getThresholdFinalSnapshot` is the last milestone's first-block snapshot ([#L447](../../../../../../src/agreementManager/AgreementManager.ts#L447)).
10. **Three-tier verification; local success is final; only the chain answers invalid; every error throws.**
    `verifyStateProof` runs, in order: (1) the builder final point — the latest local threshold-final
    snapshot from `getThresholdFinalSnapshot` ([#L434](../../../../../../src/agreementManager/AgreementManager.ts#L434)–[#L447](../../../../../../src/agreementManager/AgreementManager.ts#L447)) — through the local diamond's
    `verifyMilestonesFromTrustedStart` ([#L223](../../../../../../src/agreementManager/AgreementManager.ts#L223)–[#L237](../../../../../../src/agreementManager/AgreementManager.ts#L237)); (2) the local diamond's `verifyMilestones` from
    its storage start; (3) the chain's `verifyMilestones` ([#L209](../../../../../../src/agreementManager/AgreementManager.ts#L209)–[#L222](../../../../../../src/agreementManager/AgreementManager.ts#L222), [#L239](../../../../../../src/agreementManager/AgreementManager.ts#L239)–[#L243](../../../../../../src/agreementManager/AgreementManager.ts#L243)). The first
    valid answer is returned with no age check and no chain reconfirmation ([#L245](../../../../../../src/agreementManager/AgreementManager.ts#L245)–[#L252](../../../../../../src/agreementManager/AgreementManager.ts#L252)). A not-valid
    answer, or no local threshold-final point, falls through ([#L245](../../../../../../src/agreementManager/AgreementManager.ts#L245)); a not-valid chain answer is `invalid` ([#L254](../../../../../../src/agreementManager/AgreementManager.ts#L254)–[#L255](../../../../../../src/agreementManager/AgreementManager.ts#L255)).
    There is no try/catch: an error in any tier (local EVM revert or out-of-gas, executor or worker
    failure, chain RPC failure, programming error) throws out of `verifyStateProof`, and no later tier
    runs ([#L244](../../../../../../src/agreementManager/AgreementManager.ts#L244)). A failed tier never yields an answer.
    There is no chain-only mode: a caller that needs the chain's own judgment reads the contract
    directly (block-challenge eligibility and the posted-data `verifyStateProof` in
    [DisputeValidationService](../stateManager/dispute/DisputeValidationService.ts.md), the
    auditing data's finalized state in [DisputeManager](../disputeManager/DisputeManager.ts.md)). Why: a local valid answer leads to no on-chain action, so it is safe
    while the mirror lags; an adverse answer must come from the chain ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)); an internal
    failure is fatal, so it is never hidden behind a later tier and never becomes a verdict
    ([`REQ-SP-9-7MWKY8`](../../../../specification/disputes/state-proofs.md#req-sp-9-7mwky8)).
11. **Reduction requires the applied inbound run.** `getReduceData` loads the run the chain applied
    through [EventSyncService](../stateManager/eventSync/EventSyncService.ts.md); when that run is not locally available it returns `undefined` so the caller retries;
    it never passes a non-linking run to the local reducer ([#L372](../../../../../../src/agreementManager/AgreementManager.ts#L372)–[#L390](../../../../../../src/agreementManager/AgreementManager.ts#L390)) ([`REQ-MIRROR-3-THD7K8` (Cache, never authority)](../../../../specification/enforcement/local-mirror.md#req-mirror-3-thd7k8)).

## Assumptions, dependencies, trust boundaries, and limits

- Stored blocks and their signatures were verified at ingest; `buildThresholdMilestones` and
  `getThresholdFinalSnapshot` trust them. Tier one therefore trusts a locally threshold-final point;
  the contract walk from that point still checks the submitted proof itself.
- The local diamond is a lagging mirror. Its start can be older than the chain's (the
  `mirror missed exit` case): a proof built from the genesis view stays acceptable to the chain,
  because the walk drops milestones below its start.
- `verifyStateProof` treats every non-programming error as a failed read. A local executor failure
  that is not a revert falls through to the chain instead of propagating.
- Foreign proofs reach `describeStateProof` and `verifyStateProof` untrusted; this file runs no check
  of its own on them beyond mapping milestone snapshots; the contract walk decides.
- Concurrency: one operation reads one start (`getAnchorSnapshot`); the build, its evidence and its walk
  share it. `verifyStateProof` reads a start per tier, so its tiers can walk from different starts.

## Specification adherence

- Proof construction follows the milestone, membership-change and finality-union rules; the start is
  the walk's own start predicate.
- Verification acts on a local valid answer only, takes an invalid answer only from the chain, and
  lets every read error throw, so a failed read is never an answer.
- Reduction refuses an incomplete inbound run and returns unavailable for retry.
