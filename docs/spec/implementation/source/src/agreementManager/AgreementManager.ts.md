## Responsibility and observable boundary

Owns milestone proof construction, shared trusted-start verification, retained-proof persistence and finalized replay state selection. Callers use these operations instead of implementing a separate proof walk.

## Key design decisions

Construction starts from the local diamond's chain anchor. Required membership changes use forward
minimum evidence; the latest final point is found backward from the active requested head. A later
final point stays separate when its run overlaps an earlier hop. Missing required blocks or
snapshots throw; a lost signature may instead yield lower finality with a valid tail.

`walkStateProofTiers` tries stored local finality, the local diamond and the chain. Missing/false
results advance, while thrown failures propagate. Verification does not promote the mirror.
`persistVerifiedProof` saves the walk's retained region, merging useful evidence without storing
unchecked prefixes. The walk result carries its actual non-genesis start from the same contract execution; no separate anchor read supplies persistence or replay metadata. `tryBuildFinalProofAt` proves an exact stored final height with later virtual votes, including audit evidence above the active view;
ordinary construction remains bounded by that active view. Latest final state is required; a
separate older anchor state is unnecessary unless the anchor itself is latest final.
