## Responsibility and observable boundary

The disputer role's on-chain arm: this file constructs and submits disputes and kills invalid ones.
It owns Stages 1–2 of the [dispute pipeline algorithm](../../../../specification/disputes/dispute-processing.md)
(escalation guard, construction, atomic submission) plus the kill submission of Stage 5. It does
**not** audit disputes (`DisputeValidationService`), reduce windows (`ReductionManager`/`Executor`),
or observe chain events (`EventHandler`) — those callers drive it.

Public surface: [`dispute(forkId)`](../../../../../../src/disputeManager/DisputeManager.ts#L87)
(escalate a fork, idempotent per fork),
[`killDispute(dispute)`](../../../../../../src/disputeManager/DisputeManager.ts#L213) (submit the
stored dispute fraud proof during the kill period),
[`constructDispute(forkId)`](../../../../../../src/disputeManager/DisputeManager.ts#L292) (build
the complete `Dispute` + confirmation + auditing data + proofs-to-apply; also used by the auditor's
evidence-improvement comparison),
[`getAuditingData(forkId, stateProof, options?)`](../../../../../../src/disputeManager/DisputeManager.ts#L496)
(assemble the audit payload, reporting `isPartial` when local data cannot back it), and the
`setChannelId`/`setP2pEventHooks` wiring setters.

## Key design decisions

1. **Once-per-fork guard with rollback, under a local mutex.** `dispute()` serializes on the
   instance mutex and consults the `didIDispute` flag; the flag is set _before_ awaiting the
   transaction and rolled back on any submission failure, so a raced or reverted upload releases
   the guard for retry ([#L93](../../../../../../src/disputeManager/DisputeManager.ts#L93),
   [#L208](../../../../../../src/disputeManager/DisputeManager.ts#L208)). The mutex bounds
   concurrent local escalations; the _contract's_ throttle and one-post-per-window rules remain the
   authority.
2. **Fraud proofs ride in front of the upload, atomically.** Held proofs for unslashed participants
   are applied and the dispute uploaded in one batched call
   ([#L141](../../../../../../src/disputeManager/DisputeManager.ts#L141)), so the dispute's
   claimed `onChainSlashes` are a subset of the on-chain set at execution — the mechanism that keeps
   fraud enforcement separate from reduction.
3. **The dispute pre-commits to its own outcome via the mirror.** The successor-fork genesis is
   computed by the mirrored canonical logic
   (`computeDisputeOutputSnapshotData.staticCall`,
   [#L426](../../../../../../src/disputeManager/DisputeManager.ts#L426)) and its hash embedded as
   `outputSnapshotDataHash` — never a client-side reimplementation
   ([`INV-MIRROR-1-VAF778`](../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778)).
4. **Data-availability decision by finality probe.** Auditing calldata is posted iff the proof's
   last milestone is not provably final to everyone (`isLastMilestoneFinalByEveryone.staticCall`,
   [#L457](../../../../../../src/disputeManager/DisputeManager.ts#L457)); a known-final anchor
   spares the calldata cost.
5. **Construction aborts on partial data.** `getAuditingData` flags any locally unbackable element
   (`isPartial`) and `constructDispute` throws rather than submitting a dispute the node cannot
   stand behind ([#L394](../../../../../../src/disputeManager/DisputeManager.ts#L394)).
6. **Kill runs without the mutex, on a single-audit invariant.** `killDispute` relies on the audit
   producing exactly one dispute fraud proof per dispute exactly once (pipeline [`INV-DVP-3-ZMF1HA`](../../../views/architecture/sdk/dispute-pipeline.md#inv-dvp-3-zmf1ha)), so no
   local serialization is needed; it re-reads the kill window immediately before submitting and
   treats the four named race reverts as benign convergence
   ([#L227](../../../../../../src/disputeManager/DisputeManager.ts#L227)).
7. **Local slash subset is deliberately sufficient.** Construction reads the mirror's slash set
   without a chain round trip; `DisputeKilled` handling eagerly records the implicated disputer,
   and a full redundant-RPC sync pass is explicitly deferred hardening
   ([#L334](../../../../../../src/disputeManager/DisputeManager.ts#L334)).
8. **Right-sized gas ceiling.** The plain upload pins a 2.5M gas limit — measured ~0.5M in e2e,
   sized down from 5M to free block gas under concurrency while keeping headroom
   ([#L47](../../../../../../src/disputeManager/DisputeManager.ts#L47)).

## Assumptions, dependencies, trust boundaries, and limits

- **Callers are trusted local components** (event handler, state manager, reduction executor); no
  remote input reaches this file directly. Its outputs, however, become adversarial input to the
  chain — everything it submits is re-verified on-chain.
- **Storage-backed construction:** correctness of a constructed dispute presumes the storage
  modules' fidelity ([`REQ-IX-9-AV56NR`](../../../../specification/storage/README.md#req-ix-9-av56nr)) and the
  agreement manager's proof assembly; a state-hash mismatch between snapshot and stored state is
  treated as a fatal race ([#L358](../../../../../../src/disputeManager/DisputeManager.ts#L358)).
- **Mirror freshness:** slash-subset and finality probes read the mirror; staleness is bounded by
  the decisions above (eager kill recording; on-chain re-checks by the contract itself). Wrong-kill
  safety does not rest here — the auditor preflights proof validity before storing.
- **Ordering/concurrency:** `dispute()` is mutex-serialized per instance; `killDispute` is
  intentionally unserialized (decision 6). Transaction nonce/fee management is the signer's.
- **Limits:** one dispute per fork per instance lifetime (until rollback); 2.5M gas ceiling on the
  plain upload; auditing-data size bounded by the stream ranges between genesis, latest, and
  finalized snapshots.

## Specification adherence

- All four dispute inputs assembled per [`REQ-DIS-1-XAJ1VA`](../../../../specification/disputes/disputes.md#req-dis-1-xaj1va);
  slash listing intersected with participants so only members are claimed.
- Proofs-before-upload batching implements the enforcement/reduction separation
  ([fraud-proofs.md](../../../../specification/disputes/fraud-proofs.md)).
- Pre-committed outcome and finality probe evaluated through mirrored canonical logic only —
  no client-side predicate reimplementation found in this file.
- Kill preconditions (stored proof required, fresh window read, race reverts as no-ops) match
  Stage 5 of [dispute-processing.md](../../../../specification/disputes/dispute-processing.md).
- Escalation guard semantics (once per fork, rollback on failure) match Stage 1.

  pipeline's future work.
- **Full on-chain slash-set sync** — deferred hardening per decision 7; acceptable while the
  mirror's eager recording holds.
- **Dispute domain model** — construction manipulates raw structs (code TODO); refactoring debt,
  no behavioral gap.
