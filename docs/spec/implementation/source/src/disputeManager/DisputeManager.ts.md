## Responsibility and observable boundary

The disputer role's on-chain arm: this file constructs and submits disputes and kills invalid ones.
It owns Stages 1–2 of the [dispute pipeline algorithm](../../../../specification/disputes/dispute-processing.md)
(escalation guard, construction, submission with a best-effort upload) plus the kill submission of Stage 5. It does
**not** audit disputes (`DisputeValidationService`), reduce windows (`ReductionManager`/`Executor`),
or observe chain events (`EventHandler`) — those callers drive it.

Public surface: [`dispute(forkId)`](../../../../../../src/disputeManager/DisputeManager.ts#L115)
(escalate a fork, idempotent per fork),
[`killDispute(dispute)`](../../../../../../src/disputeManager/DisputeManager.ts#L606) (submit the
stored dispute fraud proof during the kill period),
[`constructDispute(forkId)`](../../../../../../src/disputeManager/DisputeManager.ts#L711) (build
the complete `Dispute` + confirmation + auditing data + proofs-to-apply; also used by the auditor's
evidence comparison; its private helper
[`buildAuditingData`](../../../../../../src/disputeManager/DisputeManager.ts#L958) assembles the
audit payload and throws on missing local data),
[`shouldAddOwnEvidence(forkId, dispute)`](../../../../../../src/disputeManager/DisputeManager.ts#L535) and
[`forgetEvidenceComparison(forkId)`](../../../../../../src/disputeManager/DisputeManager.ts#L602) (the auditor's once-per-fork evidence comparison,
called by `EventHandler`), and the `setChannelId`/`setP2pEventHooks` wiring setters.

## Key design decisions

Admission checks the live fork under the state mutex before construction and marker assignment. Detached requests use the shared observer; an early refusal carrying a zero-address timeout schedules no participant retry. See [DisputeManager.ts](../../../../../../src/disputeManager/DisputeManager.ts#L149).

Unhandled upload and kill failures, including unhandled custom errors, are logged and rethrown.
Only the explicit handler table consumes known races; a failed upload also clears its local marker.
See [upload catch](../../../../../../src/disputeManager/DisputeManager.ts#L261) and
[kill catch](../../../../../../src/disputeManager/DisputeManager.ts#L648).

Error text delegates to the dependency-free errorMessage helper. Existing catch policy, stack fields, log messages and error propagation remain at this call site. See [DisputeManager.ts](../../../../../../src/disputeManager/DisputeManager.ts#L29).

1. **Once-per-fork guard with rollback, under a local mutex.** `dispute()` serializes on the
   instance mutex and consults the `didIDispute` flag; the flag is set _before_ awaiting the
   transaction and rolled back on any submission failure, so a raced or reverted upload releases
   the guard for retry ([#L137](../../../../../../src/disputeManager/DisputeManager.ts#L137),
   [#L350](../../../../../../src/disputeManager/DisputeManager.ts#L350)). The mutex bounds
   concurrent local escalations; the _contract's_ throttle and one-post-per-window rules remain the
   authority.
2. **Fraud proofs ride in front of the upload, in one transaction.** Held proofs for unslashed participants
   are applied and the dispute uploaded in one batched call
   ([#L230](../../../../../../src/disputeManager/DisputeManager.ts#L230)), so the dispute's
   claimed `onChainSlashes` are a subset of the on-chain set at execution — the mechanism that keeps
   fraud enforcement separate from reduction.
3. **The dispute pre-commits to its own outcome via the mirror.** The successor-fork genesis is
   computed by the mirrored canonical logic
   (`computeDisputeOutputSnapshotData.staticCall`,
   [#L870](../../../../../../src/disputeManager/DisputeManager.ts#L870)) and its hash embedded as
   `outputSnapshotDataHash` — never a client-side reimplementation
   ([`INV-MIRROR-1-VAF778` (Single implementation)](../../../../specification/enforcement/local-mirror.md#inv-mirror-1-vaf778)).
4. **Data-availability decision by finality probe, local first.** Auditing calldata is posted
   unless the proof is empty genesis, the last milestone contains the matching chain anchor, or its required everyone set proves finality (`isAuditingDataOmissionAllowed.staticCall`,
   [#L904-L914](../../../../../../src/disputeManager/DisputeManager.ts#L904-L914)); a known-final anchor spares the calldata cost. The probe runs
   through `preferLocal` on the local diamond: a local "not final" posts the data without asking
   the chain, because posting is never wrong, only costlier; a local "final" omits the data, which
   is slashable if the lagging mirror was wrong, so the chain confirms that answer and decides
   ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys)). The on-chain predicate judges the chain snapshot set, which cannot move
   while a proof can land (adoption targets only the latest undisputed fork, a disputed fork advances only by
   reduction), plus the joiners at or below the dispute's anchor, minus the dispute's own `onChainSlashes`, so
   this construction-time probe and a later fraud-proof read of the committed dispute agree.
5. **Construction throws on missing local data.** `constructDispute` throws on a missing latest
   snapshot or state ([#L760-L774](../../../../../../src/disputeManager/DisputeManager.ts#L760-L774)),
   and `buildAuditingData` throws on a missing finalized state or inbound run
   ([#L968-L983](../../../../../../src/disputeManager/DisputeManager.ts#L968-L983)): this peer holds
   what it signed. No partial dispute is submitted.
6. **Kill runs without the mutex, on a single-audit invariant.** `killDispute` relies on the audit
   producing exactly one dispute fraud proof per dispute exactly once (pipeline [`INV-DVP-3-ZMF1HA`](../../../views/architecture/sdk/dispute-pipeline.md#inv-dvp-3-zmf1ha)), so no
   local serialization is needed; it re-reads the kill window immediately before submitting and
   treats three named race reverts as benign convergence and a late kill
   (`RaceConditionDisputeKillPeriodExpired`) as fatal
   ([#L613-L624](../../../../../../src/disputeManager/DisputeManager.ts#L613-L624), [#L654-L681](../../../../../../src/disputeManager/DisputeManager.ts#L654-L681)).
7. **Construction consumes the observed slash subset; a conditional refusal refreshes it.**
   The construction result records that observation. After `RaceConditionDisputeWindowNotOpen`,
   marker rollback and mutex release precede authoritative event recovery. Normal construction runs
   again only if the chain set changed since construction, including a slash already delivered in
   the meantime. A slash is not automatically a valid reason.
8. **Gas from the chain signer; replays funded upfront.** The plain upload and the calldata upload
   pass no gas limit; the chain signer sends each with its estimate plus
   [`withGasHeadroom`](../../utils/gas.ts.md). Honest peers race to dispute the same fraud, and a late
   disputer's upload costs more for every disputer already in the window
   (`_hadParticipantPostedEvidence` reads the whole `hasPosted` list). A dispute landing between
   estimate and inclusion would leave a bare estimate short; the out-of-gas revert surfaces only as
   the proxy's "Delegatecall failed", and the retry can land at `evidencePeriodEnd`, refusing an
   honest disputer's evidence.
9. **StateManager orders admitted signing before the single dispute marker.**
   Dispute admission waits for the state mutex, sets the marker after admitted signatures and storage
   complete, then releases that mutex before construction and network submission. Callers already
   inside the state mutex use observed detached requests. Failed uploads roll back the marker;
   later same-fork block work is allowed again. No second closed-fork set or post-signature check is used.
10. **An advancing inbound head is recovered before retry.** `RaceConditionDisputeInboundNotLatest`
    causes the manager to load the run through the reported canonical head, rebuild and submit again.
    There is no fixed retry cap. An unchanged head on another refusal, a head equal to the construction
    anchor, or a failed load is fatal. A kill attached to the refused upload can land separately;
    the replacement then uses the refreshed slash context without sending the same kill again.
11. **A transaction that replays a transition is funded for the replay upfront.** The state
    machine refuses to run a transition it cannot grant its full budget
    ([AStateMachine](../../contracts/V1/AStateMachine.sol.md)), and the manager turns that refusal
    into a failed call, not a verdict. The two sends that can replay a transition — the fraud-proof
    `multicallBestEffortLast` in front of an upload ([#L220-L233](../../../../../../src/disputeManager/DisputeManager.ts#L220-L233)) and `applyDisputeFraudProofs` in
    `killDispute` ([#L632-L642](../../../../../../src/disputeManager/DisputeManager.ts#L632-L642)) — pass `gasLimit = replayGasLimit(estimate)`: the
    signer's estimate (the chain signer's `estimateGas` already adds
    [`withGasHeadroom`](../../utils/gas.ts.md)) plus `getStateTransitionReplayGas()`
    ([#L452-L466](../../../../../../src/disputeManager/DisputeManager.ts#L452-L466)). The refusal checks that the full budget is free when the replay
    starts. An estimator that reports the gas spent (the peer3 hardhat fork the poker consumer runs
    executes the transaction once and adds 30%) counts only what the transition used, never the
    unused budget that must be free, and the work before the replay (proof checks, setting the
    machine's state, deleting the previous transition's outbound messages) can exceed any fixed margin over the requirement. On a poker dispute that work
    was about 3.9M gas with a 5.64M requirement, so about 9.5M was needed, while the larger of
    the estimate and the requirement plus a 30% margin gives only 8.89M. The sum
    covers both parts. A
    searching estimator (geth, anvil, and the SDK's own test node, hardhat 2.22 with EDR) looks for
    the lowest gas at which the whole transaction succeeds; the refusal makes every lower gas fail,
    so its estimate already contains the requirement and the sum declares more than needed (at
    least about 2.5 × the requirement). That changes no verdict but is not free: it reserves block
    space and must fit the block gas limit (limits section). Engineer decision (Luka, review 5 FO1):
    keep the sum; the whole gas and estimation topic is open as [`FIND-GASEST-2-94YFZ6`](../../../../audit/open-findings.md#find-gasest-2-94yfz6). Both estimates are taken through `getFunction`, the contract's own method. The replay gas
    is read once and kept as a promise, so concurrent sends share one read; a failed read is dropped
    and the next send reads again ([#L453-L463](../../../../../../src/disputeManager/DisputeManager.ts#L453-L463)). No other send passes a gas limit
    ([`REQ-ENFSM-1-DKJCY2` (Injected context, bounded gas)](../../../../specification/enforcement/execution-and-consumer.md#req-enfsm-1-dkjcy2)).
12. **The auditor's evidence comparison is dispute policy and lives here.** After a valid audit of
    another participant's dispute, `EventHandler` asks `shouldAddOwnEvidence(forkId, dispute)`
    ([#L535-L556](../../../../../../src/disputeManager/DisputeManager.ts#L535-L556)) whether this node should add its own dispute to the window. A
    node that already disputed the fork (`storage.disputes.didIDispute`) has committed its
    evidence: that check runs first and nothing is compared ([#L539](../../../../../../src/disputeManager/DisputeManager.ts#L539)). Otherwise
    `canConstructMoreEvidence` builds this node's own dispute with `constructDispute` and compares
    `reduce([theirs])` with `reduce([ours, theirs])` on the local diamond ([#L559-L596](../../../../../../src/disputeManager/DisputeManager.ts#L559-L596)).
    The comparison runs once per disputed fork and its promise is kept in `evidenceChecks`
    ([#L68](../../../../../../src/disputeManager/DisputeManager.ts#L68), [#L553](../../../../../../src/disputeManager/DisputeManager.ts#L553)): reduction merges evidence monotonically, so a dispute of
    ours that adds nothing to the first audited dispute adds nothing once more disputes land.
    Concurrent audits share the in-flight promise. A rejected comparison is removed and the
    error propagates to that audit. Missing required own auditing data is fatal and is never
    converted into a `false` no-evidence answer. Removal checks
    promise identity, so a comparison that settles after it was dropped cannot erase its
    replacement. A positive answer stays, so a failed upload is retried by the next audit.
    `forgetEvidenceComparison(forkId)` ([#L602-L604](../../../../../../src/disputeManager/DisputeManager.ts#L602-L604)) drops the kept answer; `EventHandler`
    calls it on a kill (the compared dispute may be gone) and when the fork's reduced result is
    committed (memory pruning only). The comparison gates only joining another participant's
    dispute: new own evidence (fraud, timeout, leave) is disputed through its own paths
    ([`REQ-DISPUTE-PIPE-6-6FZB9M` (Minimal intervention and convergence)](../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-6-6fzb9m)).
13. **Only slashes of the latest state's participants are listed.** Construction collects the
    observed chain slashes, the slash a same-transaction kill lands first (`expectedSlashes`) and the
    slashes of its own held fraud proofs, then lists only those of participants of the dispute's
    latest state snapshot ([#L800](../../../../../../src/disputeManager/DisputeManager.ts#L800), [`REQ-DIS-11-WQK8P2`](../../../../specification/disputes/disputes.md#req-dis-11-wqk8p2)). The chain slash set
    keeps slashes of participants an ancestor fork removed, and the killed submitter of an older
    dispute may have left the fork; listing either would make this peer's own dispute provably
    invalid (`InvalidDisputeReason`). Fraud proofs still ride for every participant of the latest
    block's snapshots, so an offender is slashed even when it is not listed.
14. **In a multicall the upload is best effort; a lost evidence race is a no-op.** A kill or
    fraud proofs go out with the upload through the proxy's `multicallBestEffortLast`
    ([#L220-L233](../../../../../../src/disputeManager/DisputeManager.ts#L220-L233)): they must succeed, the upload is sent last and may be refused
    without taking them down. After mining, the async `lastCallRefusal`
    ([#L504-L522](../../../../../../src/disputeManager/DisputeManager.ts#L504-L522)) reads the
    last call's revert data through the shared decoder `multicallLastCallRevertData`
    ([evmErrorHandler](../utils/evmErrorHandler.ts.md)) and decodes it with `tryDecodeCustomError`.
    A reasonless refusal (bare `0x`, or the proxy's `Delegatecall failed` `Error(string)` for a facet
    that reverted without data, `isReasonlessRevert`) means the upload ran out of the gas the
    best-effort estimate left it: it is classified as the refusal the all-or-nothing estimate
    decoded, and without one it is a fatal `Error`. A refusal is thrown into the same catch and handler table as a
    refused lone upload ([#L254-L260](../../../../../../src/disputeManager/DisputeManager.ts#L254-L260)), so every error keeps today's policy; only the
    `tx` is withheld, because resending the mined multicall would repeat its kill. The kill already
    landed, so `killLanded` is set before the refusal is read and the `finally` sends no second kill
    ([#L355-L356](../../../../../../src/disputeManager/DisputeManager.ts#L355-L356)). Gas: the all-or-nothing `multicall` estimate funds the upload too;
    only when it reverts (the upload already fails) is the best-effort call estimated
    (`estimateBestEffortMulticall`, [#L478-L494](../../../../../../src/disputeManager/DisputeManager.ts#L478-L494)); it returns `{ gas, refusal? }`, where
    `refusal` is the decoded custom error of the failed all-or-nothing estimate. A searching estimator looks for the
    least gas at which a call succeeds, and the best-effort call succeeds even when its upload runs
    out of gas, so estimating it first could fund the kill alone. An upload refused with
    `RaceConditionDisputeEvidencePeriodExpired` lost the evidence race: with or without a kill in
    front of it, the handler logs it and returns without rethrowing, and the marker rolls back
    ([#L323-L335](../../../../../../src/disputeManager/DisputeManager.ts#L323-L335); TODO for
    [`OQ-SPEC-EVIDENCE-RACE-1-TKNWBJ` (Interpreting a lost evidence race)](../../../../specification/open-questions.md#oq-spec-evidence-race-1-tknwbj)). `dispute` resolves with the refusal
    as `lostEvidenceRace` of its inline return type
    ([#L118](../../../../../../src/disputeManager/DisputeManager.ts#L118)) and calls no other component: leave policy stays with the
    leave. `MembershipService.startSelfRemovalDispute` throws it; the exit fallback
    (`onExitFallbackFailed`) then settles the leave and the leave's own dispute fallback
    (`startDisputeFallback`, block bound or watchdog) fails it
    ([MembershipService](../stateManager/membership/MembershipService.ts.md)). Every other caller ignores the result. `EventHandler` therefore calls `dispute`
    directly; it has no race wrapper. The former
    pre-construction window read that skipped a queued replacement after the evidence end is gone:
    the refused upload is the same no-op, so the read was redundant. `killDispute` logs its kill
    period end with the time left by `Clock` ([#L625-L630](../../../../../../src/disputeManager/DisputeManager.ts#L625-L630)).
15. **The auditing data's outbound run starts at the chain's snapshot.** `buildAuditingData`
    reads the on-chain snapshot from the chain contract, not the local mirror, and carries the
    outbound blocks above its outbound head up to the latest state's
    ([#L987-L1001](../../../../../../src/disputeManager/DisputeManager.ts#L987-L1001)). Cut at the chain's anchor of judgment time the run must
    link that anchor's outbound head to the latest state's, else `DisputeInvalidOutboundRun` kills
    the dispute; auditors verify it and persist the verified part so a later snapshot post, which prunes against the on-chain snapshot of its own time,
    has the blocks above that anchor. The anchor only moves forward, so a run built at construction
    keeps covering every later post. Across forks the run passes the fork genesis, which carries the
    outbound head of the state it was reduced from. An on-chain head at or above the latest state's
    leaves an empty run; a lower on-chain head that is not an ancestor of the latest head throws
    (local history that contradicts the chain's final state is an internal failure).

The posted-calldata handler implements [`REQ-DISPUTE-PIPE-11-HRGJ43` (Release a timeout refused for posted calldata)](../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-11-hrgj43): inside the handler, still holding the dispute mutex, drop the stored candidate by identity so a waiter behind the mutex rebuilds without it; after the marker is released, read the posted block for that slot from the local calldata store and ingest it once. Every other failed submission hands back the stored posted block for the fork's next slot the same way ([DisputeManager.ts L373-L394](../../../../../../src/disputeManager/DisputeManager.ts#L373-L394)), read under the state mutex; only the posted-calldata refusal drops a candidate. Nothing is re-armed and nothing is resent — the pipeline's verdict on that block decides what follows. The early-chain-timestamp handler implements [`REQ-DISPUTE-PIPE-10-BT8YAR` (Recheck an early timeout submission)](../../../../specification/disputes/dispute-processing.md#req-dispute-pipe-10-bt8yar): retain the submitted timeout slot, derive the retry delay from the decoded error, roll back the marker, release the mutex, then call ParticipantTimeoutService.scheduleCheck. WindowCreatedTooEarly remains a no-op and unrelated errors keep their existing policy apart from that hand-back.

awaited calls retain the original rejection; expected refusals still use normal recovery first.

## Assumptions, dependencies, trust boundaries, and limits

- **Callers are trusted local components** (event handler, state manager, reduction executor); no
  remote input reaches this file directly. Its outputs, however, become adversarial input to the
  chain — everything it submits is re-verified on-chain.
- **Storage-backed construction:** correctness of a constructed dispute presumes the storage
  modules' fidelity ([`REQ-IX-9-AV56NR` (Storage fidelity)](../../../../specification/interactions.md#req-ix-9-av56nr)) and the
  agreement manager's proof assembly; a state-hash mismatch between snapshot and stored state is
  treated as a fatal race ([#L777-L784](../../../../../../src/disputeManager/DisputeManager.ts#L777-L784)).
- **Mirror freshness:** slash-subset and finality probes read the mirror; staleness is bounded by
  the decisions above (eager kill recording; on-chain re-checks by the contract itself). Wrong-kill
  safety does not rest here — the auditor preflights proof validity before storing.
- **Ordering/concurrency:** `dispute()` is mutex-serialized per instance; `killDispute` is
  intentionally unserialized (decision 6). Transaction nonce, fee and gas management is the
  signer's (estimate plus headroom, decision 8); replay sends take that estimate plus the manager's
  replay gas (decision 11). The evidence memo is shared by concurrent audits
  and changed only by promise-identity checks (decision 12).
- **Residual (block gas limit):** nothing caps the replay send's gas limit at the block gas
  limit. The limit is the estimate with the signer's 50% headroom plus the replay requirement. With
  a searching estimator the estimate already contains the requirement, so the limit is at least
  2.5 × the requirement; with poker's budgets it still fits a 30M block, but a consumer whose
  transition budget exceeds roughly 9M does not fit. A send above the block gas limit fails at
  submission, never with a wrong verdict; the fraud then stays unproven on-chain. No send test
  against a searching 30M-block node exists. Open as [`FIND-GASEST-2-94YFZ6`](../../../../audit/open-findings.md#find-gasest-2-94yfz6).
- **Residual (evidence memo):** a fork that never gets a reduced-result event keeps its memo entry
  for the runtime's life (one promise per such fork). The once-per-fork answer relies on reduction
  merging evidence monotonically; a reducer change that broke monotonicity would make a later
  dispute's comparison differ from the first one's.
- **Limits:** one dispute per fork per instance lifetime (until rollback); auditing-data size bounded
  by the stream ranges between genesis, latest, and finalized snapshots.
- **Empty-timeout sentinel:** the empty timeout it submits (zero height, zero participant) is the
  input shape behind the empty-timeout reduction cancellation of
  [disputes.md §5](../../../../specification/disputes/disputes.md): intended slash precedence for
  slash-carrying disputes, but a confirmed defect in the slash-free case — resolved 2026-08-14,
  [`OQ-9-XR1MFS` (Timeout precedence edge rules)](../../../../specification/open-questions.md#oq-9-xr1mfs); the fold fix is tracked in
  [`OQ-14-5C8KV7` (Empty-timeout fold can suppress a real timeout)](../../../open-questions.md#oq-14-5c8kv7). This file follows the
  current struct contract; the behavior is owned by the reduction fold, not construction.
