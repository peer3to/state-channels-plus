# RpcContractExecutor.ts — Source Report

> **Source:** [src/evm/contractExecutor/RpcContractExecutor.ts](../../../../../../../src/evm/contractExecutor/RpcContractExecutor.ts) > **Status:** Authored — engineer verification pending.
> **Design views:** [Runtime and concurrency](../../../../views/architecture/sdk/runtime-and-concurrency.md)

## Responsibility and observable boundary

Adapts the AContractExecutor consumer interface to the typed executor connection. It normalizes bytes and addresses, forwards requests and delegates disposal to its remote root handle. It has no worker flag, fatal-failure state, callback registry or worker creation.

## Key design decisions

The receiving ContractExecutorRoot controls the engine. Connection failure and cleanup belong to common root services. Existing consumers keep their AContractExecutor method signatures.

## Inputs, outputs, state, and side effects

Stores one ContractExecutorRemoteRoot handle. Calls return the shared router's request promises. Handle disposal uses the same recursive root contract in both placements.

## Assumptions, dependencies, trust boundaries, and limits

Production construction requires the SDK endpoint. Detached reports go through the common error service and its report-and-continue route. Disposing the remote root retires the executor connection in both placements. Domain abort does not transfer ownership of that root to the state manager. This facade does not infer lifecycle policy from the shared router.
