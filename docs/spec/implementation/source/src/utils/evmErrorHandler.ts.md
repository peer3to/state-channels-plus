## Responsibility and observable boundary

Custom-error decoding and the named-handler race classifier (`tryHandleEvmError`,
`tryDecodeCustomError`): maps contract reverts to the client's convergence/no-op/rethrow
decisions. It also owns the local-revert marker: `LOCAL_EVM_EXECUTION_FAILED`, the text the local
executor puts in every revert it reports ([#L85](../../../../../../src/utils/evmErrorHandler.ts#L85)). `isInvalidStateTransitionError(error)`
([#L116](../../../../../../src/utils/evmErrorHandler.ts#L116)) is the one rule for when a failed local `stateTransition` is a verdict on the transaction.

## Key design decisions

The race-error union includes `RaceConditionDisputeWindowNotOpen`. Generic ABI decoding dispatches that exact name; DisputeManager owns rollback, slash recovery, and normal re-entry. Other custom errors keep their existing handlers.

`ContractErrorName` is the union of the names in `GeneratedArtifacts.errorAbis`, emitted `as const`, plus ethers' built-in `Error` and `Panic` ([#L8](../../../../../../src/utils/evmErrorHandler.ts#L9)). `CustomEvmError.name` carries that type, so comparing a decoded name with a name no contract declares fails type checking. `RaceConditionErrorName` is extracted from it (every `RaceCondition*` name plus four dispute `Error*` names) and keys the handler map, so a stale handler key fails the same way. It includes `RaceConditionSnapshotUpdateDisputedFork`, handled by SnapshotUpdateService and ReductionExecutor and compared by SpectateService.

`GeneratedArtifacts.errorAbis` is the single reachable-manager error union. It includes the
`StateProofFacet` and `UtilityFacet` ECDSA errors used by both the decoder and canonical binding.

1. **Errors-as-protocol-signals:** race classification keys on custom-error names from [Errors.sol](../../contracts/V1/StateChannelDiamondProxy/Errors.sol.md) — the client/contract error vocabulary is one contract.
2. **The union mirrors only constructible errors:** a name the contracts no longer declare is
   removed from `RaceConditionErrorName` in the same change, so a handler map can never name a
   revert that cannot happen. A retired name's planned permutation is retired with it, not
   renumbered or reused.
3. **The unhandled-error log delegates its metadata to `LoggerUtils`.** When no handler matches
   the decoded name, the log line carries
   `LoggerUtils.getCustomEvmErrorMetadata(customError)`
   ([#L176](../../../../../../src/utils/evmErrorHandler.ts#L170)) rather than a hand-built
   `{name, args}` object. This is the sink every argument-carrying error without a handler lands
   in, and an ethers `Result` serializes positionally, so the hand-built object logged the
   operands as a bare array; the shared helper converts them to the ABI's own field names.
4. **One constant names a local revert on both sides.** [ContractExecutor](../evm/contractExecutor/ContractExecutor.ts.md)
   builds its revert message from `LOCAL_EVM_EXECUTION_FAILED` ([#L85](../../../../../../src/utils/evmErrorHandler.ts#L85)), and
   `localEvmFailureReason` finds that text anywhere in the message ([#L99](../../../../../../src/utils/evmErrorHandler.ts#L99)), because the
   local signer and the executor's RPC boundary wrap the executor's error in their own messages but
   keep its text. `isLocalEvmExecutionFailure` ([#L88](../../../../../../src/utils/evmErrorHandler.ts#L88)) answers whether an error carries
   that text. Its only user is the sync requester, which judges a peer's dispute window whose local
   reduction reverts as peer data ([SpectateService](../rpc/network/services/spectate/SpectateService.ts.md)).
   No local-first read classifies a local failure: a local revert, like every other
   local failure, propagates ([`REQ-MIRROR-4-H9C4YS` (Local-first evaluation, adverse answer confirmed)](../../../../specification/enforcement/local-mirror.md#req-mirror-4-h9c4ys),
   owned by [localDiamond](localDiamond.ts.md)'s `preferLocal`).
5. **Only a failure inside the EVM within the full budget is an invalid state transition.**
   `isInvalidStateTransitionError` ([#L116](../../../../../../src/utils/evmErrorHandler.ts#L116)) reads the reason the executor puts after
   `LOCAL_EVM_EXECUTION_FAILED` (`localEvmFailureReason`, [#L99](../../../../../../src/utils/evmErrorHandler.ts#L99)) and answers `true`
   only for a local EVM failure whose reason is neither `ErrorInsufficientGasForStateTransition`
   (the machine refused to run because the call could not grant the full budget) nor `out of gas`
   (the call's own frame ran out before or after the transition). A failure without the marker is
   an executor or transport failure and is not invalid either. Only an invalid state transition may
   become a fraud proof; the caller ([EvmDiamondStateMachine](../evm/EvmDiamondStateMachine.ts.md))
   rethrows everything else as a local failure
   ([`REQ-ENFSM-1-DKJCY2` (Injected context, bounded gas)](../../../../specification/enforcement/execution-and-consumer.md#req-enfsm-1-dkjcy2)).
   A transition that runs out of gas inside its own budget makes the funded machine frame revert
   with its own reason (`AStateMachine - Call failed - result length 0`), not with a bare `out of
gas` of the call, so it stays a verdict.

## Assumptions, dependencies, trust boundaries, and limits

- Utility semantics must hold identically on both supported hosts.
- `isInvalidStateTransitionError` classifies by message text. A wrapper that dropped the
  executor's text would make a real invalid transition a local failure — fail-safe, since no fraud
  proof is built and other peers still judge the block — and a reason text other than the two
  named ones is treated as a verdict.
