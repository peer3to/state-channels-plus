## System design

- Several dispute-validity checks remain implicit rather than owning dedicated fraud-proof types,
  including genesis-fork linking, proof linking (`isStateProofLinked`), and latest-state checks
  inside `DisputeInvalidStateProof`. Their ownership
  and failure paths require an implementation audit.
- An invalid-state-transition proof is judged only on a replay granted the full transition
  budget. The state machine refuses to run a transition it cannot fund in full
  (`ErrorInsufficientGasForStateTransition`), and the manager re-raises that refusal, or turns a
  starved machine frame into `ErrorStateTransitionFrameOutOfGas`, so the whole call fails with no
  slash; the gas a submitter attaches never decides the verdict
  ([AStateMachine](../../source/contracts/V1/AStateMachine.sol.md),
  [StateChannelManagerProxy](../../source/contracts/V1/StateChannelDiamondProxy/StateChannelManagerProxy.sol.md)).
  Honest senders fund the replay upfront: the SDK sends every fraud-proof `multicall` and
  `applyDisputeFraudProofs` with its estimate (with the signer's headroom) plus the manager's
  `getStateTransitionReplayGas()`
  ([UtilityFacet](../../source/contracts/V1/StateChannelDiamondProxy/UtilityFacet.sol.md),
  [DisputeManager](../../source/src/disputeManager/DisputeManager.ts.md)). An estimator that reports
  only the gas spent misses the unused budget that must be free when the replay starts and the work
  before the replay; the added requirement covers both. A searching estimator already includes the
  requirement, so there the limit declares more than needed (at least about 2.5 × the
  requirement); that changes no verdict but reserves block space. Residual: nothing caps that limit
  at the block gas limit, so a replay whose declared limit is too large for a block cannot be sent
  on that chain (the send fails; no wrong verdict), and block fit depends on the consumer's budgets
  ([`FIND-GASEST-2-94YFZ6`](../../../audit/open-findings.md#find-gasest-2-94yfz6)).
- `BlockInvalidStateTransition` and `InvalidTimestamp` carry the invalid block's predecessor: the
  block it extends (an empty block for the fork genesis), that block's resulting snapshot, and for
  the transition proof that snapshot's state. The SDK builder
  ([FraudProofService](../../source/src/stateManager/utils/FraudProofService.ts.md)) takes the
  predecessor that the dispute replay passes: the previous block of the dispute's own chain, also
  when the auditor's stored history holds another block at that height. Live gossip passes none;
  the builder then reads the block the invalid block names by `previousBlockHash` by hash, and when
  storage lacks it, its snapshot or its state, it builds no transition proof (peer input must not
  crash a node). The dispute replay never lacks one: an honest auditor never abstains, and
  [DisputeValidationStrategy](../../source/src/stateManager/validationStrategy/DisputeValidationStrategy.ts.md)
  throws if a builder returns no proof
  ([`REQ-DISPUTE-PIPE-5-RZZB48` (Mirrored canonical audit)](../../../specification/disputes/dispute-processing.md#req-dispute-pipe-5-rzzb48)).
  `DisputeBlockAuthorNotParticipant` takes its previous block and snapshot from the same
  predecessor ([DisputeFraudProofService](../../source/src/stateManager/dispute/DisputeFraudProofService.ts.md)).
- Block-pointing dispute wrappers address a block by `blockIndex` in the last milestone of the
  submitted proof ([DisputeFraudProofTypes](../../source/contracts/V1/types/DisputeFraudProofTypes.sol.md)); there is
  no `milestoneIndex`, so an earlier milestone cannot be addressed.
  `DisputeInvalidBlockInStateProofApplyFraudProof` and `DisputeBlockAuthorNotParticipant` carry no
  walk evidence. The facet does not walk:
  [`_isBlockChallengeEligible`](../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L799)
  delegatecalls
  [`StateProofFacet.isBlockChallengeEligible`](../../../../../contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol#L114).
  The block is eligible when the proof has a milestone, `blockIndex` is in the last milestone, that
  milestone's first block and the challenged block decode, `blockIndex >= tailStart`, and, when the
  anchor is usable, the challenged block height is above the anchor height. `tailStart` is
  `anchor height - first height + 1` when the anchor is usable and the last milestone's first height
  is at or below it; 0 when there is one milestone whose first height is 0 (anchor not usable);
  else 1. Finalized history stays with its original signers. One milestone that starts at genesis
  block 0 makes block 0 challengeable even when it is threshold-final.
  `DisputeInvalidBlockStructure` needs no eligibility check and no walk: a malformed block is never
  honest history, so it runs the input-only `isInvalidBlockStructureInStateProof` on the last
  milestone
  ([DisputeFraudProofFacet](../../source/contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol.md),
  [StateProofFacet](../../source/contracts/V1/StateChannelDiamondProxy/StateProofFacet.sol.md)). The auditor computes the
  last-milestone scan on its local diamond
  ([DisputeValidationService](../../source/src/stateManager/dispute/DisputeValidationService.ts.md)).
- `DisputeStateProofBelowOnChainAnchor` (payload `{ bool __; }`, enum value appended last) is valid
  when the walk start is the same-fork non-genesis on-chain snapshot and the dispute's latest
  claimed block height is strictly below its height; an empty proof is also below such a snapshot.
  Equal or higher height, an on-chain snapshot of another fork, or a genesis on-chain snapshot make
  the proof invalid
  ([`_handleDisputeStateProofBelowOnChainAnchor`](../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L270)).
  The SDK builds it with `DisputeFraudProofService.createDisputeStateProofBelowOnChainAnchor` and
  detects the case from the chain's `getAnchorSnapshot` in `DisputeValidationService`.
- `DisputeInvalidBalanceInvariant` judges the dispute's latest state and runs no walk. The handler
  checks `_isLatestStateLinkedToLatestBlock(dispute, latestStateSnapshot, latestStateMachineState)`
  (snapshot hash equals `latestStateSnapshotHash`, machine-state hash, link to the latest block),
  then the balance check
  ([`_handleDisputeInvalidBalanceInvariant`](../../../../../contracts/V1/StateChannelDiamondProxy/DisputeFraudProofFacet.sol#L364)).
  The payload has no genesis data or milestone snapshots. The auditor checks the balance of
  `auditingData.latestStateSnapshot` with one local-first read and needs no usable walk
  ([DisputeValidationService](../../source/src/stateManager/dispute/DisputeValidationService.ts.md)).
